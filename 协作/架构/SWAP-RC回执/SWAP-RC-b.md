## 交付

| 东西 | 位置 |
|---|---|
| 6 张牌的数据 | `godot/data/cards/维修职业分类牌.json`（`RC_1`~`RC_6`） |
| 效果算子 + 【过量整备】 | `godot/core/battle/repair_cards.gd`（`RepairCards`） |
| 公有牌冷却区 | `godot/core/battle/public_cooldown.gd`（`PublicCooldown`） |
| 单位断言 64 条 | `godot/tests/unit/test_repair_cards.gd` |

- **入池**：`DeckBuilder.公有扩展牌们` 追加 `RepairCards.职业牌们()`，过滤口径与既有 36 张分类牌同一份
  （`Setup._公有牌入池吗`）——**队里没有维修机体就一张都不装**。
- **六张牌**（费用 / 冷却 / 入牌库条件 / 过量整备逐条对表，见 `test_repair_cards` ①）：
  `常规整备` 0/1 · `装甲焊补` 10/2 · `强制排热` 5/2（第 2 回合起）· `野战补给` 15/3（第 2 回合起）·
  `全舱整备` 15/3（第 2 回合起，代价 = 本回合不能打主武器）· `紧急损管` 15/每场 1 次（我方有人 HP ≤ 50%）。
- **【过量整备】**：目标已满血 **或** 本次回复量溢出即触发（§0 双轨解法第 1 条），六张牌各自兑现设计稿写的那一份增量；
  同时在 `ctx.维修统计` 记「本场总回复量 / 触发次数」（三层反馈的「结算」）。
  与 Iris 的个人被动【月华溢流】完全独立（本批没碰月球王国）。
- **冷却区（新）**：`冷却 > 0` 的公有牌打出后进 `ctx.公有冷却`，我方阶段初倒计时 −1，归 0 追加回公有牌库；
  `移出本场` 的牌（紧急损管）直接进 `ctx.移出牌`，不回库。
  **选择性加入**（卡上写 `进冷却区`）——这样牌池里本来带 `冷却` 的统帅牌 `⚡全军总攻` 流转一字未改。
- **新入库条件** `我方存活有人低于`：既有 `我方有人低于` 会把阵亡单位（血比 0）也算成「有人低于 50%」，
  所以维修这一侧另给一个带存活判据的键，**没有改既有那条**（避免动到毛的【达纳号·紧急补给】）。
