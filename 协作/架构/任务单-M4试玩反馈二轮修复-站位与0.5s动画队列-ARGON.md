## §1 根因与规格明细

### 子任务 `UX-4`：修复编队调整后进战斗实际站位不对 + 拒绝擅自补塞未上阵机体（反馈 1）

- **实测根因**：
  - `godot/core/run/node_resolver.gd:204-236` 的 `我方编成(state)` 在构造出战阵容时，第 207–211 行把 `state.lineup` 里的字典 `{key, slot}` **剥掉了 `slot` 只留 `key`**，随后在第 223 行一律调用 `_默认位(排位, k, ...)` 去查 `Db.T["默认五人队"]` 的写死位置（`B1→0, B2→1, CB4→2, CB2→6, M1→4`）！导致玩家在编队屏精心拖拽调整的格位（`前1..前4` / `后1..后4`）进战斗后全部作废、弹回默认位！
  - 此外，第 225–229 行还会把「名册里有、但玩家特意没放上阵」的机体自动补进战斗凑满 `deploy_limit`。
- **修改文件**：
  - `godot/core/run/node_resolver.gd`
  - `godot/session/game_session.gd`
- **具体规格**：
  1. **槽位名到战斗格位号映射**：
     - 统一映射表：`"前1": 0, "前2": 1, "前3": 2, "前4": 3, "后1": 4, "后2": 5, "后3": 6, "后4": 7`（若 `slot` 本身已是 `0..7` 整数或数字字符串也兼容）。
  2. **严格尊重玩家 `state.lineup` 的 `slot` 与出战名单**：
     - 在 `node_resolver.gd:我方编成(state)` 中：当 `state.lineup` 非空（至少有 1 台合法存活机体）时，**只出战 `state.lineup` 里的机体（绝不把名册里未上阵的机体擅自塞进战场）**；
     - 对 `state.lineup` 中的每一项：若带有合法 `slot`（映射后 `0..7` 且未冲突），**直接使用该玩家指定的 `位`**；仅当某项 `slot` 为空或冲突时，才按空余格位 / `_默认位` 兜底。
     - 仅当 `state.lineup` 完全为空时，才回退到旧逻辑（从 `roster` 补或用 `默认五人队`）。
  3. **黄金样例兼容性保护**：
     - 检查既有测试/黄金样例中是否有构造了「`state.lineup` 只有 `String`（非 `Dictionary`）或 `slot == ""`」的用例：若 `lineup` 元素是纯字符串或 `slot == ""`，仍走原 `_默认位` + 补齐逻辑，从而 **100% 保持既有黄金样例与旧测试全绿**；而一旦 `lineup` 里存的是编队屏写入的带非空 `slot` 的 `Dictionary`（或 `state` 标记了玩家已调整编队），就严格按玩家 `slot` 站位出战！

### 子任务 `UX-5`：战斗动画与发牌动画改为 ~0.5 秒/步的串行播放队列（反馈 2、3）

- **实测根因**：
  - `godot/presentation/battle/battle_view.gd:991-1006` 的 `_收窄到最后一拍()` 把一整回合产生的十几条攻击、受击、发牌事件在同一帧一次性叠加画出，0.7 秒内一锅粥闪完，肉眼根本看不清先后顺序；
  - 点「自动战斗」直接调 `session.auto_finish_battle()` 在内核跑完同步 `while` 循环秒跳结算屏，完全跳过了战斗画面。
- **修改文件**：
  - `godot/presentation/battle/battle_view.gd`
  - `godot/presentation/widgets/unit_card.gd`
- **具体规格**：
  1. **建立串行演出队列（`_演出队列: Array[Dictionary]`，每步 `STEP_DURATION = 0.5` 秒）**：
     - 当玩家点「下一回合（下一拍）」推进一回合后，提取本回合新增的全部战斗日志条目，按时间顺序拆解为串行演出帧（过滤掉纯调试噪音，保留 **`发牌`**、**`攻击/大招/反击/追加`**、**`修理/治疗`**、**`战术牌`**、**`Boss/增援/击破`**）：
     - **当 `DisplayServer.get_name() != "headless"` 且不在单元测试树中时**，启动队列协程 `_消费演出队列()`，**每隔 `0.5 秒` 依次播放 1 帧**（期间顶栏显示 `〔演出中 i/N〕`，并提供「跳过本回演出」/「2x 加速」按钮）：
       - **① 发牌动画帧（每张牌约 0.5 秒）**：
         - 横幅播报：`〔发牌〕来自【机体名】 -> 获得战术牌【牌名】`；
         - 场上对应的来源机体卡（`UnitCard`）亮起青金色发光边框并向上轻跳；
         - 在顶层画布从**来源机体卡中心 -> 底部手牌栏目标卡中心**画一道 0.45 秒的金色流光/飞行卡背轨迹，落地时该手牌卡执行放大 `1.15x -> 1.0x` 的脉冲亮框动画。
       - **② 攻击 / 修理 / 技能动画帧（每次行动约 0.5 秒）**：
         - 横幅播报：清晰写出 `【出手方】使用【武器名】 -> 【受击方】 · 造成 XXX 伤害（附加效果）`；
         - **0.00s–0.15s**：出手方 `UnitCard` 亮金框 + 朝目标方向前冲 14px，同时画一条从出手方中心到受击方中心的指向箭头光束线；
         - **0.15s–0.50s**：受击方 `UnitCard` 红闪 + 左右震动，头顶弹出大号浮动飘字（`-伤害` / `〔暴击〕-伤害!` / `未命中` / `+HP` / `〔破防〕` 等，持续飘浮 0.65 秒让玩家看清数字），出手方回弹归位。
  2. **「自动战斗」改为「每回合自动连播动画」+ 单独提供「直接跳结算」**：
     - 将原来的「自动打完」拆成两个清晰按钮：
       - **「自动播放 / 暂停」**：开启后，每当本回合的 `0.5s × N` 演出队列播放完毕，停顿 0.3s 自动调一次 `step_battle_turn()` 进入下一回合继续播动画，让玩家能像看战报动画一样完整看完每一刀每一枪；
       - **「跳过直达结算」**：保留给不想看动画时一键算完进结算。
  3. **Headless 测试零回归保障**：
     - 在 `DisplayServer.get_name() == "headless"` 时，`_消费演出队列()` 不做 `create_timer(0.5)` 阻塞等待，直接同步应用最终一帧状态并记录已播帧数，确保 1700+ 项自动化测试仍在几秒内跑完。
