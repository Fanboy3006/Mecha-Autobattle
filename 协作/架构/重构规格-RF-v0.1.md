## 〇、总原则（每个批次都适用）

1. **不改战斗结果**：除 RF-0 外，所有批次的原生样例 180 场必须**逐场、逐事件、逐 rng 步数不变**，不许重录。出现差异 = 改错了，停下报告。
2. **战报文案不改**：`pushLog` 的文字一个字不动（只允许改代码结构、键名、调用路径）。统一文案是另一件事，要作者先拍板，不在本规格内。
3. **棘轮只降不升**：`CORE_TO_FACTION_RATCHET_MAX`（现 120，实测 116）、`SIZE_RATCHET`、`COMMENT_RATCHET`。每批做完把能降的降下来；任何一批需要上调 → 停下。
4. **先加底座、再迁调用点、最后删旧口子**：同一个概念在迁移期允许新旧并存，但每个批次结束时旧口子的调用数只能减少。
5. **新共用文件**放 `core/battle/kit/`（新目录），文件首行 `##` 职责注释照 `godot/README.md` 约定；不许点名任何势力模块（规则 ⑤ 会量）。
6. Claude 与 DeepSeek 不同时改 `core/`（CLAUDE.md §4）：RF 批次串行派发，一张回来验收完才派下一张。

## 二、目标形状（重构完成时）

### 2.1 一套派发：RuleHooks 是唯一入口，Fac 降级为工具
- 所有势力 / 职业模块只通过 `RuleHooks.顺序` 登记；`fac.gd` 的 `match 势力` 分派逐步清空，最后只留工具函数（或并入 kit）。
- 钩子分六类（名字以最终登记为准）：
  - **生命周期**：`开局初始化(ctx)` · `装填单位(u,等级,ctx)→Array` · `装填大招槽(ctx,u)` · `公有扩展牌(ctx)`
  - **阶段**：`阶段初(ctx, 阶段, 段)`、`阶段末(ctx, 阶段)`，其中 `阶段 ∈ {我方, 敌方}`、`段 ∈ {前, 势力, 后}`。旧的 `我方阶段初_前/_势力/_后`、`敌方阶段初`、`我方阶段末`、`势力回合开始/结束` 合并进来（迁移期由旧名薄转发）。
  - **数值**（汇总 / 依次乘）：闪避加成、命中修正（并入 `_附加`）、暴击修正、装甲加成、防御加成、攻方 / 受方伤害倍率。
  - **战斗事件**（广播）：攻击前、受击前、受击后、逐段未命中、武器攻击后、友军攻击后、击破、修理后、致命保留_前/_后、换位后；新增 **`段判定后(ctx,att,def,段,判定)→判定`**（改判类，给赌神翻盘用；必须保持 rng 消耗顺序）。
  - **出牌**（首个结论，统一返回 `{终局, 原因, 结果}`）：卡不可打原因、区规则门槛、打出牌、牌打出前/后、武器改写、执行算子（统一签名 `(名, 运行, 表, 目标们)`）、条件值。
  - **大招 / 副武器 / AI**：按处理者（认领、不可打原因、阶段初、打出、费用）；`打出大招` 被接手后，打出前 / 后 / 收尾后广播**由 DeckFlow 统一发**，处理者不再自己复刻。副武器 7 个钩子保留；AI：可选目标（统一 `{终局, 可选}`）、AI 自动出牌跳过、掩护接管。

### 2.2 每个势力模块的固定外形（以殖民卫星军为样板）
```
const 势力 := "<势力 id>"
const 成员键 := [...]                 # 只在入口模块定义一次，子模块引用它
const 处理者名 := "<模块类名>"        # 大招槽 处理者 一律用常量
static func 开(ctx) -> bool            # 选项开关 && 场上有成员
```
- 成员判定一律 `FactionKit.是成员(u, 势力)`；状态一律 `FactionKit.单位状态(u, 势力)` / `FactionKit.全队状态(ctx, 势力)`；卡表一律 `FactionKit.卡包(势力)`（带缓存，缺包 push_error）。
- 子模块（如 `colonial_units/deck/awaken`）不直接登记，由入口模块转发。

### 2.3 共用效果库 `kit/effect_kit.gd`（以及 `kit/target_kit.gd`、`kit/timed_state.gd`）
| 原语 | 统一什么 |
|---|---|
| `记效果(ctx, 牌名, 单位, 文本, 字段={})` | 包掉 9 份 `_记`；**文本原样传入**（不改文案），`类型` 字段先保留各模块原值（统一枚举另议） |
| `加增益(u, 源, 增益, 回合=1)` | 包 `Btl.换同源增益`；源名规范为 `"<势力或职业>:<牌 id>"`（迁移期旧源名照旧，只对新代码强制） |
| `回血(ctx, 目标, 比, 选项)` | 统一 `J.round` 舍入、溢出返回值 |
| `加战意(ctx, u, 值, 原因)` / `抽牌(ctx, u, 张, 池)` | 只封装调用，日志仍由调用方给文本 |
| `减大招冷却(ctx, u, 值, 选法)` | 选法：首张 / 最长 / 过滤函数；覆盖新体系 `大招槽[].cd` |
| `下张武器加成(u, 加成字典)` / `取下张武器加成(u)` | 一个键 `下张武器加成`，攻击管线一处消费（替代 6 套键；**迁移期双读**） |
| `TimedState.登记(u或ctx, 键, 到期)` | 到期 ∈ {本回合, 下个我方阶段, N 回合}；由 `阶段初` 框架统一清，替代各模块手清 |
| `TargetKit.施放者 / 友军 / 敌机 / 血比` | 替代约 31 个模块私有辅助；回退策略做成参数，默认值逐个对齐现有行为 |

**留在模块里的独有机制**（只改为调用上面的原语，不抽成通用算子）：秘银 λ 驱动 / 连携牌库；天人 TRANS-AM、粒子耗尽、剑牌、人格交替、太阳炉牌库；ATX 赌神 / 赌局 / 筹码、合体技、读牌意图；殖民卫星军觉醒 / ZERO / METEOR / 正规军掩护；维修过量整备；顺劈 / 横向掩护几何。

### 2.4 统一单位模型
- **阵营是数据**：`Units.isFoe(a,b)` / `foesOf(u, ctx)` / `matesOf(u, ctx)` / `sideOf(u)`；逐文件替换写死的 `"ally"/"enemy"`。胜负判定、意图计算按阵营参数化。
- **模板源与阵营解耦**：`makeUnit(..., 模板源)`，模板源 ∈ {ALLY_T, ENEMY_T, inline}；名字取法、aim 缺省、成长档按模板源走，不按阵营走。
- **行为是组件**：
  - `controller ∈ {player, ai, boss}`，flow.gd 的行动分派按它走。
  - `deck` 组件（牌区 + 战意）存在才算牌组单位，取代「有没有 `战意` 键」的鸭子类型，也取代 setup 里给敌方删键。
  - `boss` 组件见 RF-D3。
- **卡效果的 `方` 改为相对施放者**（`友 / 敌`）；对我方施放的现有牌结果完全不变。
- **掩护者是能力不是 key**：`abilities` 里的「掩护」+ 额度，去掉 `key == "A6"` 之类写死。
