# 任务单：手牌区「三栏 + 公有栏」零滚动自适应缩放 & 友军牌强制拖拽绿色连线箭头（ARGON）

> **签发人**：ARGON（Gameplay + Godot Software Architect）
> **日期**：2026-10-18
> **基线**：`3815` 项全绿
> **目标**：根据作者截图与试玩反馈，彻底重构中下「手牌栏」布局（消灭横向 Scroll、填满底部空白、上排拆为【主武器 / 副武器 / 精神】并列三栏 + 下排【公有牌】自动缩放），并将所有针对友军使用的卡牌（含天人成员/太阳炉修理补给等）统一为「必须拖动到己方机体上释放 + 绿色连线与箭头」。

## §1 修复规格

### 1.1 【UI-1】中下手牌栏：「上排三栏（主武器 | 副武器 | 精神）+ 下排公有栏」零滚动条自适应缩放（`godot/presentation/battle/battle_view.gd`）
- **问题根因**：
  1. 原 `_建单机一排()` 高度写死 `58px` 且未设纵向 `SIZE_EXPAND_FILL`，导致 `248px` 高的手牌栏底部空出约 `90px` 空白；
  2. 上排把 `【主武器牌】/【副武器牌】/【精神牌】` 3 个组标和所有卡牌全部塞进**同一条横向 `ScrollContainer`**，每张卡最小宽度写死 `108px`，只要超过 4 张牌就挤出横向滚动条，必须拖 `_h_scroll` 才能看全！
- **重构要求**：
  1. **彻底去掉横向滚动条（`horizontal_scroll_mode = SCROLL_MODE_DISABLED` 或直接用 `HBoxContainer` 铺满，严禁出现需玩家拖动的 `_h_scroll`）**，并充分利用手牌栏的全部高度（`248px` 中除顶部状态行外，约 `210px` 全部给上下两排手牌，纵向 `SIZE_EXPAND_FILL`，消灭底部空白）：
     - **上排（`_专属排`，高约 `104px`，`SIZE_EXPAND_FILL`）**：内部是一个横向平铺的 **三栏 `HBoxContainer`**，分为三个独立的带浅色边框子面板（按比例分配宽度，如主武器栏 `stretch_ratio = 1.25`、副武器栏 `0.9`、精神栏 `1.35`，或根据当前各栏张数动态分配 `size_flags_stretch_ratio = max(1, 该栏张数)`！**按 `max(1, 该栏张数)` 动态分配 `stretch_ratio` 最聪明**：哪一栏牌多就自动分到更宽的空间！）：
       - 左子栏：顶部小标题 `【主武器】` + 下方 `HBoxContainer` 放当前可打主武器牌；
       - 中子栏：顶部小标题 `【副武器】` + 下方 `HBoxContainer` 放当前可打副武器牌（及非武器入场大招）；
       - 右子栏：顶部小标题 `【精神】` + 下方 `HBoxContainer` 放当前可打精神牌（最多 4 张）。
     - **下排（`_公有排`，高约 `96px`，`SIZE_EXPAND_FILL`）**：顶部小标题 `【公有牌（势力 / 职业 / 副牌库）】` + 下方 `HBoxContainer` 放当前可打公有牌（最多 6 张）。
  2. **卡牌自动缩放（Auto-Scale / Flex）**：
     - 在 `_建单机卡(卡, 栏内张数, 是公有排)` 中：不再写死 `108px` 最小宽度！
     - 每张卡设 `size_flags_horizontal = Control.SIZE_EXPAND_FILL`，`size_flags_vertical = Control.SIZE_EXPAND_FILL`，`custom_minimum_size = Vector2(36, 52)`（允许自由收缩以保证 100% 装进容器无需滚动条）；
     - 按钮开启自动换行或裁剪（`autowrap_mode = TextServer.AUTOWRAP_WORD_SMART` / `clip_text = true`），并根据当前这一排/这一栏的总张数自动微调字号（例如张数 `<= 4` 时用 `12px`，`5..6` 张时用 `11px`，`>= 7` 张时用 `10px`），卡片高度充裕（约 `64~74px`），可清晰展示 **「牌名 + 耗气/威力/简短说明」两到三行文字**，一眼看全所有手牌！
  3. **保持现有测试节点兼容**：保留 `_专属排`、`_公有排`、`_专属牌盒`、`_公有牌盒` 引用（`_专属牌盒` 可指向包含三栏的容器或保留向后兼容查询，确保 `test_presentation_layout.gd` 等所有查找手牌按钮的测试 100% 绿）。

### 1.2 【UI-2】补齐 `"天人成员"` 等全量友方目标识别 + 友军牌「禁止点击直放，必须拖动到己方机体（带绿色连线与箭头）」（`game_session.gd` + `battle_view.gd`）
- **问题根因**：
  1. `game_session.gd:2358` 的 `目标_友方集` 漏了 `"天人成员"`（以及未来殖民卫星军的 `"殖民卫星军成员"`），导致太阳炉牌库 6 张（`哈罗·紧急修理`、`GN 粒子补充`、`Veda·战况分析`、`GN 全盾·哈罗`、`超兵反应`、`伊奥利亚的遗产`）、天人势力牌 4 张（`克莉丝的通讯支援`、`战术预报`、`伊安的整备`、`托勒密号·紧急补给`）、拉塞精神牌 `「去吧，刹那」` 共 11 张牌的 `目标方` 全被错误算成了 `"敌方"`！
  2. 结果玩家拖 `哈罗·紧急修理` 时画的是红色敌方线、往我方机体上拖完全不吸附；而玩家点一下时，又直接触发了点击免指派兜底（默认奶了满血的洛克昂自己，回复 0 HP），完全看不出效果！
  3. 此外，下排公有牌/太阳炉牌拖动时，`_拥有者卡()` 起点默认取了当前选中的机体，若当前没选或由别的队友代发，起点不够准确。
- **修复要求**：
  1. **补齐友方目标集（`game_session.gd` + `battle_view.gd`）**：
     - 在 `game_session.gd:2358` 的 `目标_友方集`（以及 `battle_view.gd:_拖拽目标方`）中，完整加入：
       `["友军", "秘银成员", "ATX成员", "天人成员", "殖民卫星军成员", "月球王国成员", "影世界成员", "U7", "U6"]`（或凡 `目标.ends_with("成员")` / `目标.begins_with("友")` / `range_kind == "修理"` 一律判为 `目标方 = "友方"`）！
     - 同时检查是否有 `目标 == "自身"` 但实为治疗/修理友军的牌，确保所有需要指定己方单体的牌 `目标方 == "友方"`。
  2. **友军牌（`目标方 == "友方"`）禁止单纯点击直放，强制要求拖动到己方机体上释放**：
     - 在 `battle_view.gd:_点单机卡(卡)` 中：当玩家**单纯点击（未发生拖拽）**一张 `str(卡.get("目标方", "")) == "友方"`（或 `_拖拽目标方(卡) == 我方`）的牌时，**不要直接调用 `_打单机卡(卡, "")` 乱奶默认目标**！
     - 而是直接在操作提示栏/气泡提示显示：**`「请按住【%s】拖动到上方我方机体上释放（绿色箭头指向目标）」`**，并短暂高亮我方所有可选存活 `UnitCard`（翠绿色边框闪烁提示）！
     - *注*：仅当玩家真正**按住该卡拖动到我方某台存活 `UnitCard` 上松手**时，才调用 `_打单机卡(卡, 命中的我方机体键)` 执行释放！（编程 API `session.play_unit_card` / `session.play_tactical_card` 在单元测试中直接调用时仍保持原样支持空 `target_id` 兜底，不影响任何后台测试，只约束 UI 鼠标单纯点击行为）。
  3. **拖动友军牌时的「绿色连线 + 箭头 + 起点兜底」**：
     - 在 `battle_view.gd:拖拽瞄准线()` 中：
       - 获取起点卡时：优先取 `str(_拖拽牌.get("所属键", ""))` 或 `str(_拖拽牌.get("发动键", ""))` 对应的我方 `UnitCard` 中心；若仍为空则取 `_拥有者卡()`；若还为空（极端情况），以**被拖动的这张手牌按钮自身中心**作为绿色连线起点！保证**100% 任何时候拖动友军牌都有绿色连线和箭头**！
       - 当 `_拖拽目标方(_拖拽牌) == 我方` 时，`维修 = true`，`战斗动画层._画瞄准线()` 绘制醒目的**翠绿色发光连线 + 实心方向箭头 + 目标我方机体锁定双圆环与十字准星**，并在我方所有合法目标 `UnitCard` 上显示翠绿色可投放高亮框！

### 1.3 【UI-3】左侧牌库栏（`左牌库栏`）分类三区块 + 双列网格零滚动自适应缩放（`godot/presentation/battle/battle_view.gd` + `tests/unit/test_presentation_layout.gd`）
- **问题根因**：
  1. 原 `_建左牌库栏()` 使用单列 `ScrollContainer`（`左库滚动高 = 470`），每张卡内边距 `10×2` + 按钮 + 状态标签占高 `64~68px`，一屏只能装 7~8 张，其余必须拖滚动条；
  2. `左库卡按钮` 未设 `clip_text = true`，长卡名还会撑出横向截断/滚动条；
  3. 武器/大招、待入库精神牌、不可打公有牌混在同一条长列表里，缺乏清晰分区。
- **重构要求**：
  1. **彻底去掉 `左牌库滚动` 的 `ScrollContainer`（无需任何滚动条即可一屏看全左栏全部卡牌）**，充分利用左栏 `260×614px` 的全部可用空间；
  2. **顶部固定摘要区（紧凑 2 行）**：
     - `左牌库标题`：`未激活 / 冷却牌库（N 张）`
     - `左牌库副标题`：紧凑显示 `牌库 X · 弃牌 Y · 待入库 Z` + 当前势力副牌库（连携 / 筹码 / 太阳炉）各级剩余张数（保留 `太阳炉牌库明细` 节点的文本更新兼容）；
  3. **主体 `_左牌库列表` 拆分为 3 个带标题的自适应子区块（纵向 `SIZE_EXPAND_FILL`，按各区块 `max(1, ceil(条目数 / 2.0))` 动态分配 `size_flags_stretch_ratio`）**：
     - **区块 A `【武器 / 大招（冷却·出鞘·收起）】`**：收录当前选中机体不可打的主武器、副武器、出鞘剑牌、冷却或未满足条件的大招槽牌；
     - **区块 B `【精神 / 待入库条件牌】`**：收录当前选中机体的待入库精神牌与暂不可打精神牌；
     - **区块 C `【公有 / 势力副牌库】`**：收录当前不可打的公有牌，以及当条目较少时直观展示当前势力副牌库（太阳炉/连携/筹码）可抽卡名概览；
  4. **每个子区块内部采用 2 列 `GridContainer`（`columns = 2`）自适应高密度小卡**：
     - 每张 `左库卡` 设 `size_flags_horizontal = Control.SIZE_EXPAND_FILL`、`size_flags_vertical = Control.SIZE_EXPAND_FILL`、`custom_minimum_size = Vector2(36, 22)`，内边距收紧为 `3px / 2px`；
     - 卡内包含 `左库卡按钮`（`disabled = true`、`clip_text = true`、字号按总条目数自适应 `9~11px`）与 `左库卡状态`（`9~10px`，显示 `〔3 回合后进入手牌〕` / `〔出鞘·剑×N〕` / `〔第2回合起〕` / `〔暂不可用〕`）；
     - 完整保留 `HoverTooltip.bind(卡, 悬, "战术牌")` 鼠标悬停说明；
     - 完整保留 `卡.set_meta("left_library_entry", e)`、`左库卡`、`左库卡按钮`、`左库卡状态` 节点名；若测试 helper `_左库里有名` / `_左库有标签` / `_左库按钮全禁用` 之前只遍历 `_左牌库列表.get_children()` 一层，同步改为递归查找 `left_library_entry`（或在 `_左牌库列表` 上保持兼容），确保全部既有断言 + 新增零滚动边界断言 100% 全绿！
