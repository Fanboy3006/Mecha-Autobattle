# M4 表现层接口契约（ARGON 定，DS4F 照做）

> **谁用**：M4-2 与 M4-3 的施工子代理、以及后续任何改 `godot/presentation/**` 的人。
> **上位文档**：`协作/架构/Godot迁移架构-v1.md` §6（分层原则 / 目录）·`协作/Godot迁移-GameplayArchitect交接卡.md` §3.1（单向数据流）
> **不可破坏的既有契约**：见 `协作/Godot迁移-ARGON验收对照表.md` §8.2b。**那一节与本文件冲突时，以那一节为准。**

---

## 1. 铁律：单向数据流

```
按钮点击 → GameSession 的命令方法 → 内核（core/**） → 状态变更
                                        ↓
                              表现层只读 GameSession + Db.catalog → 重画
```

1. **表现层不改状态**：`presentation/**` 里的任何 `.gd` **不许**直接改 `RunState` 的字段、不许直接调 `core/run/**` 的会改状态的函数（`move_to` / `recruit` / `黑市买` …）。
2. **表现层要数据**：只从 ① `GameSession` 的展示辅助方法（`hand_cards()` / `topbar_state()` / `unit_view()` / `result_summary()` …），或 ② **纯读**的目录与查询（`Db.catalog.*` / `DeckBuilder.找到` / `RelicSystem.名` / `PartSystem.part_info` / `MapGenerator.shape`）取。
3. **表现层做动作**：一律调 `GameSession` 的命令方法，拿返回的 `Dictionary`（含 `ok` / `why` / 变更摘要）决定怎么反馈。
4. **表现层零 `J.*`**：`test_boundary.gd` 会扫 `res://presentation`，出现 `J.` 直接退出码 1。数值取整用 `JsCompat.js_round`。
5. ★ **门面（`GameSession`）与表现层都不得发明规则** —— 只许**转述**内核已有的事实与拒绝理由。
   **为什么单列一条**：`GameSession` **不在黄金样例的覆盖面上**（黄金样例直接走 `Setup` / `Btl` / `NodeResolver`），
   所以门面里自造的任何一条门槛（例：曾短暂存在的「每回合最多打 2 张牌」）**黄金样例永远抓不到**，只会让 Godot 版
   与封存 JS 版玩起来不一样。判据只有一个：**封存 JS（`src/js/**`）+ `core/**` 有没有这条规则**。
   查不到 = 不能加。参见 `协作/Godot迁移-ARGON验收对照表.md` §8.5 的 D-03/D-04。

## 2. 目录（照 `Godot迁移架构-v1.md` §6.2 的 `presentation/ battle/ · run_map/ · menus/ · widgets/ · theme/`）

```
godot/presentation/
├─ boot/boot.tscn · boot.gd      # ★ 唯一主场景（main_scene 指向它，路径不许改）
├─ theme/            ui_theme.gd              # 配色 / 字号 / 间距常量（集中一处，别散落魔数）
├─ widgets/          top_bar.gd · unit_card.gd · hand_card.gd · modal_layer.gd
├─ menus/            menu_view.gd（主菜单 + 分队选择）· roster_view.gd（招募/晋升）· pick_card_view.gd（3 选 1）· shop_view.gd · rest_view.gd · event_view.gd
├─ run_map/          map_view.gd（正方形大地图）· formation_view.gd（8 格编队 · 前 4 后 4 正交 4×2）
└─ battle/           battle_view.gd（8 格双方阵型 + 底部手牌栏 + 战报栏）· result_view.gd（战后结算屏）
```

> **命名纪律**：一个文件一个 `class_name`，名字 = 文件名驼峰（`ui_theme.gd` → `UiTheme`，`top_bar.gd` → `TopBar`）。
> 这样别的文件可以直接用类名引用，不需要 `preload` 路径字符串。

## 3. 视图统一契约（所有视图都必须长这样）

```gdscript
class_name MapView
extends Control

var session: GameSession

## 由 boot 调一次：把会话门面递进来，并建好节点树。内部不许读外部全局。
func setup(p_session: GameSession) -> void:
	session = p_session
	_build()

## 状态变了就调它重画（boot 在 GameSession 的 changed 信号里统一调）。
func refresh() -> void:
	pass

func _build() -> void:      # 建节点（只在 setup 里调一次）
	pass
```

**硬性要求**：
1. `extends Control`（**不许** `extends Node2D`、不许自带 `SceneTree` 逻辑）。
2. 只有 `setup(session)` 和 `refresh()` 两个入口；**不许**在 `_ready()` 里读 `GameSession`（`_ready` 时 session 还没递进来）。
3. **节点树必须能被 headless 建起来**：不许在 `_build()` 里 `load()` 一个只在编辑器里存在的场景；不许依赖鼠标/键盘事件才能建出结构。
4. **给节点起名字**：要紧的控件必须 `node.name = "..."`（如 `"顶栏"` `"大地图"` `"手牌栏"` `"候补区"` `"结算面板"`），
   因为 `test_presentation_smoke.gd` 靠 `find_child("手牌栏", true, false)` 断言它真的存在。**名字用中文本常量，且只用常用字。**

## 4. boot.gd 的职责（M4-2 拥有）

1. `extends Control`，`_ready()` 里：
   - **保留** `static func smoke_checksum() -> int`（值必须仍是 `182751003`）—— `tests/unit/test_rng.gd:25` 依赖它；
   - **保留** 那行 `print("MECHA_SMOKE %s" % JSON.stringify({"checksum":…, "version":…, "data":…}))`，**键名与含义不许改**，且必须真的执行到 —— `tools/web_smoke.mjs` 与 Pages 门禁依赖它（`data` 里要有 `ALLY_T` / `编成表` / `战术卡牌表` 三个计数）；
   - `DataLoader.install(errors)` 装数据；
   - **`session = GameSession.new()`**（自己 new 一个实例挂在根节点上，**不要加 autoload**）；
   - 建 `theme` / `TopBar` / 一个 `Control` 当「屏幕容器」/ `ModalLayer`；
   - 连 `session.changed` 信号 → 按 `session.screen` 切换容器里的视图，并调 `refresh()`。
2. **路由表**：`session.screen` ∈ `"menu" | "squad" | "map" | "formation" | "battle" | "result"` → 对应视图类。逐屏视图**懒建 + 复用**（不要每帧 new）。
3. `session.modal` 非空 → `ModalLayer` 弹对应面板（招募 / 晋升 / 3 选 1 / 黑市 / 休整 / 奇遇 / 结算）；空 → 关掉。
4. boot **自己不画业务内容**，只做「建会话 + 顶栏 + 路由 + 弹窗层」。

## 5. 三层反馈的落点（`CLAUDE.md` 第 7 节第 10 条 · 缺一层不算做完）

| 层 | 由谁提供 | 允许的表现形式 |
|---|---|---|
| **预告** | `GameSession.preview_cell_move` / `retreat_cost_preview` / 手牌的「满足条件吗 + 为什么不行」 | 大地图悬停提示、手牌置灰 + 原因文字 |
| **即时** | `GameSession.battle_log_lines()` 与 `last` | 战斗日志栏、单位卡状态行（**不许**表现层自己拼日志文本，日志文本由内核产生） |
| **结算** | `GameSession.result_summary()` | 战后结算面板、战报回顾 |

★ **表现层不许自己算数值**（回血量、战利品数量、推进剂消耗一律从内核返回的 `Dictionary` / 门面读）。表现层自己算 = 与内核两套口径 = 将来对不上。

## 6. 字体与文字纪律（M4 只许这样写）

- 新增界面文字**只用 GB2312 一级常用字**（字体子集常驻这 3755 字）。
- **不要**引入新的 emoji / 生僻字 / 花哨符号；现有 `⚡🛡` 已被后备字体链覆盖，可以继续用。
- 本机**没装 fontTools**，`godot/tools/build_font_subset.py` 跑不了 → 引入新字 = `test_font_coverage.gd` 必红 = 返工。
- 所有界面文字用**中文**（`CLAUDE.md` 第 7 节第 5 条）。

## 7. 验收测试（必须由 M4-2 / M4-3 一起交付）

新建 `godot/tests/unit/test_presentation_smoke.gd`（`extends RefCounted` + `func run(t)`，自动被发现）：

| 段 | 断言什么 |
|---|---|
| 1 | `boot.gd` 的 `smoke_checksum() == 182751003`；`MECHA_SMOKE` 那行的**代码确实存在**（读文件文本断言，防止有人重构时删掉） |
| 2 | `DataLoader.install(errors)` 成功；`GameSession.new()` 能建出来 |
| 3 | **每个视图**都能 `ViewClass.new()` → `setup(session)` → `refresh()`，**且不报错**（用 `t.ok` 包住，并把 `push_error` 计数当失败） |
| 4 | 视图里**关键节点真的存在**：`find_child("顶栏")` / `"大地图"` / `"手牌栏"` / `"候补区"` / `"结算面板"` 非 null |
| 5 | 把 `session.screen` 依次设成全部 6 个值 + 设 `session.modal` → `boot` 的路由**不崩**、容器子节点数合理 |
| 6 | **静默纪律**：全流程结束后，`session.errors` 为空数组 |

> 这样「Web 版能不能玩」再由浏览器冒烟验一次；**UI 结构回归靠这一份 headless 测试守住**，不依赖人工点击。

## 8. 派单归属（避免两个子代理改同一个文件）

| 文件 | 归属 |
|---|---|
| `boot/boot.gd` · `boot/boot.tscn` · `theme/**` · `widgets/**` · `menus/**` · `run_map/**` | **M4-2** |
| `battle/battle_view.gd` · `battle/result_view.gd` | **M4-3** |
| `tests/unit/test_presentation_smoke.gd` | **M4-2 建骨架（段 1/2/5/6）+ M4-3 补段 3/4 的战斗屏与结算屏部分**；两人都不许删对方的段 |

> **M4-3 先冻结接口**：`BattleView.setup(session)` / `BattleView.refresh()` / `ResultView.setup(session)` / `ResultView.refresh()`
> 就是全部约定。M4-2 的 boot 只按这四个签名调用，**不假设 BattleView 内部长什么样**。
> 为保证门禁不被「另一半还没写完」搞红：**M4-2 与 M4-3 按顺序施工**（M4-2 先落盘并把战斗屏接到一个「加载失败就显示一行提示」的兜底，再由 M4-3 填真实现）。
