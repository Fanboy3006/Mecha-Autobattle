## §1 第 6 节四条机制逐条可行性回复

### ① 记录「本回合我方已打出秘银牌数」+ 打出那一刻判定【连携】【连携·N】+ 手牌区显示计数 + 可连携的牌亮金边
- **结论：✅ 完全可行（改动量：小，约 45 行代码，需修正 `btl.gd` 打牌管线 1 处时序）**。
- **代码现状与落点**：
  1. **计数存储与回合清零**：
     - 现状：`godot/core/battle/setup.gd:125` 只有整场累计的 `已打出战术牌 = []`（跨回合不清零）；「本回合张数」目前是门面 `godot/session/game_session.gd:1877-1887` 事后遍历日志算出来的。
     - 改造：在 `setup.gd:125` 初始化与 `godot/core/battle/flow.gd:40` 每回合开始时置 `ctx["本回合秘银牌数"] = 0`。计入口径：`牌.归属 == "秘银"`（势力牌）、`牌.角色所属势力 == "秘银"`（秘银角色牌）、或 `牌.是TDD1 == true`（TDD-1 衍生牌）；打出其他势力或通用统帅牌**不增加计数、也不清零**。
  2. **★ 必须锁死的判定时序（防止自触发）**：
     - 现状：`godot/core/battle/btl.gd:600-635` 的 `打战术牌` 顺序为：`:617` 扣气势 → **`:619` `CardEffects.execute(ctx, card)`** → `:620-625` 扣次数/设冷却 → **`:626-628` 记录已打出**。
     - 规则约束：在 `:619` 执行卡牌效果前，必须先取 **本牌打出前的计数快照** `n_before = int(ctx.get("本回合秘银牌数", 0))` 判定本牌是否满足 `【连携】（n_before >= 1）` 或 `【连携·N】（n_before >= N）`；等本牌效果执行完毕后，再在 `:626` 执行 `ctx["本回合秘银牌数"] = n_before + 增量`（普通秘银牌/TDD-1 增量为 1）。这样第 1 张秘银牌打出时 `n_before == 0`，绝不会自己触发自己的【连携·1】。
  3. **手牌区显示计数与亮金边**：
     - 现状：`godot/presentation/battle/battle_view.gd:417-420` 已有 `_手牌标题` 与 `_手牌气势`；`:469-471` 渲染手牌卡底框时已使用 `UiTheme.底样式(...)`，而 `godot/presentation/theme/ui_theme.gd:30` 现成定义了金黄色常量 `高亮 = Color(1.00, 0.82, 0.35)`。
     - 改造：在 `_手牌气势` 旁显示 `秘银连携：N`；当手牌满足 `可打出 == true` 且带连携词条且 `本回合秘银牌数 >= 连携阈值` 时，将卡片 `StyleBoxFlat` 边框设为 2~3px 的 `UiTheme.高亮` 金色边框并标注 `【连携就绪】`。

- **结论：✅ 框架已支持 80%（其中「打出后移除不回库」现成支持），仅需新增 1 个「置入手牌」算子与 1 条「满 10 张作废」分支（约 25 行代码）**。
- **代码现状与改造点**：
  1. **「打出后移除不回库」—— 现成支持**：
     - `godot/core/battle/btl.gd:620-625` 现有逻辑就是：打出时 `card.剩余次数 -= 1`，当 `剩余次数 <= 0` 时直接从 `ctx["战术手牌"]` 移除且不回任何池。
     - 只要衍生牌（如 TDD-1 导弹）模板设 `限次: 1`、`衍生: true`，并在大招牌化的「回牌库冷却」分支里排除 `card.get("衍生", false) == true`，打出即永久销毁。
  2. **「手牌满 10 张时作废」—— 需与现有 D-01「满手推迟」区分**：
     - `godot/data/js/71-改动-4-战斗结构.json:384-385` 已定义 `手牌总上限 = 10`；但 `btl.gd:518-552` 对牌库条件牌满 10 张时走的是 `记满手牌推迟`（留在 `待触发牌` 等空位，不作废）。

  3. **⚠️ 架构防坑（多张同名衍生牌 `id` 撞车）**：
     - 现有 `btl.gd:603` 与 `:624` 按 `card.id == card_id` 找牌和删牌。若手里同时置入 2 张 `TDD-1`，共用同一个 `id` 会导致打 1 张把 2 张全删掉！
     - **必须在衍生牌置入手牌时生成唯一实例号**（或 `btl.gd:624` 改为只删除匹配到的第一张下标 `idx`）。

## §2 无限循环风险排查（重点：TDD-1 + 呼叫达纳号/火力支援请求 + 泰莎的指令）

围绕 **`TDD-1 推进连携` + `「呼叫达纳号」「火力支援请求」造导弹` + `「泰莎的指令」双倍连携`**，排查出 **3 条潜在无限循环 / 单回合锁死回路**，必须在规则与任务单中植入 **4 道硬性断路器（Circuit Breakers）**：

| 编号 | 风险回路还原 | 为什么会无限循环 / 锁死 | ★ 必须写入规格的硬性断路器 |
|---|---|---|---|
| **Loop-1** | **「打 TDD-1 → 触发连携 → 派生新 TDD-1 → 再打 TDD-1」自激回路** | 若 TDD-1 为 0 费（或被降为 0 费），且「呼叫达纳号 / 火力支援请求」或某张被动写成了「每当触发连携 / 每打出一张秘银牌，置入 1 张 TDD-1」：打出 TDD-1 自身又推进计数或算触发连携，就会单回合无限造导弹打空敌方。 | **断路器 1**：**TDD-1 衍生牌自身不带【连携】词条**（打出它只让 `本回合秘银牌数 +1` 和 `打出TDD1 +1`，**不增加 `触发连携` 计数**）。<br>**断路器 2**：「呼叫达纳号」「火力支援请求」必须是**打出瞬间一次性置入 N 张 TDD-1**，若为本回合光环型造牌，必须写死 **「每回合最多由此生成 K 张 TDD-1」**。 |
| **Loop-2** | **「泰莎的指令（双倍连携）」×「造导弹 + 连携减冷却 + 连携回气势」闭环** | 「泰莎的指令」使【连携】效果触发 2 次 → 打出「呼叫达纳号 / 火力支援请求」时双倍产出 2~4 张 TDD-1 → 连续打出 TDD-1 瞬间把 `本回合秘银牌数` 与 `打出TDD1` 推到极高 → 触发带「连携：回气势」与「连携：秘银牌冷却 −1」的牌**双倍生效** → 把刚进牌库冷却的「呼叫达纳号 / 火力支援请求 / 泰莎的指令」冷却当场减回 0 并重新发回手牌，形成**无限导弹 + 无限气势 + 无限减 CD** 永动机！ | **断路器 3（最关键铁律）**：**任何非衍生牌一旦在本回合打出进入牌库，本回合内严禁再次发入手牌（即每张非衍生牌每回合最多打出 1 次，`card.上次打出回合 == ctx.turn` 时不发牌）**。立住这一条，「呼叫达纳号」「火力支援请求」「泰莎的指令」在单回合内就绝对不可能被刷回手牌打第 2 次！<br>**断路器 4**：「泰莎的指令」的双倍连携状态设为布尔/封顶值（`本回合连携触发次数 = 2`，**同名或多次打出不叠加成 4 倍**）。 |
| **Loop-3** | **条件入牌（`触发连携 ≥ N` / `打出 TDD-1 ≥ N`）在冷却归零时的同帧重入** | `btl.gd:635` 在每次打牌末尾立即同步调用 `检查条件发牌`。若某张以 `触发连携 ≥ N` 或 `打出 TDD-1 ≥ N` 为条件的卡牌冷却被减到 0（或配置成了 0 CD），打出的同一拍 `:635` 检查发现累计计数依然 `>= N`，会当场把它重新发回手牌，造成单张牌无限重入。 | 同**断路器 3** + **所有回库型卡牌基础 `冷却 >= 1`**，且打出的那一拍先不吃当次连携的减冷却，本回合已打出的牌到下回合初之前不参与 `检查条件发牌`。 |

## §3 派生任务单（待作者/CC 确认后按序派工，当前不开工）

### 子任务 MITH-1：底层扩展 —— 衍生牌通道 + 本回合连携计数器 + 4 道断路器
- **归属模块**：`godot/core/battle/setup.gd` · `flow.gd` · `btl.gd` · `card_effects.gd`
- **具体内容**：
  1. `ctx` 新增 `本回合秘银牌数: int = 0`、`本回合连携触发倍率: int = 1`（每回合初在 `flow.gd` 重置）；`ctx["战况计数"]` 新增 `"触发连携": 0`、`"打出TDD1": 0`。
  2. `btl.gd:打战术牌`：
     - 为每张手牌维护唯一 `_实例号`（防多张同名 TDD-1 衍生牌一次全删）；
     - 在 `CardEffects.execute` 前读取 `n_before = ctx["本回合秘银牌数"]` 判定是否满足 `连携阈值`，满足则按 `本回合连携触发倍率`（上限 2）执行连携分支并令 `战况计数["触发连携"] += 1`；
     - 在效果执行后，若本牌属秘银势力牌 / 秘银角色牌 / TDD-1，则 `ctx["本回合秘银牌数"] += 1`（TDD-1 额外令 `战况计数["打出TDD1"] += 1`）；
     - **断路器落地**：非衍生牌打出回库时记录 `牌["上次打出回合"] = ctx.turn`，`检查条件发牌` 跳过 `上次打出回合 == ctx.turn` 的牌（单回合每张非衍生牌限打 1 次）；`衍生: true` 的牌打出后直接移除、不进牌库。
  3. `card_effects.gd` 新增算子 `grant_derived_card`：手牌 `< 10` 时实例化衍生牌置入 `ctx["战术手牌"]`；手牌 `>= 10` 时作废并记日志 `〔衍生牌〕手牌已满（10/10），【…】作废`。
  4. `btl.gd:检查条件发牌` 接入声明式条件 `触发连携 >= N` 与 `打出TDD1 >= N`，移除废弃的 `MITH_MARK`。
- **验收门禁**：新增单元测试验证 ① 第 1 张秘银牌不自触发连携、第 2 张触发【连携·1】、穿插非秘银牌不清零；② 衍生牌置入手牌、打出后彻底移除、满 10 张作废记日志；③ 4 道断路器生效，构造「泰莎的指令 + 呼叫达纳号 + 火力支援请求 + TDD-1」极限组合单回合出牌数有界、不死循环。
