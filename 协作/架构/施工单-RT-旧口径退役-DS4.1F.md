## 背景（一段话版）

游戏最早是网页（JS）版。当时的战斗是"按速度混排、全队共用一手战术牌"（下文叫**旧模式**）。现在玩家实际玩的是"阶段制、每台机体自带牌组"（`单机牌组`，下文叫**新模式**）。菜单开局、读档、三个快速测试，全部会把 `单机牌组模式` 打开。

但 168 场战斗黄金样例是当年从 JS 版录的，跑的是旧模式。为了让它们一直逐条一致，代码里留着：整套旧流程、`手牌装填_JS参考` 对账开关，以及一大片"开关关着就返回中性值"的版本分支（`秘银v02开 / 秘银v03开 / 卡牌流转v01开 / 武器范围v01开 / ATXv01开 / ATXv02开 …`）。

本单先给新模式录一套 Godot 原生的标准答案，然后把只为旧样例存在的东西全部拆掉。

## RT-2：录 Godot 原生黄金样例（新增文件为主，不删任何东西）

### RT-2a 生产选项单一来源（唯一一处生产代码改动）

把 `GameSession._build_battle_options()` 和 `_附加战斗选项()` 里拼选项的逻辑抽成一个静态函数，例如 `session/battle_options.gd` 的 `SessionBattleOptions.生产(run_state, 全卡池体验 := false) -> Dictionary`。原来两个方法改成调用它。

原因：原生样例必须用**和玩家一模一样**的选项开局，两处各写一份迟早会对不上。

验收：所有现有测试和旧黄金样例照常全绿（这一步本身不改变任何行为）。

### RT-2b 输入复用

旧样例的**输入**（我方阵容、敌方编成、种子、藏品）是当年精挑细选过的覆盖面，值得留下；要换掉的只是"跑的规则"。

写 `tools/extract_native_inputs.gd`：从 `tests/golden/battle/{default,faction,character,relic}.json` 里只取每条样例的 `id / 输入.我方 / 输入.敌方规格 / 输入.种子 / 输入.藏品 / 输入.编成`，写成 `tests/golden/native/inputs.json`（应该只有几十 KB）。这样 RT-3 删掉旧大文件后，输入还在。`card_baseline` 不要（它测的是旧手牌）。

另外追加一组 `quick`：3 支快速测试队（复用 `GameSession` 里的 `_秘银五人编成 / _ATX五人编成 / _天人五人编成`）× 第 1 层普通编成 × 种子 `20261013 / 20261014 / 20261015`。这组用快速测试选项（`全卡池体验 = true`），其余各组用肉鸽节点战选项。

### RT-2c 确定性出牌策略

新模式下"结束我方回合"只会替没出手的机体补打主武器，**精神牌、公有牌、大招都不会打**。只按结束回合录，覆盖面太窄，所以要一个替玩家出牌的确定性策略：`tests/native_golden_policy.gd`。

规则：
1. 每个我方阶段，按机体槽位从小到大轮一遍。每台机体按固定顺序看它的牌：大招槽 → 副武器 → 衍生卡 → 精神 / 公有牌 → 主武器。
2. 能不能打，用**界面置灰用的同一个函数**判断（`CardPlay.不可打原因`，CR-2 定的唯一来源）。**不许"试着打、失败了再换"**。
3. 目标：取 `CardPlay.目标方` 那一侧、按槽位从小到大第一个合法目标。
4. 真正出牌要调**门面 `play_*` 背后的那个核心函数**（例如 `Btl.打出主武器卡`、`DeckFlow.打出大招`、`Btl.打出精神或公有牌` 等，以 `session/battle_deck_view.gd` 实际调用的为准），不要另写一份结算。
5. 每个阶段最多 30 次出牌，打不出牌了就 `Btl.结束我方回合`。
6. 策略本身**一次 `ctx.rng` 都不许抽**。在回执里写明你是怎么验证这一点的。

### RT-2d 录制器与对拍

- `tests/native_golden_runner.gd`（新文件，结构仿 `golden_runner.gd`）：开局 → 循环{策略出牌 → 结束我方回合 → 记回合摘要}直到出结果或超过护栏 → 记结束。

## RT-2 验收结论（Claude，2026-10-19）

RT-2 通过主体：选项三处收口、策略不抽随机数（实测 + 源码扫描双证明）、两次录制逐字节相同、整套 3960 项全绿，都核对过。`_找武器栏卡` 的缺陷发现得好，绕开的方式（传 id，与界面同口径）也是对的。

**但出牌策略漏了两个区，这是施工单的疏漏（我写 §RT-2c 时只列了五类），不是执行问题。** `CardPlay` 一共 8 个区，策略只轮了 6 个，**`连携牌`（秘银）和 `筹码牌`（ATX）从没被打过**，所以覆盖缺口里才会有 `V3_L3_*` 和 7 张 `ATX_CHIP_*`。另外主武器永远打武器栏里第一张能打的，导致 `CB*_W2~W5`、`ATX*_W4` 等一次都没出场。RT-3c 要删的 `武器范围v01` / `卡牌流转v01` 分支，正需要这些牌守着。

### RT-2 补录（一个提交 `[RT-2补]`，做完再进 RT-3）

1. **策略补两个区**，完整顺序改为：大招槽 → **连携**（`DeckFlow.打出连携牌`）→ **筹码**（`AtxChips.打出筹码牌`）→ 副武器 → 衍生 → 精神 / 公有 → 主武器。判定照旧只用 `CardPlay.不可打原因(…, CardPlay.区_连携 / 区_筹码)`；候选牌从哪个字段取，以 `session/battle_hand_view.gd` / `battle_deck_view.gd` 里给界面列这两个区的代码为准。
