### A1 修 P1-1：装甲共享池吃 `ignoreArmorPct`
在 `calc.gd` 抽出唯一口径，老公式和共享池都调它：

```gdscript
## 一次攻击里装甲能抵消多少（老公式的 A 与装甲共享池的初值同一口径）。
static func 抵消甲(def: Dictionary, w: Dictionary) -> float:
	if w.get("dmgType") == "特殊" or J.truthy(w.get("ignoreDef")):
		return 0.0
	var A := J.round(effArmor(def) * defMul(def))
	var 甲免 := float(J.num0(w.get("ignoreArmorPct")))
	if 甲免 > 0.0 and 甲免 <= 1.0:
		A = J.round(A * (1.0 - 甲免))
	return A
```

- `dmgCore` 第 298–305 行改为 `A = 抵消甲(def, w)`（`c.defMul` 本来就是 `defMul(def)`，口径不变）。

- 黄金样例里没有任何武器带 `ignoreArmorPct`，数值不会变；如果有变化，说明抽函数时改错了。

**规则**
1. **只放数据，不放逻辑**。现在的 `_炉底 / _势力底 / _驾驶员 / _拉塞 / _武 / _炉算子 / _并` 这些构建函数**留在代码里**，改成「读 JSON 条目 → 调同一个构建函数」。卡的默认字段、武器参转武器字典、算子包装，仍然只有一份实现。
2. **`+` 版写成显式覆盖**（深合并），名字后面的 `+` 由加载器补。不要在 JSON 里写公式，也不要搞模板引擎。现在代码里 `2800.0 * 威` 这类计算，在 JSON 里直接写成算好的数，**以快照为准**。
3. **整数和浮点**：JSON 读进来一律是 float。现有卡字典里是 `int` 的字段（例如 `剑数`、`等级需求`、`太阳炉等级`、`段数`、`距离` 的元素），由加载器按清单转回 `int`。快照比对会抓出所有类型不一致。
4. **顺序就是语义**：JSON 数组顺序必须等于现在 `append` 的顺序（牌库顺序会影响随机抽牌）。
5. 加载失败（缺文件、缺字段）时 `DataLoader.install` 报错，**不许静默回退到空卡表**。
