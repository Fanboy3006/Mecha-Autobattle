## 10. `[BR-1.1-b]`（`1079648`）增援单位发唯一键（未决 2，方案①）

- `Units.下一个键(键, 已用)`：同一个键第 n 次出现发 `键#n`（第 1 台仍用原键）。`Units.已用键表(单位们)` 把场上的
  `#n` 按 `tplKey` 归一回去数。`makeUnit` 多一个可选 `实例键`：`key` 用它、`tplKey` 写回原键
  （**只在真的重名时加 `tplKey`**，不重名的单位一个字段都没多）。
- 两条生成路径走同一份口径：开局编成 `Units.makeUnits`（只对敌方才发号）与增援 `Flow.增援`。
  增援那行战报文案改用 `name`（玩家看到 `hound`，不是 `hound#2`），字段 `单位们` 仍是 key。
- `NativeGoldenPolicy.挑目标` 在 BR-1-e 加的「只认按 key 解析得到的那台」绕行**已删掉**，改回普通写法。
- **查过的按 key 找单位的位置**（施工单要求列出来）：
  1. `BattleCardPool.找单位` 的三条路：数字 = 位号、字典 = 按引用、字符串 = `key` / `name` / `tplKey`，
     且「先找活体、找不到再退回死键」，最后才是位名兜底。重名时第一台拿到原键、第二台 `键#2` → **两者都唯一定位**；
     原键在「第一台已死、第二台活着」时会解析到 `键#2`（同一型敌人，语义上更合理）。
  2. `BattleCardPool._键匹配`（key / name / tplKey 三路）与 `BattleCardPool._是` / `Btl._是`（key 或 tplKey）

  写一行战报：`〔标定〕X（指挥）号令点名 → Y +1 层标定：n/3 层`（字段 `类型 = 标定`、`事件 = 点名`、`结果 = 指挥点名`、`生产 = 指挥`）。

  玩家看到的「标定 n 层」永远只来自特种，`每回合全场上限 = 1` 这条限制也从来没生效过。
- **接的话放在哪**：`我方阶段初_指挥` 之后最自然（读者是「指挥」，且旧顺序就在指挥被动后面），
  一行 `Calc.标定经济点名(ctx)`；会改战果（多一条指挥产层，狙击 / 范围引爆的暴击与倍率跟着变），所以按施工单**先不接**。
