# 战报分析 · 口径（**给「分析会话」看的规矩**）

> 作者 2026-10-12 原话：
> 「另外我认为需要一个对话在**理解规则的情况下检视我的游戏记录**，然后**尝试理解我的游戏思路**」
>
> 这份文件管的是**那个对话**（分析会话）：它该怎么说、不许怎么说。
> **工具**（`tools/战报分析.mjs`）负责事实层：解析 + 算术，每条结论附「依据 = 记录第 N 条」。
> **本文**负责推断层：怎么从那些事实去读作者的思路 —— 以及**在哪一步必须停下来说「这要问他」**。
>
> 开工顺序（硬要求）：**先跑工具**（`node tools/战报分析.mjs <记录.txt>`），把它的输出当**唯一的事实来源**；
> 然后照本文的规矩写分析。**工具没算出来的数字，一个都不许出现在分析里。**

---

## 0. 一句话立场

**记录是证据，不是作文。** 分析会话的任务是「把作者做过的事、它与规则的关系、当时还有什么可选项」
摆清楚 —— **不是评价他打得好不好**，也**不是替他解释动机**。

---

## 1. 事实层 vs 推断层（**最重要的一节**）

分析输出里**每一句话**都必须落在下面某一层里，并且**标出来**：

| 层 | 长什么样 | 硬要求 |
|---|---|---|
| **事实层** | 「第 1 回合我方 4 次出手、3 中 1 空，输出 23501」「第 5 回合三人全打战斗机，全空（55% / 73% / 65%）」 | **数字与序列必须来自记录**，每条后面挂「依据 = 记录第 N 条」（或「依据 = 摘要「方针」行」） |
| **推断层** | 「他倾向于先集中火力点掉一台」 | 必须标**证据强度（强 / 中 / 弱）**，并写出它依据的 **2–3 条记录**（编号 + 原文） |
| **边界（不许越）** | 「他为什么不换方针」 | 只能写「**记录里能看到的**是…」+「**需要问他**的是…」，**不许给动机** |

### 1.1 证据强度怎么定（用这三档，别自创）

- **强**：同一场里**多次**重复同一模式（≥3 次），**或**跨 ≥2 场都出现同样的模式，且**都有具体记录行**。
  例：「整场 6 回合只下过一条方针，且记录里没有任何改变方针的行」（依据 = 摘要「方针」行 + 全场没有 `〔方针〕` 改向行）。
- **中**：一场里出现 2 次，**或**只有一个数字指标（例：防御回合的平均承伤 339 vs 其它回合 1881）支持。
- **弱**：只出现 1 次，或只能靠「他没有做某件事」来说（**缺席不算证据**，除非记录本来就会写那一行）。
  例：「他一次都没把大招改成保留」—— 这条其实**算中**，因为摘要的「单位开关」那一行**本来就会写**，
  它写「（全默认：大招自动）」是**正面证据**，不是缺席。

### 1.2 写法模板（照这个写，别自由发挥）

```
【事实】第 2–5 回合，我方每次出手都在打同一台（战斗机）—— 依据 = 记录第 24、29、33、48、50、51 条。
【推断·强】目标选择上「点掉一台再换」是默认动作：全场 17 次我方出手里 11 次落在同一台身上，且换了 3 次目标，
           每一次都是前一台倒下之后才换（依据 = 记录第 5→16 条、18→19 条、34→35 条）。
【当时还有别的选择】第 5 回合三人全打战斗机（55% / 73% / 65%，全空，依据 = 记录第 48、50、51 条）——
           同一回合记录里敌方只有战斗机与无人机两台在动；改打「无人机」（当时 3 台我方的段命中率里最低的那个
           是打战斗机的 55%）…（★ 这一段**只能写记录里真的有的比较**：不许自己算一条记录里没有的分数线）
```

★ 最后那条「当时还有别的选择」**必须落在记录里真的看得见的量上**（谁还剩 HP、谁的命中率写在记录里、
方针表里那一回合写的是哪一条）。**不许**用工具算不出来的东西（例如「如果当时用集中攻击会多打多少」——
那要重跑引擎，属于另一件事，要看就说「这条要重跑才能给数」）。

---

## 2. 不要评判玩家（措辞红线）

- ❌ 不许写：「你打得好 / 差」「这个决策很糟糕」「太保守了」「失误」。
- ✅ 只写三件事：
  1. **你做了什么**（事实 + 依据）；
  2. **它与规则的关系**（这条规则叫什么、在哪儿、为什么会有这个结果）；
  3. **还有什么选择当时是可行的**（用记录里的数字说明当时那些选项各值多少）。
- 措辞换成「**中性描述**」：不写「你太保守」，写「你在 6 个回合里都选了同一档方针，记录里没有改向的痕迹」。
- 也不要**替作者下结论**：不写「所以你应该…」。要建议只能写成「如果想让 X 发生，规则上要动的是 Y」（并注明这是推测层）。

---

## 3. 要回答作者真正关心的问题

分析必须至少覆盖下面这几问（**每一问都要有事实 + 依据**，答不了就照实说「记录里没有这一项」）：

### 3.1 决策模式
| 问 | 从记录里怎么读 |
|---|---|
| 偏保守还是偏爆发？ | 方针分布（摘要「方针」行）+ 全队防御的回合数 + 大招使用率（工具 3.6 / 3.7） |
| 爱不爱改方针？ | 方针表里有几种类型（**工具异常③**会直接点出来）+ 记录里有没有 `〔方针〕` 改向行 |
| 大招留不留？ | 摘要「单位开关」那一行有没有「保留大招」；大招放了几次、在第几回合、占全场伤害多少 |
| 什么时候全军防御？ | 下过「全军防御 / 前守后攻」的回合号，以及那几个回合的敌方输出（工具 3.2 / 3.6） |
| 是不是把「集中攻击」当默认？ | 方针分布里「集中攻击」的回合占比 + 目标位换过几次（工具异常③的第 2 条） |
| 遇到厚目标会不会换目标？ | 同一台被打了几回合、每次伤害占它剩余 HP 的比例（**HP 在工具的重放里有**）、什么时候换的 |

### 3.2 「他在哪几处其实有别的选择而没选」
挑 **2–4 处**，每处必须给：**当时的记录行** + **当时那台的状态**（HP / 命中率 / 在不在场）
+ **另一条同样可行的路在记录里的数字**。**不许编造没试过的那条路的结果**：能说的只是
「当时 X 还在场上 / 当时这条方针没下过 / 当时那台的命中率记录里写着 55%」。

### 3.3 最后固定给 **3–5 个「值得问作者的问题」**
- 目的：帮他发现自己**没意识到**的习惯。
- **问题不许带倾向**：不能有褒贬、不能暗示答案。
  - ❌「你是不是觉得集中攻击更好用？」
  - ✅「第 2–5 回合你一直用同一条方针，当时有哪几条记录里的信息让你决定不改？」
  - ✅「第 5 回合三个人都打了战斗机（55% / 73% / 65% 全空），当时屏幕上是什么让你继续打它？」
- 问题要**具体到某一回合 / 某一条记录**（「你当时在想什么」这种太空的不要）。

## 4. 记录里没有的东西**不许编**（边界清单）

工具的 stdout 第 6 节会照实列出来（`记录里没有的字段`）。写分析时遇到它们，按下面的写法处理：

| 缺什么 | 分析里只能怎么写 |
|---|---|
| `单位位` / `目标位` | 同名多台（例如「无人机」两台）**分不开**：「这一场同名 2 台合成一组，所以这一行只能读成『这一组』」 |
| `目标剩余HP` | HP 靠工具重放算（**已验证与引擎逐条一致**，见 `tests/分析.js` 第 [5] 段）；重放对不上账时整块标**存疑** |
| `防御少挨` | 写「引擎算过的『全军防御少挨了多少』**记录里没有**」+ 给「防御回合平均承伤 vs 其它回合」的**对照**（并注明这是对照、不是引擎那个数） |
| `被挡` / `隐匿` / `特种减命中` | 只能从**段命中率**间接读；**不许**写「这是因为隐匿」—— 除非记录里真写了（`〔…〕` 那类行）。要写只能是「命中率被压到 40% 以下还在打（记录里只有未命中那一行会写命中率）」 |
| 每条攻击上的 `方针` / `集中` | 「这一发是在哪条方针下打的」只能靠**摘要的方针表按回合对齐**；一回合里改过方针就分不清，要照实说 |
| **通用的「X 被击破」行** | 引擎**没有**这一行 → 阵亡只能来自工具的重放（或 `〔方针〕…击破` / `〔自爆〕…` 那几条顺带提到的） |
| `藏品` 清单 / `RUN.等级` | **肉鸽那一局**的 maxHp / 伤害会被藏品改 → HP 重放**只能标存疑**（练习那一场没有藏品，是准的）。**想准就得把藏品清单也导出**（这条要报给统筹） |
| 界面上的**落点预告** | 只画在屏幕上、**不在记录里** → 「预告的落点与实际不符」这一类**判不了**（能对账的只有写在记录里的三种：Boss 蓄力声明的释放回合 / 摘要的增援计划 / TRANS-AM 声明的冷却） |
| **动机**（他为什么…） | 一律归到「**需要问他**」那一栏，不许写成结论 |

### 4.1 一条特别提醒：TRANS-AM 那种「行首回合号」口径
记录里 `〔势力〕… TRANS-AM 启动！第 A–B 回合：…` 这一条是**回合结束**时写的
（`src/js/72-势力.js:1253` 用 `ctx.turn + 1` 推进状态机），所以**行首的回合号比文本里声明的 A 小 1**。
对账一律用**文本里的 A**。工具在异常④里会自己带这句提醒。

## 5. 输出格式（固定成这几节，作者和统筹都好读）

1. **这一场是什么**：种子 / 层 / 节点类型 / 编成 / 结果 / 回合数（工具第 1 节照抄）。
2. **他做了什么**（事实层，逐回合，带依据）；
3. **他的决策模式**（推断层，每条标强 / 中 / 弱 + 2–3 条依据）；
4. **当时还有别的选择**（2–4 处，用记录里的数字说明）；
5. **值得问他的问题**（3–5 个，不带倾向）；
6. **记录里判不了的**（缺字段 + 需要他回答的边界）。

多场一起看时，先给一张**跨场对比**（工具第 5 节那张表照抄），再谈「跨场稳定的模式」（这种才是**强**证据）。

---

## 6. 不许做的四件事（违反就算这份分析作废）

1. **不许出现工具没算出来的数字**（包括「大约」「估计」）；
2. **不许评价玩家**（好 / 差 / 应该 / 失误）；
3. **不许替作者给动机**（「他一定是想…」）；
4. **不许把「记录里没有」写成「他没做」**（缺席 ≠ 事实，除非那一行本来就会写 —— 例如摘要的「单位开关」行、
   「方针」行；这两行**总是**会写，所以它们能当正面证据）。

---

## 7. 怎么跑（给分析会话的最小命令）

```bash
# 一场：作者从结算屏 / 记录屏「复制为文本」或「下载 .txt」拿到的那段，存成 .txt
node tools/战报分析.mjs 作战记录-第1层-普通-种子20261010-*.txt

# 多场一起看（会多出一张跨场对比表）
node tools/战报分析.mjs 记录A.txt 记录B.txt 记录C.txt

# 顺手存一份 Markdown 给自己看（UTF-8 无 BOM）
node tools/战报分析.mjs 记录A.txt --out=分析-A.md

# 只想快跑、不读 index.html（血量 / 大招那几项会写「记录里没有这一项」）
node tools/战报分析.mjs 记录A.txt --no-game
```

- 工具**同输入两遍输出逐字相同**（没有时间戳、没有 `Math.random`）—— 所以可以把它的输出直接引用进分析。
- 工具也能吃**本局日志导出**（大地图 / 事件层的 `RUN.日志`）—— ★ 那个格式还没定稿（另一条线在做），
  工具走宽松口径**只统计事件**，不给战斗内指标。要战斗内指标就得让作者导出**作战记录**。
