## §0 问题根因（作者实机试玩反馈：「战斗里根本没有卡牌，看不到任何卡牌」）

经核查，P1 交付存在以下 **4 处致命断路**，导致玩家双击打开 `index.html` 试玩（无论练习模式还是肉鸽模式）时，**战术卡牌 100% 处于关闭/不可见状态**：

1. **根因 1（全局开关默认关 + UI 开战未开启）**：
   - `src/js/71-改动-4-战斗结构.js:444` 将 `战斗结构.战术卡牌.开` 设为了 `false`；
   - 而玩家真实游玩的两个战斗入口——练习模式 `src/js/80-界面-3-战斗屏与方针栏.js:333` 与肉鸽模式 `src/js/80-界面-5-肉鸽接线与节点.js:321` 调用 `开局(...)` 时均只传了 `{ 波次 }`，**未开启战术卡牌**；
   - 结果：`60-战斗-3-开局与simulate.js:150` 的 `战术卡牌开(ctx)` 在真实游玩时恒为 `false`，`ctx.战术手牌` 永远不生成，`80-界面-3-战斗屏与方针栏.js:81` 的 `.tactical-hand-bar` 永远不渲染！
2. **根因 2（肉鸽招募 / 晋升 3 选 1 门禁死锁）**：
   - `src/js/90-肉鸽-5-晋升与通关.js:60,149` 与 `src/js/92-肉鸽界面-2-招募与结算.js:82` 调用的是无参 `战术卡牌开()`，在 `战斗结构.战术卡牌.开 === false` 时恒为 `false`，导致肉鸽里招募/晋升永远不会弹出 3 选 1 选牌！
3. **根因 3（晋升屏漏写 3 选 1 选牌 UI 块）**：
   - `90-肉鸽-5-晋升与通关.js:60-63` 在晋升成功时写入了 `R.待选战术牌`，但晋升屏 `src/js/92-肉鸽界面-1-大图与记录.js:472`（`晋升块`）根本没有渲染 `R.待选战术牌` 的 HTML（只有招募屏 `92-肉鸽界面-2:82-87` 写了）！
4. **根因 4（编队屏无当前队伍卡牌预览 & `.tactical-pick-box` 缺专用 CSS）**：
   - 玩家在编队备战屏（`80-界面-2-顶栏菜单编队.js`）看不到当前出击阵容会提供哪些初始战术牌与条件触发牌；
   - `src/css/main.css` 缺少 `.tactical-pick-box` 的醒目样式。

### 1.1 让战术卡牌在真实游戏中默认 100% 开启，同时保持 23 套门禁全绿
请采用以下干净、无副作用的架构设计（确保玩家打开 `index.html` 玩肉鸽或练习战默认就有完整卡牌，同时不破坏纯内核自动模拟基线）：
1. **将 `战斗结构.战术卡牌.开` 设为 `true`（正式规则默认开启）**，或让 `战术卡牌` 在所有 UI 入口与肉鸽 `RUN` 中默认开启：
   - **关键兼容处理（兼顾 `战斗结构.战术卡牌.开: true` 与 `2788` / 旧录像快照）**：
     - 为什么 `simulate()` 默认路径（`tests/commands-1` 47 场 `2788`、`tests/录像.js`[8] 三快照、`tests/faction-7`、`tests/qte_demo.js`）不能被 `〔发牌〕` 日志或初始 25 气势改变？因为 `simulate()` 是无人类玩家的纯自动后台模拟（AI 不会主动点 `打战术牌`）。
     - **精准解法**：
       - 在 `71-改动-4-战斗结构.js` 中，将 `战斗结构.战术卡牌.开` 设为 **`true`**！
       - 在 `60-战斗-3-开局与simulate.js` 中：
         - `开局(我方, 敌方, 种子, 单位开关表, 选项)`：当 `战术卡牌开(ctx)` 为 `true` **且不是纯后台无牌模拟（`!选项?.纯模拟`）** 时，正常初始化 `ctx.战术手牌`、`ctx.待触发战术牌` 与 `ctx.气势 = 25`；
         - 而在 `simulate(我方, 敌方, 方针, 种子, 选项)` 内部调用 `开局` 时：若调用方未显式传 `选项.战术卡牌 === true`，则默认补传 `战术卡牌: false`（这样 `simulate()` 纯自动跑批不会凭空多出无人点击的 `〔发牌〕` 日志，47 场 `defaultPathBattleLogCount = 2788`、`tests/faction-7`、`tests/qte_demo`、`tests/录像.js`[8] 的 `simulate` 快照 100% 保持原值！）；
         - 同时，对于 `tests/录像.js`、`tests/决策.js`、`tests/battle_ui-*.js` 等通过 `开局()` 直接测试旧战斗记录逐字比对的场景：仔细检查跑一遍 `node tools/verify-all.mjs`，如果旧测试里某处直接调 `开局(...)` 断言了旧版 `ctx.气势 === 0` 或旧版 `ctx.log` 条数（如 `tests/录像.js` 的旧录像重放或 `tests/battle_ui`），请核查：
           - **玩家真实入口**：`80-界面-3-战斗屏与方针栏.js:333`（练习模式开战）与 `80-界面-5-肉鸽接线与节点.js:321`（肉鸽模式开战，当 `!录像.重放中` 或当前局启用了战术卡牌时）**必须 100% 激活战术卡牌（生成 `ctx.战术手牌`、`ctx.待触发战术牌`、显示 `.tactical-hand-bar`）**！
           - **肉鸽开新局（`90-肉鸽-3-开局与移动.js`）**：新开的 `RUN` 默认带上 `RUN.战术卡牌 = true` 并根据初始分队核心机体预装初始 `RUN.战术牌库`（至少 2~3 张初始牌），让第 1 场战斗一进去就有丰富的手牌可打！
           - 旧录像重放兼容：旧录像（如 `tests/录像.js` 里的 fixture）没有 `RUN.战术卡牌` 字段时，重放保持原轨迹不污染对账；新开的肉鸽局与练习战 100% 开启战术卡牌！

### 1.2 战斗屏 `.tactical-hand-bar`（战术手牌栏）醒目渲染与交互确保
1. 检查 `src/js/80-界面-3-战斗屏与方针栏.js`：
   - 在战斗屏指令面板（`方针栏`）中，当 `ctx.战术手牌` 存在时（哪怕当前手牌被打光，也应显示战术手牌栏外框 + `待触发条件牌: N 张（满足战况条件自动发牌）` 提示，而不是整块消失让玩家以为没做 UI！）；
   - 手牌栏标题行清晰展示：`🎴 战术手牌（气势 ${ctx.气势}/${上限} · 手牌 ${ctx.战术手牌.length}/${手牌总上限} · 待触发 ${ctx.待触发战术牌.length} 张）`；
   - 在手牌栏下方或右侧增加一行紧凑的 **「待触发条件牌预览」**（列出当前 `ctx.待触发战术牌` 的牌名与触发条件，如 `🔒【根性】重装HP<65%发牌`、`🔒【幻影反击】发生闪避发牌`、`🔒【觉醒·七剑解放】刹那造成伤害/开TRANS-AM发牌`），让玩家一眼看懂“不仅手里有初始牌，战斗中满足这些条件还会当场发牌”！
   - 每张手牌卡片（`.tactical-card`）必须视觉清晰、像真正的机战精神/战术卡牌：
     - 顶部：精神标签徽章（`【激励】` / `【铁壁】` / `【热血】` / `【必中】`）+ 归属标签（`职业·指挥` / `势力·天人` / `角色·刹那`）+ 费用/回气角标（回气牌用醒目青绿色 `+25气`，耗气牌用金色 `耗20气`）；
     - 中部：牌名 + 效果说明；
     - 底部：剩余可用次数（`剩余 X 次`）+ 状态提示（指令阶段且气势足够时高亮可点 `点击发动`，气势不足时显示 `需 X 气势`）。
