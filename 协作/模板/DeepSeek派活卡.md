# DeepSeek 派活卡模板

> 用法：Claude 每派一次 `ds_code`，就把下面「派活卡」填好，**整段作为 `task` 参数**发出去；`files` / `read_only` / `tests` 三个参数与卡里的同名栏一致。
> 派活卡不单独存档：结果写进回执（`协作/架构/<单号>回执/<Batch>.md`），回执里引用单号即可。

## 什么活适合派给 DeepSeek
- ✅ 规格已经写死的改动：改 1~3 个文件、有明确的验收测试。
- ✅ 照现有模式补一份：新卡表条目、新钩子实现、照样子加测试。
- ✅ 纯搬家式拆文件（只移动代码，不改判断、数值、战报文案）。
- ❌ 需要做设计判断的（规则含糊、几种做法都说得通）→ Claude 先把规则写进设计稿再派。
- ❌ 跨很多文件的重构（Aider 只改 `files` 里列的文件）→ 拆成几张卡，或 Claude 自己做。
- ❌ 碰注册表边界（`rule_hooks.gd` / `fac.gd`）或体积棘轮表的 → Claude 自己做或逐行写死。

## 派活卡（复制这一段填写）

```
【单号】<如 MOON-1-a>    【一句话】<这张卡要做成什么>

【背景】（≤3 行，只给 DeepSeek 动手需要的；别贴设计讨论）
- 规则出处：<设计稿路径 §节>
- 相关现状：<现在代码是怎样的，哪个函数>

【要改的文件】（= files 参数，最多 3 个）
- <godot/core/battle/xxx.gd>：<改哪里>
- <godot/tests/unit/test_xxx.gd>：<加哪些测试>

【只读参考】（= read_only 参数）
- <照着学的文件 / 设计稿>

【具体改法】（逐条，能写死就写死：函数名、签名、键名、数值）
1. 在 <文件> 的 <函数> 里……
2. 新增 `static func <名字>(<参数>) -> <返回>`，规则是……
3. 测试：新增 `test_<名字>`，断言 <输入> → <输出>

【不许做】
- 不改 `files` 以外的文件；不改任何数值和战报文案（除非上面写明）
- 不在 calc / btl / flow / card_play 里点名势力模块
- 不删、不挪文件首行 `##` 职责注释；不写来源 / 日期标签和「从前…现在…」式注释
- 不重录黄金样例（需要重录时由 Claude 单独跑）

【验收】（= tests 参数；省略则跑全量）
- 只跑：<test_xxx, test_yyy>
- 预期：<全绿 / 新增 N 项 / 某样例差异只出现在某势力场次>
- 提交信息：`[<单号>] <一句话>`
```

---

## 收货时 Claude 只看三样
1. `ds_code` 返回的**提交号 + diff --stat**：文件是否只在 `files` 范围内，行数是否合理。
2. **测试摘要**：全绿；有 ✗ 先看失败行，再决定退回重派还是自己修。
3. **RouteMap --check**：EXIT=0；不是 0 就看 violations 那几行。

出问题才读代码；连续两次派不成的活，Claude 自己做。
