## §0 一句话

**选完分队 → 发 3 张招募券（含 ≥1 张「对应分队」的券），不再发固定五人队；机体升级（晋升）= 希望 + 同类券。
不做「打经验涨机体等级」那套。**

作者原话（`协作\分工看板.md:88-95`）：

> 「试玩第一步就和我预想不一样，我选完分队以后应该先给我 3 个招募券的。不是直接给我 5 个，然后现在的我方角色不能升级也很怪」
> 「1 分队不自带机体，但是**至少要给一张对应分队的招募券**；2 **券系统必须要做了才有试玩的意义**；3 **升级就是用券升级**」

## §1 战棋（旧仓库）里券的真实实现 —— 逐条带出处

### 1.1 券**有哪几档**？数据结构长什么样？

**结论：券本身不分档。「精锐 / 骨干 / 普通」三档是 `角色` 的档位，不是券的档位。**

- `RUN.tickets` = **字符串数组**（`27-开局.js:33` 的 `tickets:[]`；`27-开局.js:72` 的 `addTicket` 是 `RUN.tickets.push(cls)`）。
- 每个元素**要么是一个战斗分类**（`CLASSES` 六选一），**要么是一个势力名**。判据就是 `27-开局.js` 用的
  `ticketOk`：`22-输入.js:436`
  `const ticketOk = (k, m) => CLASSES.includes(k) ? tplOf(m).tags.战斗分类 === k : inFaction(tplOf(m), k);`
- 券的显示名：`22-输入.js:437`
  `const ticketName = k => CLASSES.includes(k) ? `${k}招募券` : `${k}势力招募券`;`
- 三档只出现在**价格表**里：`22-输入.js:425-430` 的 `TIER` + `TIER_NAME = {S:'精锐', A:'骨干', B:'普通'}`（`22:430`）。
- `CLASSES` / `FACTIONS`：`22-输入.js:433`（`['近卫','尖兵','指挥','重装','狙击','特种']`）、`22:435`（从 `ALLY_T` 推）。
- **券有没有上限 / 有没有 tier 字段：查不到**（全仓库 grep「券 / voucher / ticket」39 处，没有任何一处给券加档位或加数量上限）。

### 1.2 招募时券与希望的关系

**结论：券是「入场券 + 类别过滤器」，招募照样花希望；普通档本来 0 希望，所以「有券 = 那种券能免费招」。不是「券免费招」。**

- 招募入口只在券对话框里：`27-开局.js:73-90` 的 `useTicket(i)`；没有券就没有招募界面（`27:78-80` 的候选池按 `ticketOk(cls, m)` 过滤）。
- 真的扣钱：`27-开局.js:87` `RUN.hope -= recCost(v); RUN.units.push({mech:v, lv:10});`
- 价格表：`22-输入.js:431` `const PRICE = {S:{rec:5, p20:3, p30:4}, A:{rec:3, p20:2, p30:3}, B:{rec:0, p20:1, p30:2}};`
  → **精锐 5 / 骨干 3 / 普通 0 希望**；`22:445` `const recCost = m => PRICE[tierOf(m)].rec;`
- 普通档「免费」是这个 0 本身的显示：`27-开局.js:69` `${cost ? 招募 N 希望 : '<span class="cost">免费</span>'}`
- 券在招募时**被消耗**：`27-开局.js:84` `RUN.tickets.splice(i, 1);`（在「先留着」判定之后）
  —— 顺序是：`27:83 if (v === 'keep') return;` → `27:84` 删券 → `27:85-88` 丢弃 / 晋升 / 招募。
- 招募到的等级固定 Lv10（`27-开局.js:87` 的 `lv:10`）；开局选分队那一台是 Lv20（`27-开局.js:41`）。

### 1.3 晋升（升级）：`promoCost` 的完整算法 + 「同类券」是哪一档 + 「不能跳级」

- **算法**：`22-输入.js:446`
  ```js
  const promoCost = (m, to) => Math.max(0, PRICE[tierOf(m)][to === 20 ? 'p20' : 'p30']
    + (to === 20 && CAP_CHARS.includes(m) ? 1 : 0)
    - (RUN && RUN.promoDiscount ? 1 : 0)
    - (to === 20 && RUN && skLv('编制') >= 3 ? 1 : 0));
  ```
  后两项在战棋里恒不生效：`CAP_CHARS` 是空数组（`22-输入.js:432`，注释「已取消」），`skLv('编制')` 是月之国指挥官技能（指挥官系统关掉时没有）。
  所以实际值 = `PRICE[档].p20 / p30`（S 3/4、A 2/3、B 1/2），再减休整给的 `promoDiscount`，最小 0。
- **真的升**：`31-战斗.js:324-332` 的 `runPromote(m)`：
  ```js
  const to = u.lv === 10 ? 20 : u.lv === 20 ? 30 : null; if (!to) return;   // 31:326 不能跳级
  const cost = promoCost(m, to); if (cost > RUN.hope) return;               // 31:327 希望不够就退
  RUN.hope -= cost; u.lv = to; if (RUN.promoDiscount) RUN.promoDiscount = false;  // 31:328
  ```
- **「同类券」是哪一档 → 不是档，是「同一战斗分类」或「同一势力」**：
  `27-开局.js:77` `const owned = RUN.units.filter(u => ticketOk(cls, u.mech) && u.lv < 30);`
  → 这台机体所属的**职业**或**势力**和券上的名字对得上就行。
  **「Lv10→20 要骨干券、Lv20→30 要精锐券」在战棋里查不到**（没有任何按档筛券的代码）。
- **一次晋升同时花「券 + 希望」**：`27-开局.js:84`（删券）→ `27:86` `runPromote(...)`（扣希望）。
- 唯一的例外是藏品「教范」：**免费晋升 1 名该职业，既不花希望也不用券** —— `23b-藏品.js:39-44`
  （`t1`-`t6`，`special:'promo'`，desc「立即免费晋升 1 名近卫」）、`23b:123-128` 的 `relicPromo`（`u.lv = to` 直接改）。
- 界面入口（名册上点一下就升）：`29-渲染.js:62-70` 的 `teamCard`，价格不够时 `disabled`（`29:64-66`）。

**随机券的抽法**（`22-输入.js:438-442`）：

```js
const anyTicket = () => Math.random() < .6 ? pick(CLASSES) : pick(FACTIONS);   // 22:438 60% 职业券 / 40% 势力券
const squadTicket = () => RUN && (CLASSES.includes(RUN.squad) || FACTIONS.includes(RUN.squad)) ? RUN.squad : null;  // 22:440
const SQUAD_TICKET_P = .5;                                                    // 22:441
const randTicket = () => { const sq = squadTicket(); return sq && Math.random() < SQUAD_TICKET_P ? sq : anyTicket(); };  // 22:442
```

即：**50% 出本分队的券**（作者 2026-10-08 拍板「分队偏重招募券」，`22:439`），否则 60% 职业券 / 40% 势力券。
（`anyTicket` / `randTicket` 都用 `Math.random()` —— 战棋没有种子随机；**我们这边要换成 `mulberry32`**，见 §2.5。）

### 2.2 券的档位与数据结构

战棋的券是**裸字符串**（`27-开局.js:72`），但字符串分不开「职业」与「势力」的重名，也不方便以后加档位 →
我们把元素升级成对象（【初稿】，形状按本仓库数据风格：中文键名、`{键, 等级, hp比}` 那种）：

```js
RUN.券 = [
  { 类: '职业', 名: '近卫', 档: null, 来源: '开局' },
  { 类: '势力', 名: '天人', 档: null, 来源: '战后' },
]
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `类` | `'职业' \| '势力'` | 决定拿 `CLASSES` 还是 `FACTIONS` 匹配（【照抄】`22-输入.js:436` 的 `CLASSES.includes(k)` 判据） |
| `名` | 战斗分类名 / 势力名 | 显示与匹配都用它 |
| `档` | `null \| 'S' \| 'A' \| 'B'` | **默认 `null` = 不分档**（【照抄】战棋券不分档）；留着字段是为了以后按档切（§3.3） |
| `来源` | `'开局' \| '战后' \| '招募站' \| '黑市' \| '事件'` | 只用于日志 / 界面显示 |

配套函数（放 `90-肉鸽.js` 现有工具函数区，命名照本仓库习惯）：

```js
/** 这张券能不能用来招 / 晋升这台机体（照 22-输入.js:436 的 ticketOk）。 */
const 券合 = (券, 键) => {
  if (!券 || !tplOf(键)) return false;
  const t = tplOf(键);
  const 本类 = 券.类 === '职业' ? t.tags.战斗分类 === 券.名 : t.tags.势力 === 券.名;
  const 本档 = !券.档 || 券.档 === tierOf(键);        // 默认 档 = null → 恒 true（不分档）
  return 本类 && 本档;
};
/** 显示名（照 22-输入.js:437 的 ticketName）。 */
const 券名 = 券 => !券 ? '' : (券.类 === '职业' ? `${券.名}招募券` : `${券.名}势力招募券`);
```

`肉鸽数值` 里加常量（`90-肉鸽.js:42` 起那张表）：

### 2.3 招募流程

**口径（本节按任务书写；与战棋的差别在 §3.2 请作者确认）**：

- **持「对口的券」→ 免费招对应档**（【初稿·与战棋不同】战棋是「券 + 希望」，见 §1.2。理由：作者说「券系统必须要做」，
  券总量有限，免单才有获得感；代价是 `tests/rank.js` 里「花掉正确的希望」那条断言要跟着改）。
- **没用券 / 没有券 → 走现有希望价**：精锐 5 / 骨干 3 / 普通 0（【照抄】`22-输入.js:431`；我们已经有 `肉鸽数值.招募费`，`90-肉鸽.js:108`）。
- **普通档本来就 0 希望 → 没券也是免费**（【照抄】战棋 `22:431` 的 `B:{rec:0}` + `27:69` 显示「免费」）。写死在文档里，
  免得实现成「有券才 0 希望」。
- 券在招募时**消耗 1 张**（【照抄】`27-开局.js:84` 的顺序：**先删券、再给人**）。
- 招募等级：`肉鸽数值.招募等级 = 10`（`90-肉鸽.js:107`）不动；`招募等级(层)`（`90-肉鸽.js:231-232`）现在只用于预览，
  `招募()` 里 push 的是固定 10（`90-肉鸽.js:1135`）—— **券系统这一版不碰它**（列进 §2.6「不动的」）。

**界面落点**（`92-肉鸽界面.js` 的 `招募屏()`，`:262-290`）：

1. 屏顶加一段**「手上的招募券（N）」**按钮组（【照抄】战棋 `29-渲染.js:72-75` 的 `ticketCard()` +
   `29:24` 的 `[data-ticket]` 绑定）：每张券一个按钮 `data-act="用券:<下标>"` → 选中 / 取消选中。
2. **选中一张券时**，候选池按 `券合(券, 键)` 过滤（【照抄】`27-开局.js:75` 的
   `recruitPool().filter(m => ticketOk(cls, m) && !已有)`），按钮上的价格写「**券招募（0 希望）**」。
3. **没选券时**，候选池是全部（= 现在 `92:266` 的行为），价格照现在写「招募 N 希望」（`92:270-272`）。
4. **动作写法**（重要）：`界面.动作()` **只按第一个 `:` 拆一次**（`80-界面.js:195-199`），所以**不能**写
   `data-act="券招募:0:B1"`。做法：把「选中的券」放进界面状态 **`肉鸽界面.选中的券 = 下标 | null`**，

### 2.5 券的来源（【初稿】）

## §3 需要作者拍板的（4 条，每条给建议）

1. **「对应分队券」怎么定义 + `'无'` 分队怎么办？**

3. **券分不分档？**
   建议 A：**不分档（照战棋）** —— Lv10→20 与 Lv20→30 用同一张同类券，差别在 `PRICE[档].p20/p30`（S 3/4、A 2/3、B 1/2）。

## §4 风险 / 易错点

1. **券与希望混用 → 免费无限招**：如果写成「有券就 0 希望」而**券忘了消耗**（或误入战棋那个 `v === 'keep'` 提前 return 的分支，`27:83`），
   就会无限招。防：`招募()` 里**先 `splice` 券、再 push 人**（照 `27:84` 的顺序），测试断言「券 −1」。
2. **分队券定义含糊**：`CLASSES` 与 `FACTIONS` 万一重名，`券合` 就歧义。防：券**必须显式记 `类`**（这也是 §2.2 把券从字符串升成对象的原因）；
   另外 `FACTIONS` 是从 `ALLY_T` 推出来的（`12-档位职业.js:24`），**别把势力名硬编码进券逻辑**（加角色时会变）。
3. **刷新页面刷券**：25% 那条如果在界面重绘时重掷，玩家刷新就能刷。防：在 `战斗结束()` 里**掷一次并进存档**，
   界面只读 `RUN.券`；随机数一律 `mulberry32`（照 `93-藏品.js:713` 的口径），**禁用 `Math.random`**。
4. **旧存档**：最危险的是「顺手把队伍也当成开局状态清空」→ 玩家丢进度。防：`读存档()` **只补 `券`**，
   队伍 / 地图 / 推进剂一个字不动；**版本号不升**。
5. **动作名只拆第一个 `:`**（`80-界面.js:195-199`）：别写 `data-act="券招募:0:B1"`（会被当成「动作 `券招募`、参数 `0:B1`」）。
   防：券的选中状态放 `肉鸽界面.选中的券`，动作名保持 `招募:<键>`。
6. **开局名册为空 → 0 台出战**：`出击 = []` 之后，如果玩家直接点战斗节点，编队屏会是空的（甚至直接开打）。
   防：战斗类节点的入口（`80-界面.js` 的 `打这一场` / `去节点` 分支）先挡一句「名册里一台机体都没有，先去招募」；
   另外肉鸽模式下的 `默认五人队` 动作（`80-界面.js:1245-1249`）要能处理空名册。
7. **教范藏品不走券**（`93-藏品.js:446`）：玩家会问「为什么这个免费晋升不用券」→ 界面文案要写清（照战棋 `23b:123-128` 是藏品效果）。
8. **券发太多 → 晋升门槛形同虚设**：本仓库一局平均已经有 **43.70 希望**（够把默认五人队全升到 Lv30，`CLAUDE.md` M6 段），
   如果券也富裕，晋升就只剩「点一下」。防：券总量（精英 1 张 / 场）与晋升需求对齐后再定，`tests/rank.js` [7] 段顺带量。
9. **「影世界」势力券是合法的**：影世界不做势力特色（`CLAUDE.md` 第 3 节）但**有角色**，所以发到它的势力券不是 bug，
   能招到人（`12-档位职业.js:24` 从 `ALLY_T` 推 `FACTIONS`）。副势力（`tags.副势力`，`10-数据.js:218`）**这一期不参与券匹配**（§3.1 之外的事）。
10. **生成物 / 构建**：改了 `src/js/**` 必须重跑 `node tools/build-src.mjs`，否则 `--check` 红、页面还是老代码；
    若新增文件还要在 `src/shell.html` 加 `<!-- @include -->` 行。**本规格建议全部写进现有文件**（不加新 js 文件），
    这样不必动 `src/shell.html`。
11. **和另一条线冲突**：券系统的落点几乎全在 `90-肉鸽.js` / `92-肉鸽界面.js` / `80-界面.js` ——
    这几个文件现在**正在被另一条线改**（工作区未提交）。建议**排在它落地之后再开工**，或先只做 §2.2 的券数据结构（不碰界面）。
12. **`RUN.券` 的显示与「留存」语义**：券是跟着局走的（`RUN` 的一部分），
    所以「跨层留存」「出口才能用」这类原作用法**这一期不做**（照战棋：券随时可用，`29-渲染.js:72-75` 右侧卡片随时点）。
