## 1. 流程（一台机体走一遍）

| 步 | 谁 | 输入 | 输出 | 放哪 |
|---|---|---|---|---|
| 1 草图 | 作者 | — | 草图图片 + 一句话感觉 | `协作/机设/草图/<机体键>-<序号>.png` |
| 2 说明卡 | Claude 或 DeepSeek | 草图 | 机设说明卡（第 3.1 节模板） | `协作/机设/说明卡/<机体键>.md` |
| 3 像素稿 | 同上 | 草图 + 说明卡 | **2–3 个变体**（同一轮廓，不同处理），每个都有待机帧和攻击帧，透明底 PNG | `协作/机设/像素稿/<机体键>-v<N>.png` |
| 4 定稿 | 作者 | 变体 | 挑一个，在 Aseprite 里改最后一轮 | `art/battle/<机体键>/<机体键>.aseprite` |
| 5 入库 | DSH | 定稿 | 导出图集（PNG + JSON 帧信息）；换进演出 demo 看效果 | `art/battle/<机体键>/` |

- 第 3 步给变体时，**轮廓按草图不动**，变的是：细节密度、配色方案、某个部位的处理（例：推进器做成两片还是三片）。不要把作者的轮廓「改好看」。
- 第 4 步之后，作者的 Aseprite 文件就是这台机体的**唯一源文件**；以后改造型改它，别改导出的 PNG。

## 2. 草图规范（给作者）

画得越随意越好，以下几条能让 AI 读得准：

1. **画侧面全身**：战斗画面是侧面。面朝哪边都行（程序会镜像）。
2. **写一句感觉**：例「高机动近卫，推进器像披风，有点骑士味」。这一句比细节更重要。
3. **标出最在意的 2–3 处**：画个圈写「这里要大」「这里发光」「这把枪要长」。说明卡里会原样列成「必须保留」。
4. **颜色**：写字或随手涂一块都行；不写就按势力配色（`art/mech-icons.js` 的 `FACTION_PAL`）。
5. **最省事的画法**：直接在 Aseprite 的 **64×64 画布**上涂。草图本身就是像素尺寸，加工几乎不走样。拍照、截图、纸上画也都可以。

## 3. 交付格式（Claude 和 DeepSeek 一样）

### 3.1 机设说明卡模板（`协作/机设/说明卡/<机体键>.md`）

```markdown
# <机体键> <机体名>（<机师>）
- 势力 / 职业：
- 作者的一句话感觉：（原样抄）
- 草图：协作/机设/草图/<文件名>
- 轮廓要点：（3–5 条：头、肩、躯干、腿、背包 / 武器各是什么形状）
- 必须保留（作者标注的）：
- 尺寸档：我方标准 / 我方大型 / 小兵 / 精锐 / Boss（具体像素见第 3.2 节）
- 调色板：≤ 12 色，列出 hex；主色跟势力配色走
- 帧清单：待机（2 帧呼吸）/ 攻击姿势 /（可选）受击 / 头像
- 版权自查：这台机体的造型来自作者草图；没有照某一台具体作品机体的脸、配色和特征组合去画（见第 4 节）
- 变体说明：v1 / v2 / v3 各自哪里不一样
```

### 3.2 像素稿规范（和演出线共用，以 `协作/演出/演出协作.md` 为准）

- 战斗画面 240×160，整数倍放大；精灵画在 1 像素网格上，**不要半透明的抗锯齿边**。
- **SD 比例**，约 2–2.5 头身。
- 尺寸档（**初稿，演出线第 6 节第 5 条待作者拍板**）：我方标准 56–72px 高，小兵 40–50px，Boss 另定。
- 对齐点：脚底中心（图的最下一行是脚底）。
- 描边：1 像素深色外描边（可以自动生成）。
- 交付：透明底 PNG；定稿后用 Aseprite 导出「PNG 图集 + JSON 帧信息」（HTML 和 Godot 都能用）。

## 4. 版权规矩（硬规矩）

- **可以**：机器人题材的通用语汇——V 字天线、单眼、背包推进器、肩甲、光束剑、披风状装甲、三色涂装这类元素单独用。「感觉上像某类作品」也可以。
- **不可以**：照着某一台**具体作品机体**去画（同一张脸 + 同一套配色 + 同几处标志特征的组合）；用作品截图描边；把作品名或机体名写进说明卡当设计依据。
- **AI 这边的规矩**：说明卡和变体里**不为了「更像某某机体」去加特征**；作者草图如果明显是在描某台具体机体，指出来，请作者改，不照做。
- 参考截图只用来理解「感觉」，**不进仓库**（和美术线的规矩一致：`图片库/` 不进游戏）。
