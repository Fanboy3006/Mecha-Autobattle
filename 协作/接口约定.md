## 1. 全队方针（★ 2026-10-12，作者拍板的第一件）

**用途**：把「每台下一条指令」换成**两层决策** —— 全队层一条**全军方针**（保持到改为止）+ 单位层只有大招开关。
规格书 = `协作/方向调整-全队方针与反馈.md` 第 1 节（§1.1–§1.8）。

### 1.1 `设方针(ctx, 方针)` —— 全队层

```
设方针(ctx, { 类型, 目标位 }) → ctx
```

| 参数 | 说明 |
|---|---|
| `ctx` | 一次战斗的状态（`开局()` 给的） |
| `类型` | `'全军突击'`（默认）/ `'集中攻击'` / `'攻击后排'` / `'前守后攻'` / `'全军防御'`。**认不出来的当「全军突击」** |
| `目标位` | 只在 `'集中攻击'` 用：敌方**格子号**（`0..8`）。没给 / 那一格已经不活 → 引擎当成「全军突击」 |

- **返回**：同一个 `ctx`（`ctx.方针` 已经改好）。
- **保持到改为止**：回合之间**不重置**；`开局()` 里每一场新战斗是「全军突击」（§1.3 第 1 条）。
- **集中攻击的目标被击破 → 自动回全军突击**，并在**下一个回合开始**写一条
  `〔方针〕集中攻击的目标 X 已击破，恢复全军突击`（判定在 `60-战斗.js` 的 `方针回合()`，读格子号）。
- **备注**：这条**不消耗随机数**；`simulate(…, {}, …)`（不下方针）与改动前「全员进攻」**逐字相同**（§1.8 第 1 条，硬验收）。

### 1.2 `设单位开关(ctx, 开关表)` —— 单位层

```
设单位开关(ctx, { [位]: { 保留大招, TRANSAM, 本回合开TRANSAM } }) → ctx
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `保留大招` | `false` | `true` = 这一回合**不放大招**（推迟，不是作废） |
| `TRANSAM` | `'自动'` | `'手动'` = 天人的 TRANS-AM **不自动开**，等玩家点 |
| `本回合开TRANSAM` | `false` | 手动档下「这一回合点开」（点一次只管本回合） |

- **返回**：同一个 `ctx`。**没写的位 / 没写的字段一律不动**（沿用上一回合）。
- **备注**：这三个字段原来和「类型 / 目标位」挤在同一张逐台指令表里；现在**单位层只剩它们三个**。

### 1.3 `window.__game` 上的相关入口

| 名字 | 用途 |
|---|---|
| `设方针` / `设单位开关` | 上面两个（★ 新增） |
| `方针们` | `['全军突击','集中攻击','攻击后排','前守后攻','全军防御']`（界面画按钮的顺序） |
| `默认方针()` / `规整方针(p)` / `当前方针(ctx)` / `方针目标(ctx)` | 方针对象的小工具（`当前方针(ctx)` 永远有值） |
| `禁止攻击(u, ctx)` / `按防御结算(u, ctx)` | 「这条方针禁止我攻击吗」/「这一下按防御姿态结算吗」（§1.3 第 5 条） |
| `是方针对照表(方针)` / `第几回合的方针(方针, 回合)` | `simulate()` 的「按回合的表」那两个工具 |
| `方针回合(ctx)` | 回合开始时落地 + 「目标被击破 → 回突击」的那一步 |
| **`设指令`** | **已删除**（`window.__game` 上不再有；`60-战斗.js` 里那个内部函数也一起删了） |

### 1.4 `simulate(我方, 敌方, 方针, 种子, 选项)`

`方针` 三种写法（§1.6）：

1. **一条方针**（整场不变）：`'全军防御'` 或 `{ 类型: '集中攻击', 目标位: 4 }`；
2. **按回合的表**：`{ 1: '全军防御', 2: '全军突击' }` —— 表里**没写的回合沿用上一回合**；
3. `{}` / `null` / **不传** = **整场全军突击**。

**返回值不变**：`{ 结果, 原因, 回合数, 记录, 我方, 敌方, 种子, ctx }`。

## 2. 战斗记录（`ctx.log` 的字段）

- **`类型` 取值**：`开始 / 回合 / 攻击 / 修理 / 增益 / 再动 / 防御 / 回复 / 跳过 / 指挥 / 增援 / 嘲讽 / 连斩 /
  残月余响 / 势力 / Boss / 方针 / 结束`（★ 新增 **`方针`**）。
- ★ **2026-10-12 起，攻击记录里这三个字段不再会产生新值**，但**字段本身保留**（值恒为默认），
  这样默认路径的记录格式**一个字节都不变**（§1.8 第 1 条）：
  `集火: false` / `守护挡下: false` / `原目标: null` / `原目标位: null`。
  （实测：改动前的 39 场 / 1638 条记录里，这四个字段**一个 true / 非 null 都没有**。）
- **新增记录**：`类型: '方针'`，文本 `〔方针〕集中攻击的目标 X 已击破，恢复全军突击`，
  字段 `{ 方针, 原方针, 目标位, 目标名, 回合 }`。
- **不再有的记录**：`〔守护〕…替…挡下这一击`、`〔换位〕…换位到…`（机制已删，§1.4）。
- **单位的 `u.指令` / `u.指定目标位` / `u.守护对象` 三个字段已删**：谁都不许再读写它们。
  要「这台单位这一回合做什么」，读它行动时写下的那条记录。

## 6. 三层反馈（★ 2026-10-12，作者拍板的第 2 件）

**用途**：玩家的每个决策都要有**预告 / 即时 / 结算**三层反馈（§2.1 的规矩，已立成 `CLAUDE.md` 第 7 节第 10 条）。
规格书 = `协作/方向调整-全队方针与反馈.md` 第 2 节（§2.2 五行表 / §2.3 / §2.4）。
实现 = 新文件 `src/js/84-反馈.js`（预告 + 结算，**纯读**）+ `60-战斗.js` / `20-战斗计算.js`（即时，记录字段）。
**这一层只做显示与统计**：不改任何战斗数值与判定、**不消耗随机数**（§2.4）。

### 6.1 记录里的新字段（`ctx.log` 的每一条）

| 字段 | 写在哪 | 值 | 什么时候写 |
|---|---|---|---|
| `方针` | 攻击记录 / 防御记录 | 当时的全队方针字符串 | **只在我方出手**且**不是「全军突击」**时 |
| `集中: true` | 攻击记录 | true | 这一发打在「集中攻击」点名的**那一台**上（比**单位对象**，不比格子号） |
| `被挡: true` + `被挡惩罚: -20` | 攻击记录 | 命中修正 | 我方直射打**被挡的后排位**（`rowBlockPenalty() < 0`）且下过方针 |
| `防御少挨` | 攻击记录 | 正整数 | 这一下按**防御姿态**结算、且真的挨到伤害（= 不带防御加成时会挨的 − 实际挨的） |
| `事件: '集中攻击击破'` | 类型 `方针` 的记录 | 字符串 | 集中攻击点名那台被这一发打死 → 紧跟一条 `〔方针〕集中攻击击破 X` |

- ★ **默认路径（全军突击 / 没有我方命中被挡位 / 没人挨防御姿态的攻击）这五个字段一个都不出现** ——
  §1.8 第 1 条「默认路径逐字不变」继续成立（实测：整张编成表 39 场 / 1638 条与改动前快照**逐字节相同**）。
- ⚠ **格子号是分边的**（我方「位 0」与敌方「位 0」是两个格子）：判定「是不是点名那一台」必须比**单位对象**
  （`实际 === 方针目标(ctx)`）——只比 `slot` 会把「敌方打我方位 0」误标成集中（这一版修掉了这个 bug，
  `tests/battle_ui.js` 第 [9] 段与 `tests/commands.js` 第 [10] 段盯着）。
- `dmgCore(att, w, def, o)` 新增一个**只给显示用**的选项：`o.不带防御加成: true` → 强制 `defending = false`
  （`20-战斗计算.js`）。只用来算「防御少挨了多少」；走 `preview: true` 时**不动任何计数器、不消耗随机数**。

### 6.2 `window.__game` 上的新入口

| 名字 | 用途 |
|---|---|
| `集中攻击预告(ctx)` | → `{目标位, 目标名, 剩余HP, 预计伤害合计, 台数, 会打, 详情}`（`台数` = 打得到它的；`会打` = 这一回合真的会打它的） |

| `预告快照(ctx)` | 上面几样一次性算好（界面画卡片用）→ `{回合, 方针, 集中, 大招, 防御位, 后排位, 后排我能, 防御说明}` |
| `反馈标签(记录)` | 记录 → 卡片上那个小标签（`集中` / `被挡 −20` / `防御 少挨 N`），没有就空串 |
| `战报统计(战斗)` / `战报行们(战斗)` / `本场战报Html(行们, 副标题)` | 本场战报（**数据全部从记录统计**）；`战斗` 可以是 `ctx`（`log`/`allies`）或结算屏的 `战报`（`记录`/`我方`） |

| `chooseAttack` | ★ 新暴露：单台在**当前方针**下会打谁 / 期望多少（预告与测试对账用） |

## 7. 敌人机制钩子（★ 2026-10-12，作者批的「敌人卡第一批」）

**用途**：把 `ENEMY_T` 里**早就写着、一直没人读**的三个 `abilities` 键接上（`协作/敌人机制盘点-可用的钩子.md`
的 **B1 / B4 / B3**）——**幻影**（`stealth`，命中 −35）/ **镜甲**（`beamReflect`，受到的 30% 反弹）/
**献祭者**（`selfDestruct`，击破瞬间自爆）。规格书 = `协作/敌人卡-第一批.md`（三张卡）。
数据侧**一个字节都不改**（`10-数据.js` 是战棋复制件）：三个钩子读的就是**数据里已有**的那三个键。

- **参数表**：`战斗结构.敌人机制`（`src/js/71-改动.js`）——
  `{ 开, 只给敌人, 称谓:{敌人键→名字}, 隐匿:{命中惩罚, 吃惩罚的射程}, 镜甲:{反弹比例},
     自爆:{威力倍率, 濒死线, 范围, 武器名} }`。**所有数值都是【初稿·待作者在调参室调】。**
- **`开: false`** = 三个钩子全部退回改动前（**逐字不变**的验证口径；界面 / 测试都读它）。
- **`只给敌人: true`** = 只对 `side === 'enemy'` 生效。★ 我方 `S2 卡嘉莉` 的数据里也有 `beamReflect`
  （`10-数据.js:139`，战棋的「光束反射」特技）：**这一批没接我方那一条**（写 `只给敌人: false` 就能打开）。

### 7.1 记录里的新字段（`ctx.log`，**只在真发生时才写**）

| 字段 | 类型 | 写在哪 | 什么时候写 |
|---|---|---|---|
| `隐匿: true` + `隐匿惩罚: 35` | 布尔 + 整数 | 攻击记录 | 打**幻影**、这一发**整次一段都没中**、且这一发真的吃了那个惩罚（直射 / 曲射） |
| `类型: '镜甲'` | 新记录类型 | —— | 打**镜甲**、这一发造成了伤害 → **紧接着那条攻击记录**写一条反弹记录 |
| `反弹` / `伤害`（= 反弹量）/ `原伤害` / `反弹比例` | 整数 / 小数 | 镜甲记录 | 同上（`单位方/单位位` = 镜甲那台，`目标方/目标位` = 挨反弹的攻击者，`目标剩余HP` = 攻击者挨完的 HP） |
| `类型: '自爆'` + `自爆: true` + `自爆伤害` + `自爆少挨` + `威力` + `落点们` + `命中数` | 汇总行 | 自爆记录 | **献祭者被击破的瞬间**（一条汇总行；`单位方/单位位` = 自爆那台，**没有 `目标方/目标位`**） |
| `自爆: true` + `自爆落点` | 逐台行 | 攻击记录 | 上面那条汇总行**之后**逐台一条（和普通范围攻击同形状，播放 / 战报直接认） |

- ★ **默认路径（没有这三个键的敌人 / `开: false`）这些字段一个都不出现** ——
  实测：39 场 / 1638 条记录与「方针前快照」**逐字节相同**（`tests/commands.js` 第 [1] 段）。
- ⚠ **镜甲那一条不走 `resolveAttack()`**（卡里原本建议「可重入地打回去」）：那会为反弹那一发掷命中 / 暴击，
  **改变随机数消耗顺序**，与同一张卡上的红线冲突。实现改成「按实际造成的伤害直接扣 HP」→ **一个 `ctx.rng` 都不调**
  （`tests/boss.js` 第 [12] 段有 rng 调用次数与攻击记录逐字对照）。

### 7.2 `window.__game` 上的新入口

## 9. 招募的券门槛（★ 2026-10-12，修作者试玩报的真 bug）

**用途**：`肉鸽.招募(键, 参)` 从「**不传券也能招**（价格 = 希望价）」改成「**没有可用的券就拒绝**」——
照任务书 §7 / §8 第 1 条 + 战棋 `27-开局.js:77` 的 `ticketOk`：**招募必须用掉一张同类券（职业 / 势力对得上）+ 希望，
券与希望同时消耗**。不改这条约定的后果就是作者看到的那个 bug（普通档招募费 0 希望 → **0 希望无限招人**）。
`晋升()` 的同类判据本来就是对的（没券 → 拒绝、希望一分不扣），没有动。

### 9.1 行为变更（**调用方必须知道**）

| | 改前 | 改后 |
|---|---|---|
| `招募(键)`（**不传 `参`**） | `ok:true`，按希望价招人（**普通档 0 希望 = 免费**，可无限招） | **`ok:false`**，`why` 见 9.2；**希望与名册一分不动** |

| 判据顺序 | 队伍上限 → 不能重复 → 券对不对得上 → 希望 | 队伍上限 → 不能重复 → **有没有券** → 券对不对得上 → 希望（照 `晋升()` 的「先判完再动手」） |

### 存储：**独立** `localStorage` 键 `mecha-autobattle-录像`

```

```

- `RUN` 结构**不改**、肉鸽存档版本号**不动**（和 `mecha-autobattle-run-v4`、`mecha-autobattle-战斗记录` 都无关）。

### 录像格式（一份 = 一局）

```jsonc
{ "格式版本": 1, "游戏版本": "0.6.2", "种子": 20261010, "分队": "无",
  "开始时间": "2026-10-12 19:30:04", "结束时间": "…", "结果": "胜|败|放弃", "结果原因": "…",

              "回合": 1, "理由": "…", "对账": "层1 场0 …", "弹窗": "遗迹", "可选项": ["藤蔓","交流","离开"] } ],
  "最终摘要": { … } }
```

| 字段 | 说明 |
|---|---|
| `格式版本` | 录像格式自己的版本（游戏版本另有一个 `游戏版本`） |
| `游戏版本` | 录的时候 `__game.version`（重放时不同 → **先警告、照样重放**） |
| `种子` / `分队` | `开新局` 用的种子（界面按钮不传参数时记**实际取到的那个**）/ 开局选的分队 |
| `开始时间` / `结束时间` | `开始时间` 取自 `RUN.t0`（读档回来不变 → 会话身份 = 种子 + 分队 + 开始时间） |
| `结果` / `结果原因` | 胜（通关）/ 败 / 放弃（玩家放弃） |
| `操作[]` | 每一步：`序号`（1 起）/ `屏` / `动作` / `参数`（**动作名 = 动作表里的键**）；战斗内带 `回合`；关键选择可带 `理由`；每步都带 `对账`（这一步做完那一瞬间的紧凑局面串）；弹窗答案那一步带 `弹窗` / `可选项` |
| `最终摘要` | 一局结束时 `RUN` 的**规范化投影**（去掉 `日志[].时间` / `t0` / `已走过集` 等随时间变的东西）—— 重放完逐字比对 |

  （连告知 / 开关 / 试传按钮都不出现）——「与现在完全一致」由 `tests/上报.js` 第 [1] 段钉着。
- 想临时换地址（不改代码）：`__game.上报.设地址('https://…/exec')`（`设地址(null)` = 回到常量）。

### 存储：**两个独立** localStorage 键（和录像键 / 肉鸽存档 / 作战记录都无关）

| 键 | 内容 | 谁写 |
|---|---|---|
| `mecha-autobattle-已上报` | `{版本:1, 已上报:[对局ID…]}`（最多 500 条，超了从最老丢）—— **只有成功发出才写** | `上报.标记已上报(对局ID)` |
| `mecha-autobattle-上报开关` | `'1'` = 开 / `'0'` = 关（没有这个键 = 用 `上报默认开`） | `上报.设开关(开)` / `上报.切开关()` |

- **`mecha-autobattle-录像`（录像那条线的键）只读**：`8a-上报.js` **一个字节都不写它**，
  更**不挂封存回调**（这是为了不和「回血」线撞 `89-录像.js`）。

### POST 的载荷（字段名一个都不改，照规格第三节）

```jsonc
POST <上报地址>            // mode:'no-cors' + Content-Type: 'text/plain;charset=utf-8'（Apps Script 不给 CORS 头）
{ "对局ID": "604292-20261012-2340", "时间": "2026-10-12T23:40:57+08:00",
  "种子": 604292, "版本": "0.6.2", "分队": "近卫", "结果": "败",
  "层": 1, "回合数": 7, "时长秒": 812, "操作数": 4,
  "录像": { … }            // 一份录像**原样**（格式见本文「对局录像」一节）—— 不截断、不改写、不加字段
}
```

| 字段 | 怎么来的（本线自己定的口径只这两条） |
|---|---|
| `对局ID` | `种子-开始时间`（`2026-10-12 23:40:57` → `604292-20261012-2340`）= **去重用，不是身份**；开始时间没有就用结束时间 |
| `时间` | **开始时间**的带时区 ISO（跟玩家浏览器时区）；没有开始时间 → 结束时间 → 现在 |
| `种子` / `版本` / `分队` / `结果` | 录像里的 `种子` / `游戏版本`（没有就读 `__game.version`）/ `分队`（没有写「无」）/ `结果`（胜 / 败 / 放弃） |
| `层` | 录像 `最终摘要.层`（没有 → `''`） |
| ★ `回合数` | 操作流水里出现过的**最大回合号**（录像只记操作、不单独记回合数；没有 → 0） |
| `时长秒` | 结束时间 − 开始时间（有一个解析不出来 → 0）；`操作数` = `操作.length` |

- **no-cors 读不到响应** → **一律按成功**；真正的去重由**接收端**按 `对局ID` 做（规格第四节）。
- **失败不打扰**：`fetch` reject / 没有 `fetch` / 地址为空 / `localStorage` 坏 → **绝不 throw、绝不弹窗、不改 `RUN`**，
  失败的那一局**留在队列里**，下次进页面（`boot()` → 开屏菜单）自动重试。

### 触发点（只有两处，都在 `80-界面.js` 的渲染里；**纯追加**）

1. `菜单屏()` 顶部一句 `上报.顺便传()`、`</section>` 之前 `${上报.菜单块()}`
   —— **页面加载时 `boot()` → `开屏('菜单')` 走的正是这一条路**；
2. `结算屏()` 顶部一句 `上报.顺便传()`。
