## §4 Batch D：规则钩子注册表（第一步）

### D0 先做 30 分钟技术验证
在 Godot 4.7.2 下确认这两件事能成立，并把结论写进回执：
- 对一个 `class_name` 脚本，`var m: Script = AtxThree` 之后用 `m.call("命中修正", a, b, c, d)` 能调到它的 **static func**；
- 可以用 `m.get_script_method_list()` 拿到方法名集合，用来判断「这个模块有没有实现某个钩子」。

如果其中任何一条不成立，就退回到「注册表文件内用 `match 模块名` 分派」的写法。**两种写法对外的接口相同**，通用内核都不需要知道具体有哪些模块。

### D1 新建 `core/battle/rule_hooks.gd`（`class_name RuleHooks`）
- **注册表本身**是唯一允许点名势力 / 职业模块的通用文件。和 `fac.gd` 一样，从规则 ⑤ 的「通用内核」里排除；在 `build_godot_routemap.mjs` 里同步改口径，并在 RouteMap §4.0 注明。
- **每个钩子一份显式顺序表**（顺序等于现在代码里的调用顺序；乘法链每一步都有 `J.round`，所以顺序就是数值）：

```gdscript
const 顺序 := {
	# —— calc.gd ——
	"闪避加成":     [AtxThree],
	"命中修正":     [AtxGodsbet, AtxSmoke, ClassCards, AtxDuo, AtxThree, CelestialV01],  # 加法，汇总后统一 round
	"暴击修正":     [AtxThree],
	"受击前":       [AtxChips, AtxDuo, AtxThree],                                          # 有副作用，按序
	"攻方伤害倍率": [ClassCards, CelestialV01],                                             # 每步 d = J.round(d × 倍)
	"受方伤害倍率": [CelestialV01, AtxDuo],                                                 # 同上
	"致命保留":     [AtxChips, ClassCards],
	"攻击后":       [ClassCards, AtxDuo, AtxThree],
	# —— btl.gd 阶段时序 ——
	"我方阶段初_前": [FacAtx, AtxChips, AtxGodsbet, AtxSmoke],          # 在「回合初战意 + 抽牌」之前
	"我方阶段初_后": [ClassCards, AtxDuo, AtxThree, CelestialV01],      # 在 DeckFlow.阶段初_武器恢复 / 检查之后
	"敌方阶段初":   [AtxDuo, AtxThree, CelestialV01],
	"我方阶段末":   [CelestialV01],
}
```

- 上表是按我读到的现行代码整理的。**以你对照代码核实后的顺序为准**，有出入就改表，并在回执里列出改了哪些。
- **接口约定**：
  - 汇总类（`命中修正` 之类）返回数值，不实现的模块视为 0 或 1；
  - 事件类（`受击前` 之类）返回 void；
  - 每个钩子在模块里的函数名与签名要一致。现在名字不一致的，在模块里加一个**薄转发函数**，不改原函数，降低风险。例如 CelestialV01 的「攻方伤害倍率」 = `伤害倍率(ctx, att, w) × 根除战争倍率(ctx, att, def)`，与现行代码一样先相乘、再 round 一次。
- 「特殊钩子」**不进**注册表，留在原处：`AtxGodsbet` 的翻盘（会消耗随机数，改判打空段）、`CelestialV01.狙溢暴击`、`AtxSmoke` 用于详情显示的那次读取。在 `calc.gd` 里给它们加上 `# [规则钩子·特例] 原因：…` 标签，方便以后统一处理。
