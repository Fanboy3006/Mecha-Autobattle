## §1 Batch A：先把通用设施做好，并给所有要搬的卡表拍快照

### A1 卡包结构改为卡包自己声明（`session/data_loader.gd`）
现在 `卡包必需` 写死了天人专有的顶层键（太阳炉 / 拉塞 / 驾驶员 / 纳德雷），没法用到别的卡包上。改成：
- 每个卡包 JSON 在顶层写自己的结构声明：

```json
{
  "势力": "天人",
  "设计稿": "协作/设计/天人势力卡牌设计 v0.1.md",
  "结构": { "太阳炉": "卡组", "势力牌": "卡组", "拉塞": "卡组", "驾驶员": "分人卡组", "大招": "单卡", "纳德雷": "武器表" },
  "太阳炉": [ ... ]
}
```

  `卡组` = 非空数组，每条都要有 `id` 和 `名`；`分人卡组` = 字典，每个值是一个卡组；`单卡` = 一个带 `id` 和 `名` 的字典；`武器表` = 非空字典或数组。需要新的类型就在 loader 里加一条判定，**不要**在 loader 里按势力名写特判。
- `CARD_PACKS` 改成**扫描** `res://data/cards/*.json`，按文件名排序加载，不再手写列表。
- **新增全局检查**：所有卡包里的卡 `id` 必须全局唯一（`+` 版用自己的 id，或者由加载器统一加后缀，按现有规则）。有重复就整单报错。
- 给 `天人.json` 补上 `"结构"` 声明（数据本身不动）。天人快照必须逐字一致。

### A2 卡表快照通用化（`tests/unit/test_card_table_snapshot.gd`）
- 把「天人 14 组」改成一张**注册表**：每个卡包登记若干组「名字 → 取卡表的函数」，每个卡包一份快照文件 `tests/golden/card_tables/<卡包名>.txt`，判定方法不变（`var_to_str`，逐字比对；快照不存在时生成并报 ✗）。
- **在本 Batch 里、搬家之前**，为下面这些函数生成快照并提交（这样快照的来源一看提交记录就清楚，不用事后再核对）：

| 快照文件 | 登记的取表函数（以实际存在的公开函数为准，回执里列出最终清单） |
|---|---|
| `秘银.txt` | `MithrilV03Cards.卡表()`，以及各角色、连携牌、势力牌、分类牌的分组取法 |
| `ATX.txt` | `AtxThree.卡表()`、`AtxThree.升版卡表()`、`FacAtx.卡表()`、`AtxChips.卡表()`、`AtxChips.初始筹码牌库()`、`AtxDuo.卡表()` |
| `职业分类牌.txt` | `ClassCards.卡表()` |

- 快照**必须覆盖** `+` 版，以及按等级 / 档位筛选的取法（例如 `角色牌们加版`、`角色专属牌们按等级`）。这些筛选逻辑留在代码里，但它们的输出要被快照锁住。

## §2 Batch B：秘银 v0.3 卡表抽数据（`mithril_v03_cards.gd`）

**现状**（Claude 实测）：86,782 B，卡表构建段 `_宗介 / _克鲁兹 / _毛 / _克鲁佐 / _杨 / _连携牌 / _势力牌 / _分类牌` 共约 39 KB，**占 45%**，是本单收益最大的一个文件。

**做法**（照 CR-1 天人的做法）
- 新建 `data/cards/秘银.json`，结构里每个构建函数对应一段（例如 `宗介 / 克鲁兹 / 毛 / 克鲁佐 / 杨 / 连携牌 / 势力牌 / 分类牌`）。
- **只搬数据**：`_底`、武器参转换、算子包装这些构建函数留在代码里，改成「读 JSON 条目 → 调同一个构建函数」。
- `+` 版写成显式覆盖（深合并），JSON 里**不写公式**。代码里现在计算出来的数，在 JSON 里直接写算好的值，浮点精度以快照为准（照搬 `3219.9999999999995` 这种数，不规整）。
- JSON 读进来的数值都是 float。现有卡字典里是 `int` 的字段，由加载侧按清单转回 `int`，快照会抓出所有类型不一致。
- **数组顺序就是语义**（牌库顺序影响随机抽牌），必须等于现在 `append` 的顺序。
- 静态缓存照天人的做法，按 `Db.代` 失效。

**验收**：秘银快照逐字一致；`mithril_v03_cards.gd` 字节下降 ≥ 40%；全量门禁绿。
