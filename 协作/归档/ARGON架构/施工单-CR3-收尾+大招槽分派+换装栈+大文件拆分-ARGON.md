## §2 Batch B：`DeckFlow` 大招槽改为按处理者分派

**现状**：`DeckFlow.大招不可打原因` 和 `打出大招` 里，有一串「是天人吗 / 是赌神入局卡吗 / 是 v01 别名吗 / 是合体技吗」的判断（`deck_flow.gd` 里还有约 117 处对势力的引用）。殖民卫星军、影世界加进来，还得继续往这串判断后面追加。

**做法**
1. 装填大招槽的时候，在每个槽条目上写 `处理者`（模块名字符串，例如 `"AtxGodsbet"`、`"AtxThree"`、`"AtxFaction"`、`"CelestialV01"`；通用大招不写）。写入点就在各模块现有的 `装填大招槽` / `放入大招槽` 里。
2. `RuleHooks` 加三个按处理者分派的钩子：`大招不可打原因(ctx, u, 槽)`、`打出大招(ctx, u, 槽, 目标)`、`大招阶段初(ctx, u, 槽)`。用 `RuleHooks.按处理者(槽.处理者, 钩子, 参)` 分派；没有处理者、或处理者没实现这个钩子，就走通用逻辑。
3. `DeckFlow`：
   - `大招不可打原因`：最顶层的断路器 2（`本回合已打`）**原样保留**，它是全局规则，不归任何模块；之后先问处理者，再走通用门槛。
   - `打出大招`：有处理者且处理者实现了钩子，就整段交给它；否则走通用逻辑。
   - `阶段初_冷却与维持` 里对 `v01别名` 的跳过，改成「处理者实现了 `大招阶段初` 就交给它」。
4. 把 `CelestialV01.记打出 / 打出前介入`、`AtxSmoke.打出时`、`AtxLuck.打出时`、`AtxFaction.尝试二次下注` 这类插在通用打出流程里的调用，收进 `RuleHooks` 的事件钩子 `大招打出前 / 大招打出后`（每个钩子一份显式顺序表）。

**验收**
- 全量门禁绿，行为零变化。
- `deck_flow.gd` 的规则 ⑤ 计数明显下降，回执里写出前后值，并下调基线。

## §3 Batch C：武器栏换装栈

**现状**：`DeckFlow.切换武器栏` 只记了一份 `武器栏原样`，`"overlay"` 模式实际没有实现；λ 驱动另有一套 `λ换武器 / λ还原武器`，里面写死了 `V3_U7_W1 → V3_U7_LW1` 这类秘银卡 id，而且还原时用 `MithrilV03Cards.卡(原)` 重建原卡，会把卡上的运行期状态（冷却等）重置掉。

**做法**
1. `DeckFlow` 新增：

```gdscript
## 压一层武器栏（来源唯一，例如 "λ驱动" / "脱装" / "METEOR"）。永久 = true 的层不能弹出。
static func 压栈武器栏(u: Dictionary, 新表: Array, 来源: String, 永久: bool = false) -> void
## 弹出指定来源的那一层：原样恢复压栈前的武器卡对象（同一个字典引用，运行期字段一律保留）。
static func 弹栈武器栏(u: Dictionary, 来源: String) -> bool
static func 当前换装来源(u: Dictionary) -> Array
```

   - 栈存在 `u.武器栏栈 = [{来源, 永久, 原表}]`。原表保存的是**原来那组卡对象本身**，不复制、不重建。
   - 同一来源重复压栈时直接忽略，并记一条战报。
   - 永久层上面还可以再压临时层；弹出时只弹指定来源。
2. λ 驱动：`λ换武器 / λ还原武器` 改为调用压栈 / 弹栈，来源 `"λ驱动"`。替换表（W1 → LW1、W2 → LW2、加上 LW3）挪进秘银模块，例如 `MithrilV03Cards.λ武器表(u)`，**`deck_flow.gd` 里不再出现秘银卡 id**。
3. 脱装·纳德雷：改为 `压栈武器栏(u, 纳德雷武器表("CB4"), "脱装", true)`；删除旧的 `切换武器栏`（或者保留为 `压栈(…, 永久 = true)` 的一行包装）。
4. **补测试**：
   - λ 开启时某把原武器还在冷却中 → 关闭 λ 后冷却数值不变（Review 报告 P3-5 的风险点）；
   - 脱装之后再开一个临时层，再弹出临时层 → 回到纳德雷武器表，不会回到原表。

**验收**：全量门禁绿；上面两条新测试绿；`grep -n "V3_U7_" core/battle/deck_flow.gd` 无结果。
