## §1 分层（迁移目标的边界）

| 层 | 片段 | Godot 端去向 |
|---|---|---|
| L0 基础与数据 | `00` `05` `10` `11` `12` | 数据资源（Resource / JSON），阵型几何移植成纯函数 |

依赖方向的目标：**只允许高层 → 低层**。L2 不能依赖 L3~L6。

## §4 对账协议（Oracle）草案方向

- **输入**：`{ 规则签名, 我方, 敌方, 种子, 选项(含 战术卡牌 / 已选战术牌 / 藏品 / 调参), 命令流[] }`。命令流是 MBR-3 的可序列化命令：`{ 回合, 类型, 参数 }`。
- **输出**：`ctx.log` 逐行 JSON（字段按 `协作/接口约定.md` 登记的为准）+ 每回合末的状态哈希（单位 HP / 护盾 / 增益 / 气势 / 手牌 id 列表 / rng 步数）。
- **对账粒度**：先对每回合状态哈希，不一致时再逐条对日志，定位到第一条分叉事件。
- **前提**：S1、S2 拆完、MBR-2 落地后，内核才是 `(输入, 命令流) → 输出` 的纯函数，协议才成立。
