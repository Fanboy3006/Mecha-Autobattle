### 2.2 `词条` 的语义（**只用对账判成 `现成` / `小改` 的机制**）

| 字段 | 取值 | 语义 |
|---|---|---|
| `作用` | `'全体'` / `'单台'` | `全体` = 这一条编成里**全部**敌人；`单台` = 只作用在 `位` 指定的那一台 |

| `值` | 整数 / 布尔 | 加数或开关 |
| `叠加` | 缺省 `'不叠'` / `'叠'` | **同一台、同一个键**撞车时：`不叠` = 后面覆盖前面（**默认**）；`叠` = 相加 |

### 2.3 抽取的确定性规则（照现在 `抽编成(层, 类型, rng)` 的口径）

**现状（我读到的）**：`肉鸽.抽当前编成详情()` 的种子是
`mulberry32((R.种子 + R.层 * 131 + R.场次 * 17 + (n.k || 0) * 7) >>> 0)`（`90-肉鸽.js:1063`），
拿到 `rng` 后交给 `抽编成兜底(层, 类型, rng, 记)`（`70-编成.js:259`），
里面 `抽一条` = `候选[Math.min(候选.length − 1, Math.floor(r() * 候选.length))]`（`:261-264`）。

**新规则（池子变大、加一层挂载，抽取口径一个字不改）**：

```
第 L 层第 S 场、格号 K 的战斗节点：
  rng   = mulberry32((RUN.种子 + L×131 + S×17 + K×7) >>> 0)     ← 与现在逐字相同
  候选  = 选编成(L, 当前战斗类型(节点))                            ← 池子：普通 3→7 条、精英 3 条、守军 3 条
  条目  = 候选[ floor(rng() * 候选.length) ]                      ← 均匀抽，与现在同构
  词条  = 条目.词条  ＋（条目.挂载 若写了，把那份词条组整组叠上）    ← ★「必定挂载 1-EE」就落在这里
```

**五条必须写进注释的边界**：

1. **`词条` 的落地必须在「这一场的随机数已经抽完」之后** —— `词条` **不许消耗 `rng`**
   （否则整场随机数序列会挪位，「同种子逐字相同」当场失效）。**`词条` 全部是确定性数据。**
2. **挂载不额外抽一次**：`挂载` 是**无条件叠上**的（原话「**必定**挂载」），**不占 `rng`、不影响均匀分布**。
3. **兜底路径照旧**：`抽编成兜底` 的五级退回**一个字不改**（`70-编成.js:259-296`）。池子变大只让第 ① 步更容易命中。
4. **`重点: true` 不参与均匀抽取**（它只给人看）。如果作者要「守关必须按固定场次出现」，
   写法是**加一条 `每N场` 规则**（下一版再做），**默认不做**。
5. **`RUN.场次` 的自增点不变**（`90-肉鸽.js:1511` 的 `R.场次++`），所以第几场是稳定的。

## 6. 验收口径草案

> 三条口径都**只读**，不改任何代码；跑法建议放仓库外 `F:\DSH-mecha\_probe\`
> （先例：`_probe\扫参.mjs`、`_probe\方针前快照.json`）。
> ★ 遵守 `协作\协作框架.md` 第 16 节：**不变量要写成本构建内的关系式**（开 / 关、传 / 不传、A / B 对比），
> **不许钉历史常量**。

### 6.1 同一层反复开局 → 池子抽取分布（每个变体都出现过）

**口径**：固定一层一种类型 + 固定队伍与方针 + **换种子**跑 N 局，每局记下抽到的 `编号`
（或直接调 `肉鸽.抽当前编成详情()` 逐场读 `编号`）。

- **通过线**：**每个变体至少出现 1 次**；且最大 / 最小频次比 **≤ 3.0**（池子 7 条、N = 200 时，均匀抽的期望 ≈ 28.6 次/条）。
- **N 的取法**：**先跑 N = 200**；若某个变体 0 次，**换一批种子再跑 200**（失败线 = 连换三批都没有）。
- **要报的数字**：逐条编号的命中次数 + 最大最小比 + 「有没有一条从没出现」。
- **★ 挂载要单独验**：`1-EE` **不该**出现在 `编号` 分布里（它不占 `rng`），
  但**每一场精英战的词条组里都必须有 `1-EE` 那一组**（= 「必定挂载」的验收）。
- ⚠ 同一局里 `RUN.场次` 会自增（`90-肉鸽.js:1511`），所以**本层第 1 场 / 第 2 场要分开统计**。

### 6.2 同种子逐字相同

**口径**：同一个 `RUN.种子` + 同一套输入，**跑两遍**，比：

| 比什么 | 怎么比 | 依据 |
|---|---|---|
| `simulate()` 的返回 | `结果` / `原因` / `回合数` / `记录`（**逐字节**） | `60-战斗.js:874-877` 的返回形状 |
| 每一场抽到的 `编号` | 两遍的 `编号` 序列**逐字相同** | `90-肉鸽.js:1063` 的种子公式 |
| 记录里跟词条有关的字段 | 两遍**字段数也一样**（不是「没有就跳过」，是「一条都不多、一条都不少」） | `71-改动.js:1204` 那套「逐字不变」先例 |
| `_probe` 快照 | 存两份 JSON 比 SHA256（照 `方针前快照.json`） | `CLAUDE.md` 第 2 节 |

★ **额外一条**（最容易踩）：**`词条` 与 `挂载` 都不许消耗 `rng`** ——
验收写「开词条 / 关词条跑同一场，`rng` 调用次数与记录条数一致、只有数值不同」
（照 `60-战斗.js:200` 那条「镜甲不消耗随机数」的对照写法）。

### 6.3 ★ 变体真的改变了解法（**2 个可测量指标的例子**）

**判据**：同一层同类型下的**两条不同变体**，用**同一支队伍 + 同一方针**跑，
**至少一个指标**出现**明显不同**。指标全部从**现成的记录字段**统计，不新增埋点。

#### 例子 A：`1-N1`【重装之墙】vs `1-N2`【狙击蜂群】

| 指标 | 怎么算 | 从哪来 | 预期差 |
|---|---|---|---|
| **胜率** | 胜场 / N | `simulate().结果`（`60-战斗.js:875`） | `1-N1` 高（高护甲要破甲，但打得慢）· `1-N2` 更低（高频率狙击把前排瞬间融化） |
| **平均回合数** | `Σ 回合数 / N` | 同 `:875` | 两条要能差出 ≥ 1 回合 |
| **前排承伤占比** | 落在我方前排位的伤害 / 我方总挨打伤害 | `84-反馈.js` 的 `战报统计()`（`:280-` 的 `我方伤害 / 敌方伤害 / 总伤害`，加「按位分账」） | `1-N2` 显著**更高**（它就是考前排承伤） |
| **我方第 1 台阵亡的回合** | 第一条 `目标剩余HP === 0` 的攻击记录的 `回合` | `60-战斗.js:449`（`目标剩余HP`） | `1-N2` 明显**更早** |

**建议通过线**：**胜率差 ≥ 10 个百分点，或 平均回合数差 ≥ 1.0**。

#### 例子 B：`1-N6`【电磁干扰阵】vs `1-N7`【重甲残骸】（**顺着替代写法验**）

| 指标 | 怎么算 | 从哪来 | 预期差 |
|---|---|---|---|
| **`冷却延长` 真的发生了几次** | 记录里「延长啦」的条数 | 替代写法新增的那条记录（§2.2 #24） | `1-N6` **> 0** · `1-N7` **= 0** |
| **我方大招放出来的回合** | 第一条大招出手记录所在的 `回合` | `84-反馈.js` 的 `是记录大招()` + `60-战斗.js:449` | `1-N6` 比 `1-N7` **晚**（这就是「干扰技能轴」的直接证据） |
| **物理伤害占比 / 暴击伤害占比** | `dmgType==='物理'` 那部分伤害 ÷ 总伤害；暴击段伤害 ÷ 总伤害 | `20-战斗计算.js:449`（`暴击` 字段）+ 记录里的武器名回查 `dmgType` | `1-N7` 的**物理占比明显低**（−15% 减免）、**暴击占比明显高**（暴击抗性 0）→ 证明它真的在「引导暴击流」 |

**建议通过线**：`1-N6` 的「大招出手回合」比 `1-N7` **晚 ≥ 1 回合**，
**且** `1-N7` 的暴击伤害占比高出 ≥ 10 个百分点。

★ **两条例子都只用现成字段**（加一条替代写法自己的记录），**不需要给引擎加埋点、不需要改 `84-反馈.js`**。
