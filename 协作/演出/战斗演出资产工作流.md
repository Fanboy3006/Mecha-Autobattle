## 0. 一句话

**每个驾驶员、每台机体只画少量静态图；动作全部由演出脚本和着色器完成；每招只写一小段数据。**
这是机战A能给上百台机体配动画却几乎不画动作帧的原因，也是我们控制 token 和画量的办法。

## 1. 分工（按 2026-10-21 的协作模式）

| 谁 | 做什么 |
|---|---|
| **作者** | 人设一句话 / 草图、机设草图；挑稿；在 Aseprite 里定稿；看录像判断打击感；拍板 |
| **Claude** | 写规格（本文件、指令集、招式卡格式）；审 DeepSeek 的初稿；设计演出播放器和着色器的结构；定验收测试 |
| **DeepSeek**（`ds_code` / `ds_test`） | 看图出说明卡和像素初稿；写 GDScript 实现；把招式卡批量转成脚本；跑测试和录像 |

默认 **DeepSeek 出初稿、Claude 审**；作者点名的单位由 Claude 出初稿。

## 2. 每个单位要画什么

| 类别 | 内容 | 尺寸（初稿，待拍板） | 数量 | 谁画 |
|---|---|---|---|---|
| **人设·对话头像** | 剧情对话框、战斗台词框共用 | 32×32 | 每人 1 张起；以后加表情（怒 / 笑 / 伤） | 人设线 |
| **人设·cut-in 半身像** | 大招发动时的横带 | 约 64×60 | 每人 1 张（眼睛高光由演出点亮，不另画） | 人设线 |
| **机设·主立绘** | 待机姿势 | 我方 56–72px 高，小兵 40–50px | 每台 1 张 | 机设线 |
| **机设·姿势图** | 只在轮廓真的变了时才画：展翼、冲刺、拳头射出、拔剑 | 同主立绘画布，**脚底中心对齐** | 每台 0–2 张 | 机设线 |
| **机设·可脱离部件** | 飞拳、浮游炮、投掷武器 | 按实际大小 | 有才画 | 机设线 |
| **招式专属特效** | 例：影凤凰（振翅上 / 下） | 按需要 | 每个大招 0–1 套，2 帧 | 机设线或演出线 |
| **台词** | 喊招、收招、被击、击破 | 两行一页，每行约 14 字 | 每招 1–2 句 | 剧情 / 角色线 |

**全游戏画一次就行**：两层可横向循环的背景 × 地形（天空 / 地面 / 宇宙）、通用特效（光束、实弹、爆炸、火花、斩击、护盾，各 2–3 帧）、界面（对话框、HP 面板、招式名牌、伤害数字）、像素字体、音效。

**不用画**（写在脚本里）：震动、闪白 / 闪黑、残影、速度线、马赛克转场、冲刺 / 刹停缓动、伤害数字弹跳、cut-in 横带。

### 2.1 像素规范（人设、机设共用）
- 按 240×160 原生分辨率画，**1 像素就是 1 像素，不放大**；没有半透明抗锯齿边；1px 深色外描边。
- 每张图 ≤ 16 色（一个 GBA 调色板），主色跟势力配色。
- 头像、半身像是 GBA 日式动画风：平涂肤色 + 一档阴影，头发三档加一条高光，眼睛手点像素。
- 交付：Aseprite 源文件 + 导出的「PNG 图集 + JSON 帧信息」。Aseprite 标签命名：`idle`、`pose_<名>`、`part_<名>`、`fx_<名>`、`face_<表情>`、`cutin`。

## 3. 流程

### 3.A 人设线（新开）

| 步 | 谁 | 输入 | 输出 | 放哪 |
|---|---|---|---|---|
| A1 | 作者 | — | 一句话（例：蕾卡「蓝发女官，冷静、擅长潜入暗杀」）+ 可选草图 / 参考的感觉 | `协作/人设/草图/<角色键>-<序号>.png` |
| A2 | DeepSeek（Claude 审） | A1 + `设定/角色语料库/` 里这个人的条目 | 人设说明卡：发型发色、服装、标志物、配色 ≤12、表情清单 | `协作/人设/说明卡/<角色键>.md` |
| A3 | 同上 | A2 | 2–3 个像素变体（头像 32×32 + cut-in 半身），拼一张图 | `协作/人设/像素稿/<角色键>-v<N>.png` |
| A4 | 作者 | 变体 | 挑一个，Aseprite 定稿 | `art/pilot/<角色键>/<角色键>.aseprite` |
| A5 | DeepSeek | 定稿 | 导出图集；换进演出预览场景看一遍 | `art/pilot/<角色键>/` |

版权规矩同机设线第 4 节：不照某个具体作品角色画（同一发型 + 同一配色 + 同几处标志特征的组合）。

### 3.B 机设线（沿用 `机设协作.md`，补两条）
- 第 3 步的帧清单改成：**主立绘 + 0–2 张姿势图 + 可脱离部件**（第 2 节）。不再要求每台都画「攻击帧」，攻击姿势只在轮廓变化时才画。
- 所有姿势共用脚底中心；作者在 Aseprite 里用洋葱皮叠图自查。

### 3.C 演出线（Godot）

**C0 一次性（Claude 设计 → DeepSeek 实现）**
1. 演出播放器：读战斗记录，按脚本逐条执行指令（第 4 节），**不改战斗状态、不消耗随机数**；结算后发信号，用 `await` 等演出播完。
2. 着色器 4 个：闪色（混到白 / 黑 / 任意色）、调色板替换（阵营换色）、马赛克、渐变。
3. 预览场景 `演出预览.tscn`：选招式、选结果（命中 / 未中 / 暴击 / 击破 / 护盾 / 多目标）、¼ 速、逐帧、拖时间轴、素材框开关。
4. 录像脚本：Movie Maker 固定 60 帧导出（第 6 节）。
5. 把 HTML 原型（`演出原型.html`）的「播放器 + 模块 + 数据脚本 + 四段语法」结构移植过来。

**C1 每招（重复）**
1. 招式卡（作者或 Claude 填）：模板、台词、专属特效、节拍覆盖。
2. DeepSeek 转成脚本资源（一招约 1–2 KB）。
3. 自动测试 + 每种结果各录一段。
4. 作者看录像，一句话反馈；改数值、重录，直到通过。

## 4. 指令集 v0（默认值来自机战A实测；要和演出语法对齐后再定名）

| 指令 | 参数 | 默认 | 机战A实测出处 |
|---|---|---|---|
| `fade_in` / `fade_out` | 帧数 | 30 / 30 | 调色板从黑渐亮约 30 帧 |
| `cutin` | 驾驶员, 台词, 帧数 | 48 帧，横带滑入 9 帧 | （机战A无，GBA 后续作品有；影凤凰 demo） |
| `line` | 说话人, 台词 | 逐字 4 帧 / 字 | 对话框两行一页 |
| `pose` | 姿势键 | 瞬间切换 | 魔神Z 第 138 帧 A→B，无中间帧 |
| `effect` | 特效键, 位置, 循环 | 2 帧，每 6 帧换 | 光束每 6 帧换帧 |
| `move` | 位移, 缓动, 帧数 | 3 帧一步 | 冲刺 48px / 42 帧，4,5,4,5,4,4,3,3,2,1,1,1 |
| `projectile` | 精灵, 起点, 终点, 帧数 | 3 帧一步 | 飞拳每 3 帧约 26px |
| `afterimage` | 数量 | 3 | （demo 补充） |
| `mosaic_out` / `mosaic_in` | 帧数 | 40 / 24 | 约 50 帧放大、约 30 帧还原 |
| `switch_shot` | 攻方 / 守方 | — | 两个镜头，同屏只一台机体 |
| `shake` | 振幅, 帧数 | ±6px 斜向、3 帧换位、80 帧 + 衰减 25 帧 | 实测 |
| `flash` | 序列 | 白 → 原 → 黑 → 原，每档 6 帧，72 帧 | 实测 |
| `damage` | 目标 | 弹跳 2 步，显示约 95 帧 | 伤害数字在文字层 |
| `hp_drain` | 目标 | 约 50 帧 | HP 数字逐步递减 |
| `explode` | 大小, 位置 | 2 帧循环 | 实测 |
| `hitstop` | 毫秒 | 100 | （陨石 demo；机战A无） |
| `wait` | 帧数 | — | — |

所有位移和换帧都按 **3 帧一步**量化，这是机战A那种略带顿挫的手感的来源。

## 5. Godot 技术约定

- 视口 240×160；拉伸模式 `viewport`；缩放 `integer`；纹理过滤 Nearest；开启 2D 像素对齐；固定 60 帧。
- 图集导入：Aseprite Wizard（或同类插件），标签对应第 2.1 节的命名。
- 背景：Parallax2D 两层自动滚动，近景约为远景 2 倍速，可加斜向分量。
- 字体：OFL 授权的 12px 中文像素字体做成位图字体（候选 Fusion Pixel、Ark Pixel，待选）。
- 音效：jsfxr 等生成的芯片风 .wav。
- 表现层只读 Battle Core 的记录（与 `Godot迁移架构-v1.md` 的 Runtime / Presentation 边界一致），三档：完整 / 短版 / 简版，加跳过和快进。

## 6. 验收

### 6.1 工具
- 预览场景（第 3.C 节）。
- 录像：`godot --path . res://演出预览.tscn --write-movie 验收/<招式>_<结果>.avi --fixed-fps 60 -- 招式=<键> 结果=<结果>`，录像放进仓库 `验收/`，作者在手机上也能看。

### 6.2 引擎（一次）
| 项 | 合格标准 | 谁查 |
|---|---|---|
| 像素正确 | 240×160、整数倍放大、放大看无模糊和半像素 | 作者看截图 |
| 不抖 | 慢速平移时边缘不闪 | 作者看录像 |
| 节奏量化 | 位移每 3 帧变一次；时长与脚本一致，误差 0 帧 | 自动测试 |
| 不改结果 | 同种子战斗演出开 / 关，结果和随机数逐字一致 | 自动测试 |
| 跳过 | 任意帧跳过都干净结束，状态正确 | 自动测试 + 作者点几下 |
| 指令覆盖 | 每条指令有最小样例能播 | 自动测试出清单 |
| 性能 | 最差目标设备（含 Web 导出）稳定 60 帧 | 作者实机一次 |

### 6.3 每招
- 每种结果都能播完，无报错、无缺图（缺图显示紫色占位块）。
- 完整 / 短版 / 简版时长在演出语法规定范围内（测试打印实际时长）。
- 台词无错字，不超过两行。
- 打击感：作者回答「对 / 哪里不对」，改指令表里的数值后重录。

### 6.4 美术（人设、机设定稿时）
- 尺寸、色数、描边符合第 2.1 节；姿势间脚底对齐（洋葱皮）；1 倍大小下认得出轮廓。

验收通过：在对应协作文档的进度表打勾，`演出协作.md` 第 8 节记一行。
