## 一、语-15「一次出手」怎么认

**语法原文要点**：从一条 `攻击` 往后收，同 `单位方 + 单位位 + 武器` 的连续 `攻击` 算一次出手；夹着的 `嘲讽 / 方针` 归进来，`残月余响` 不归；遇到别的单位、`连斩 / 回合 / 结束` 就停。不加字段。

**Godot 现状**
- 范围攻击：`core/battle/flow.gd` `Flow.resolveAction` 末尾 `for t in targets:` 对每个目标调一次 `Flow.结算一个目标`，后者写**一条** `类型:"攻击"` 记录（`Btl.pushLog(ctx, rec.文本, 攻击字段)`）。所以「打 3 个目标 = 3 条记录」成立。真实样例（`default/10-1-Boss` 第 4 回合，B2 的 `★ 影凤凰`）：
  ```
  {类型:攻击, 单位:B2, 单位方:ally, 单位位:1, 武器:"★ 影凤凰", 目标:fighter,  命中:true, 伤害:5692,  暴击:0, 目标剩余HP:0}
  {类型:击破, 单位:B2, 单位方:ally, 单位位:1, 目标:fighter}
  {类型:攻击, 单位:B2, …, 武器:"★ 影凤凰", 目标:swarm#2, 伤害:6696,  目标剩余HP:0}
  {类型:击破, …, 目标:swarm#2}
  {类型:攻击, 单位:B2, …, 武器:"★ 影凤凰", 目标:hound,   伤害:13392, 暴击:1, 目标剩余HP:0}
  {类型:击破, …, 目标:hound}
  {类型:上张打出牌, 单位:B2}   {类型:大招槽, 单位:B2, 单位位:1}
  ```
- 统计（180 场，`攻击` 记录 12179 条）：按原语-15 分组，单条组 10276、2 条 530、3 条 147、4 条以上 81；**组内出现目标重复 39 次**（说明有把两次出手并成一组的情况）。

**发现的 4 个缺口**
1. **`嘲讽` 在攻击记录之前**，不在中间：`Flow.结算一个目标` 先写 `嘲讽` 再写 `攻击`（实测 223 次）。从 `攻击` 开组会漏掉它。样例：`{类型:嘲讽, 单位方:ally, 单位位:2, 保护者:CB4, 原目标:B2, 目标:CB4}` → `{类型:攻击, 单位:artillery, 武器:榴弹炮, 目标:CB4, 伤害:1082}`。另：`嘲讽` 记录的 `单位方/位` 是**保护者**，不能按「别的单位就停」处理。
2. **卡牌战斗没有出手边界**：连打两张同一把武器的牌，中间只有出牌记账记录（`上张打出牌 / 武器栏 / 专属精神牌 / 大招槽`…，组内出现 248 次）。`DeckFlow.记上张打出牌` 在**每张牌结算完**写一条 `上张打出牌`，是可靠的边界。
3. **`固定伤害` 记录没有署名**：`core/battle/card_effects.gd` 写的 `{类型:攻击, 单位:"", 武器:"固定伤害", 固定伤害:true}` 没有 `单位方 / 单位位`（509 条），连续几条会被并成一组（39 次重复里大部分是它）。
4. **组内还会夹**：`击破`（每次击破一条，`PhaseFlow` 写）、`标定 / 破绽 / 势力 / 押注王牌 / 九死一生` 等势力记账、`镜甲`（受方的反弹，是另一次动作）、`残月余响`（两处写：`Flow.runAutoCast` 与 `FacMoon` 追加）。

**补上边界后**（`上张打出牌` 也停、`固定伤害` 单独成组）：目标重复从 39 降到 8。剩下 8 次是两种合法情况：一张牌内同一武器打了两轮（中间夹 `嘲讽` = 新的单体出手，因为范围攻击不走嘲讽）；殖民的 `达纳号·巡航导弹` 本来就是一发一发选目标，会重复打同一台。

**结论：部分成立**。改法（演出层，不动记录）：
- 开组时**往前看一条**：紧挨着的 `嘲讽` 归进本组。
- 停：别的单位的 `攻击`、`上张打出牌`、`连斩`、`回合`、`结束`、`自爆`、组内**第二条** `嘲讽`（它开始的是新的单体出手）。
- 归进来但不演的：`击破`（`目标剩余HP` 已经说明了）、各势力记账记录。
- 拆出去排在后面演：`镜甲`、`残月余响`。
- `固定伤害` 一律单独成组、简版。**要补署名就要动内核**（`card_effects.gd` 那条记录加 `单位方/单位位`），会改 509 条样例事件，**不建议现在做**。
- 不加「出手编号」字段：加了会改动几乎所有攻击记录的样例。真要加，可以把键名放进 `tests/native_golden_runner.gd` 的 `DISPLAY_ONLY`（这样样例零差异），但那样就没有回归保护了。

## 二、语-20 播放钩子

**语法原文要点**：`演出.要演(战报, 位置, 播放)` 返回 `{脚本, 档, 条数, 输入}`；播放层暂停 → 等演出 → 再把 N 条记录**逐条应用**；`HP前 / 最大HP` 从「播放中、记录还没应用」的单位状态读。

**Godot 现状**
- 时序是**先结算、后回放**：`presentation/battle/log_panel.gd`（结束回合）和 `hand_panel.gd` `_演本拍新增`（每打一张牌）都是：先调 `session.end_player_turn()` / 出牌接口**同步结算完**，切出新增日志 → `BattleFxPlayer._构建演出队列(新增, 前手, 后手)` → `refresh()`（棋盘直接显示终态 HP）→ `BattleView._消费演出队列()`。
- 演出帧：`battle_fx_player.gd` `构建单拍演出帧` 按 `类型` 一条记录拆一帧（`攻击 / 镜甲` → `_攻击帧`，**一条攻击记录一帧**，所以范围攻击打 3 台 = 3 帧）。
- 播放协程：`battle_view.gd` `_消费演出队列` 逐帧 `await _播一帧(帧)`；`_播一帧` 按 `类别`（`card_deal / attack / heal / card_fx`）分派；跳过走 `_演出跳过请求` + `_应用帧终态`；倍速 `_演出倍速`。headless / 无声模式只走 `_应用帧终态`。
- 「是不是大招」：`board_panel.gd` `_是大招` = 在单位的 `weapons` 里按武器名找，再 `Ai.isUltimate`。**卡牌战斗里基本认不出**：大招牌打出的攻击记录 770 条，它只认出 41 条（大招牌的武器在 `卡.武器` 里，不在 `u.weapons`）。

**结论：部分成立**。钩子该放的位置很清楚，但 JS 那套「记录还没应用、从播放状态读 HP前」在 Godot 不成立。改写成：
- **钩子位置**：`BattleFxPlayer.构建单拍演出帧` 里，遇到 `攻击` 时调「认出手 + 分级」（第五节），档 ≥ 短版就把这一组合成**一帧** `类别:"cutscene"`（带 `条数`、`档`、`记录下标们`），否则照旧一条一帧。`BattleView._播一帧` 多一个分支 `"cutscene": await _播横版(帧)`。Godot 里不用 Promise / 信号，沿用现在的 `await` 协程。
- **`HP前`**：在调 session 之前给全体单位拍一个 HP 快照（照 `_手牌快照()` 的做法），构建队列时按记录顺序用 `目标剩余HP` 往前推。`最大HP` 读单位当前的 `maxHp`。**不加记录字段**。
- 跳过 / 「关」档 / 4× 起：不生成 cutscene 帧，播放层逻辑不变（和语-20 原意一致）。
- 武器静态信息仍可以读：我方查 `u.weapons` + 大招槽的 `卡.武器`，敌方查 `u.weapons`。

## 三、语-21 记录缺 `护盾吸收 / 无效化`

**语法原文要点**：照 `防御少挨` 的写法，只在真发生时带上 `护盾吸收: N`、`无效化: '屏障' | 'λ力场'`；数字在伤害管线里都有，只是没往外带。

**Godot 现状**
- 减免在 `core/battle/calc.gd` `Calc.dmgCore` 末尾：`# 1 能量屏障`（≤2500 → `c.dmg = 0`、`c.nullified = true`）、`# 3 λ 力场`（减 `λ减免量 × defMul`，**是减法，不一定归零**）、`# 4 护盾`（`a2 = min(dmg, shieldHp)`，扣 `shieldHp`）。只有 `nullified` 留在 `c` 里，λ 减了多少、护盾吸了多少都没留。
- `Calc._单体结算` 写 `字段` 时有 `防御少挨 / 掩护吸收 / 掩护减伤`（都是「>0 才写」），**没有**护盾和力场。
- 真实样例（`character/U_M1`，打带护盾的 M2）：`{类型:攻击, 单位:raider, 武器:突刺, 目标:M2, 命中:true, 伤害:0, 段数:1, 目标剩余HP:19750}`——演出只能看到「命中了、0 伤害」。λ：`default/19-2-N7` `{单位:CB2, 武器:援护射击, 目标:venom, 命中:true, 伤害:0}`，详情只有「第 1 段（100%）0」。全部样例里「命中但伤害 0」的攻击记录 192 条。

**结论：成立**。

**最小改法**（只写记录、不改数值、不碰随机数；改 1 个文件 `calc.gd`，约 15 行）：
1. `dmgCore`：护盾段加 `c["护盾吸收"] = a2`；λ 段记 `c["λ减免"] = 减前 - 减后`，减到 0 再记 `c["λ归零"] = true`。屏障已有 `c.nullified`。
2. `_单体结算`：在**真结算那一次** `var c := dmgCore(att, w, def, 段参)` 后面逐段累加（预览用的那几次 `dmgCore` 不算）；写字段处照 `掩护吸收` 的样子：`护盾吸收 > 0` 才写；`无效化` = `"屏障"`（`nullified`）或 `"λ力场"`（λ 归零）；建议顺手加 `λ减免 > 0` 才写（λ 只减一部分时演出要显示「力场 −N」，否则看不出来）。
3. `_散布结算` 现在只把**主目标**那组字段当底，要在合并循环里把这几个数也加总（2～3 行）。
- `残月余响`、ATX 牌、自爆这些自己写记录的地方都是 `merged(…, rec.字段)`，会自动带上，不用另改。
- 注意口径：`护盾吸收` 是**护盾值实际少了多少**（在伤害倍率之前），和 `伤害` 不是同一把尺子；演出显示「盾 −N」没问题，但不要拿它和伤害相加。

**对原生样例的影响**（实测：在草稿目录里改了一份 `calc.gd`，重录 180 场后逐条比对）：
- 变化 **59 / 180 场、357 / 70112 条事件**；新增键次数：`护盾吸收` 276、`λ减免` 81、`无效化` 56（全是 `λ力场`）。**除新增键外没有任何差异**：事件数、`_rng` 步数、其它字段全同。按组：default 120 条、relic 87、月球王国 83、影世界 33、秘银 13、character 10，其余个位数，quick 0。
- 只加语-21 那两个键（不加 `λ减免`）大约少 25 条。
- **屏障在原生样例里一次都没触发**（样例里没有带 `barrier` 的敌人上场），要补一条单元测试专门覆盖 `无效化:"屏障"`。
- 需要作者同意（改内核记录字段 = 改样例）；按 CLAUDE.md 第 5 节只重录一次并附差异摘要，差异应该只出现在上面这些场次。

## 四、语-13 演出自用随机

**语法原文要点**：碎屑 / 火花用演出自己的伪随机，种子 = 战报种子 ^ 记录序号；绝不调用 `ctx.rng`。

**Godot 现状**
- `ctx.rng` 是 `Mulberry32`（`core/battle/setup.gd` `Setup.开局`：`"种子"`、`"rng"`、`"_rng_at"`），`steps` 记录抽了几次，`_rng_at` 与 `log` 一一对应（`BattleLog.pushLog`）。
- `presentation/` 和 `session/` 里搜不到 `randf / randi / RandomNumberGenerator`，也没有读 `battle_ctx.rng` 的地方（`Mulberry32` 只出现在 `boot.gd` 的自检和 session 里另起种子的节点编成 / 发券）。
- 实测（快速测试战 · 秘银 · 种子 20261022，推 4 拍，每拍把演出队列整个播完）：每拍播放前后 `rng.steps` 都相同（17/17、31/31、43/43、55/55）。
- 门禁：`tests/unit/test_boundary.gd` 的「不用引擎随机数」只扫 `core/`，所以演出层**可以**用 `RandomNumberGenerator`，但现在也**没有**任何规则拦它去碰 `ctx.rng`。

**结论：成立**。要注意的是：因为先结算后回放，演出如果偷用了 `ctx.rng`，改变的是**下一拍**的结果，而且很难查出来。改法（演出层 + 测试，不动内核）：
- 演出用 `RandomNumberGenerator`，种子 = `int(ctx.种子) ^ 记录下标`（也可以用 `ctx._rng_at[下标]`，同样确定）。
- 加门禁 ①：`test_boundary` 增一条，`presentation/` 里禁止出现 `.rng` / `"rng"`。
- 加门禁 ②：一个单元测试照上面实测的做法，播完队列后断言 `rng.steps` 不变（阶段 3 的那条测试可以直接用它）。

## 五、分级判据函数草案（已定规则 12）

**放哪**：新文件 `godot/core/battle/fx_grade.gd`（`class_name FxGrade`，纯读：不改 ctx、不掷随机数、不点名势力模块）。新增 `.gd` 后要补跑 import + 重建 RouteMap。session 加一层薄转发（如 `GameSession.battle_fx_grade(下标)`），演出经 session 调用。

```gdscript
## 从 log[起] 认一次出手（第一节的规则）。返回 {起, 止(不含), 攻击下标们: Array, 单位方, 单位位, 单位, 武器, 拆后演: Array}
static func 认出手(日志: Array, 起: int) -> Dictionary
## 给 log[下标] 开头的这次出手定档。返回 {档: "完整"|"短版"|"简版", 原因: String, 条数: int, 招键: String, 主目标下标: int}
static func 演出分级(ctx: Dictionary, 下标: int) -> Dictionary
```

**判据草案**（按顺序，命中即返回）：
1. `log[下标]` 不是 `攻击`（修理、增益、出牌记账…）→ **简版**。
2. `组 = 认出手(ctx.log, 下标)`；`招键 = 单位方/单位/武器`。
3. 是不是「大招类」，任一成立即是：
   - **大招牌**：从组尾往后，到同单位的第一条 `上张打出牌`，紧接着的是同单位的 `大招槽` → 是（现在记录里没有「来自哪张牌」，靠这个往后看；实测大招牌攻击 770 条都是这个顺序）。
   - **Boss 大技能**：组首往前紧挨着的是 `{类型:Boss, Boss事件:"大技能"}`，且同单位、`武器` 相同（`boss.gd` 写的，样例里 70 次）。
   - **头目大招**：敌方，且在单位 `weapons` 里查到的武器 `Ai.isUltimate` 为真（语-3）。
4. 大招类：`ctx.log[0 .. 组首)` 里没有同 `招键` 的大招类出手 → **完整**（原因「大招牌 / Boss大技能 / 头目大招」）；有 → **短版**（原因「重复」）。
5. 不是大招类，但组内有一条 `伤害 > 0 且 目标剩余HP == 0`，或带 `散布击破` → **短版**（原因「击破」）。
6. 其余 → **简版**。
- `主目标下标`：本次击破了的 > 伤害最高的 > 第一条（语-16）。
- 设置档（语-2）和倍速（规则 8：4× 起全简版）由演出层在拿到结果后再套，不进内核函数。
- **需要作者确认的一处**：规则 12 写「完整 = …、本场首次出现的招」。字面读是「任何招第一次出现都完整」，那每个小兵第一枪都要切横版，和规则 3、语-3、语-4 冲突。草案按「首次 / 第二次起只用在大招类上」处理；另外击破是否也包括**敌方击破我方**（语-14 说同一套），草案暂按包括。
