## 3. 已定规则（作者 2026-10-12 拍板）

1. **画风**：Q 版像素，接近机战 A（GBA）。画面按 **240×160** 原生分辨率绘制、**整数倍放大、不做平滑**。机体 **SD 比例**（约 2–2.5 头身）。文字用像素字体（或二值化渲染）。
2. **只读结果，不决定结果**：演出读战斗记录（命中 / 伤害 / 暴击 / 击破 / 护盾……），**一律不改战斗状态、不消耗随机数**。同种子结果不变（`CLAUDE.md` 第 7 节、方案 8.1）。
3. **分级**（工作量和节奏都看这一条）：
   - 普通攻击：**1 秒以内**的简版，不进横版画面（在现有战场上演）；
   - **大招、击破、Boss 大技能**：完整横版演出；
   - 全程有「跳过演出 / 加速」开关。
4. **模块化，不逐招手写**：通用模块（发射、弹道、近战、命中反应、爆炸、切入、镜头）+ 每招一份**数据脚本**。目标规模约 300 招。
5. **资产格式两边通用**：精灵与特效用 **Aseprite 图集（PNG + JSON 帧信息）**；演出节奏写成**数据**（时间表）。以后如果迁到 Godot，这两样原样复用（作者 2026-10-12 讨论过：规则稳定之前不迁引擎）。
6. **演出节奏以 demo 为起点**：demo 里各拍时长是初稿，作者在 demo 页上调过的数字以作者说的为准。

## 4. 接入口（DSH 实现时照这个接，细节在演出语法里定）

### 4.1 播放钩子（`85-播放.js` 只加这一处）

- 播放到一条记录时，问演出层「这条要不要演完整演出」：
  `演出.要演(记录, 上下文) → 脚本 ID | null`（按第 3 节第 3 条分级判断）。
- 要演就**暂停播放**，调用 `演出.播放(脚本ID, 输入) → Promise`，结束后继续。跳过开关打开时直接返回已完成。
- 美术线以前的任务板里记过「战斗演出需要统筹在出手时留一个『等动画播完』的接口」，就是这一个。

### 4.2 演出的输入（从战斗记录里取，**不另算**）

```js
{
  攻击者: { 键, 方, 位, 名, 精灵组 },
  目标们: [{ 键, 方, 位, 名, 精灵组, HP前, HP后, 最大HP, 结果 }],   // 结果: 命中 | 未中 | 暴击 | 护盾吸收 | λ力场 | 防御中 | 嘲讽替挨 | 击破
  武器: { 名, 档次, 伤害类型, 威力 },
  伤害: [每个目标的数字],
  主目标: 0,                     // 多目标时镜头给谁（演出语法第 5 条定）
}
```

缺字段就在 `60-战斗.js` 的记录里补字段，**不在演出层重新计算**。

### 4.3 每招的脚本（数据，示意；正式格式由演出语法定）

```js
演出脚本.M1_zangetsu = {
  模板: 'summon_drop', 档次: '大招',
  台词: ['质量加速器，充能完毕——', '月光，坠落吧！'],
  弹体: 'meteor', 命中: 'hit_large', 镜头: '横移',
  节拍覆盖: { 坠落: 600 },           // 不写就用模板默认
};
```

## 6. 待定（等作者拍板，不定的不做）

1. 多目标（打整排 / 整列）怎么演：镜头给主目标、其余只跳数字和闪白？还是分屏？
2. 敌人的招式要不要演完整演出（建议：只有 Boss 和头目的大技能演）。
3. 普通攻击简版要不要也切到横版画面（建议不切，在战场上演）。
4. 每台机体最少要画几帧（建议：待机 / 攻击姿势 / 受击 + 可选头像）。
5. 精灵尺寸档的具体像素（demo 里 Feena 约 43px、小兵约 28px，作者觉得偏小的话：我方 56–72px、小兵 40–50px）。

## 7. 省用量（作者在意 token）

- **每批工作开新会话**，不要在长对话里迭代（每次调用都会重读整段上下文）。演出会话做完一件就在本文件第 8 节记一行，再开新会话接着做。
- 规则和模块由 Claude 做；**机械活（卡 → 脚本、登记、批量改名）交 DeepSeek**。
- 看效果用截图（Playwright 渲染几帧拼一张图看），不要反复整页发布。
- 估算（2026-10-12）：引擎 20–40 万 + 模块库 30–60 万 + 300 招脚本 100–250 万 + 返工，合计约 250–550 万 token；逐招手写会是它的 5–10 倍。
