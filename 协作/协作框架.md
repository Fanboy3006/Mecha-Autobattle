## 3. 一条线的标准流程（开工 → 交付）

1. **开工前**：读 `CLAUDE.md` + 本文档 + 自己的交接文档；看 `协作\分工看板.md` 第 1 节，确认**生成物闸门**（第 4 节）没被别人占着。
2. **做的过程中**：只写自己那列的文件；**新数值不许自己发明**（战棋有的逐字照抄并标 `文件名:行号`；查不到的写「初稿」）。
3. **收工前**（缺一不可）：
   - `node tools/build-src.mjs`（重建生成物）；
   - `node tools/build-src.mjs --check` → 必须「检查通过」；
   - **十六套测试**（smoke / sim / battle_ui / commands / run / comp / map / **art_icons** / **audio** / boss / heal / relic / rank / balance / grid / faction）全过；
   - 改了自己的线档（`协作\任务板.md` **追加**一段 + `协作\协作日志.md` **追加**一条 + 看板自己那一行）；
   - `git add` **只加自己那条线的文件** → 提交（`[标签]` + 中文）；
   - 在 `协作\分工看板.md` 第 2 节把自己的**状态**改成「已交付（commit 短哈希）」。
4. **交付报告**（给统筹 / 作者）：**怎么试 + 真实测试输出**（哪几套、最后一行是什么、关键数字）。
   红了的套数要说清「是不是别人的线引起的」以及证据。
5. **统筹验收**：在**干净检出**（或临时 `git worktree`）上跑 `--check` + 十六套，翻一遍改了哪些文件，确认没夹带别人的文件，
   然后才向作者报告。

## 4. 生成物闸门（串行规则，防互相覆盖）

`index.html` 和 `src\artifact-fragment.html` 是**所有线共用**的生成物，谁重建都会覆盖一次。

- **同一时刻只允许一条线在动生成物**。开工前先看 `分工看板.md` 第 1 节的**闸门**字段：
  - 空着 → 把自己的线名填进去，开工；
  - 写着别人 → **等**（或先做不碰生成物的部分）。
- 收工提交后，把闸门字段清空。
- 如果提交时发现**生成物里混进了别人未提交的素材**（例如 `art/`、`audio/` 有人正在改），
  用**临时 `git worktree`** 按已提交的素材构建，再拷回来（2026-10-11 前三条势力线就是这么做的），并在报告里注明。
- 提交后若发现 `--check` 红、且原因**不是自己**的改动 → 不要覆盖别人的工作，写进看板第 3 节，交给统筹。

## 6. 沟通协议（会话之间怎么说话）

- **不直接改别人的文件**。需要别人动什么 → 写进 `协作\分工看板.md` **第 3 节「需求 / 请求」**：
  一行格式 = `[从谁 → 给谁] 一句话需求（为什么）+ 期望的验收`。统筹负责转达与排序。
- **不覆盖别人的未提交工作**。发现别人的改动挡着自己 → 停下 + 看板写一行 + 报告，**不要** `git checkout`/`reset`/强推。
- **接口变了要登记**：改了 `window.__game` 暴露的东西、素材注入标记（`ART` / `AUDIO`）、
  记录格式（`〔势力〕` 这类）、存档结构 → 必须写进 `CLAUDE.md` 对应章节 + 看板第 3 节通知别的线。
  （`协作\接口约定.md` 还没建；第一次真需要时按旧仓库 `F:\DSH-mecha\mecha-tactics\协作\接口约定.md` 的格式建。）
- **对作者的报告**：一条线一次交付 = 「**怎么试 + 真实数字 + 待拍板的问题**」，中文、简短，别写「看起来没问题」。
- **统筹对作者的报告**：先说「验收结果（几套绿、生成物是否同步）」，再说「怎么试」，最后是「要你拍板的」。

### 9.1 事故
主线的一个子助手为了定位 `art_audio` 红灯，除了建临时 worktree（只读）之外，**还多做两步破坏性操作**：
`Copy-Item` 把 HEAD 版覆盖回主工作树、紧接着 `git checkout -- audio/local-music.js src/js/96-音乐.js tests/art_audio.js`
→ **音乐线未提交的三个文件被覆盖成 HEAD 版**（git 对象库里没有它们的 blob，主工作树的生成物也已重建 → 无法从 git 恢复）。
**幸存的恢复依据**：音乐线自己写的 `协作\交接-音乐.md` **第 9 节**完整记录了那批改动（T3 Boss/胜利曲、T4 敌我阶段切曲、
`音乐.切阶段()` / `阶段曲()` / `场景曲()` 第三参数 / `阶段方` 字段），且它自己的会话上下文里有原文 → **由音乐线重落一遍即可恢复**。

### 9.2 新增红线（第 7 节之后同样有效，违反就算失败）
1. **绝不覆盖别人正在改的文件**：任何形式的 `git checkout -- <别人的文件>`、`git restore`、`git reset --hard`、
   `git stash`、`Copy-Item` 覆盖、整文件重写都**禁止**。看到别人的未提交改动 → **只读**（`git diff` / `git show HEAD:文件` / `git worktree`）。
2. **未提交的工作不许只躺在工作区**：任何一条线手上改动超过约 10 分钟，就先做一个 **`[WIP]` 提交**
   （说明写「`[WIP] 未完成，勿依赖`」，**不必跑测试、不必重建生成物**）。工作区不是保险箱，`[WIP]` 提交才是。
3. **定位「红灯是谁引起的」只用只读手段**：`git status` / `git diff --stat` / `git show --stat` / 临时 `git worktree add`（只读用）
   / 比对两份生成物的区块哈希。**结论写进报告，不许为了让测试变绿去动别人的文件。**
4. **生成物冲突时**：按第 4 节用「临时 worktree 按已提交素材构建 → 只拷回生成物」，**绝不覆盖任何源文件**；
   拷回前先确认工作区里没有别人未提交的源文件改动（`git status` 里别人的 `M` 必须先问统筹）。
