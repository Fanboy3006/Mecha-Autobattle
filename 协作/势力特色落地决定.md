## 追加（作者 2026-10-11 拍板）· 秘银 = 「交叉训练」

> 方案出处：Claude 2026-10-11（团队羁绊第二批的思路一）。λ 觉醒仍按上面第 5 条算**宗介个人**，不并入。

### 结论（Claude，2026-10-11）

- **决定**：秘银单位除自己的职业特色外，**再拿到相邻位上其他秘银单位的职业特色**（「相邻」= `05-阵型.js` 的 `相邻位(位)`：同排左右 + 有阻挡关系的对位）。
  - 原作依据：SRT 人人交叉训练，「谁倒下任务都还能完成」；秘银五人正好是五个不同职业（宗介 特种 / 克鲁兹 狙击 / 毛 指挥 / 克鲁佐 近卫 / 杨 尖兵，缺重装）。
  - **开局按站位算一次**；**换位后重算**；**战友阵亡后，他借出去的特色这场战斗内保留**（不收回）。新站到相邻位的人照常获得。
  - 同名特色不叠加（借来的和自己的是同一条就只算一份；指挥命中 +10 本来就按同源只留一份）。
  - **借来的「近卫连斩」全队每回合最多触发 1 次**（克鲁佐自己的连斩不受影响，仍是他自己每回合 1 次）。
  - 只对我方秘银生效；非秘银的相邻队友**不借出也不借入**。
- **落点文件**：`src/js/30-射程.js` 的 `职业是()`（让它多查一张「借来的职业」）；开局 / 换位 / 阵亡处更新这张表（`60-战斗.js`）；连斩上限在 `60-战斗.js` 近卫再动那一段；常量写在 `src/js/71-改动.js`。
- **需要新增的字段名**（`71-改动.js`）：
  - `秘银羁绊 = { 启用: true, 范围: '相邻', 借来连斩全队每回合上限: 1, 每台最多借几门: 0 /* 0 = 不限 */, 阵亡保留: true }`
  - 单位运行期：`u.借来职业`（Set，内容是职业名，如 `'近卫'`）；战场运行期：`ctx.秘银借连斩Turn`（记本回合是否已用掉全队那 1 次）。
  - 战斗记录：开局一条 `〔交叉训练〕克鲁佐 ← 特种（宗介）、狙击（克鲁兹）`；借来的连斩触发时写 `〔连斩·交叉训练〕…`。界面卡片上给借来的职业加小标记。
  - **降档旋钮**：嫌强先把 `每台最多借几门` 改成 1（优先级：近卫 > 指挥 > 狙击 > 尖兵 > 特种，按下面实测收益排）；再不够就把 `范围` 改成 `'同排'`。
- **验收方式**（`tests/` 新增一段，种子 1…10）：
  1. **规则**：秘银五人摆 前1 克鲁佐 / 前2 宗介 / 前3 杨 / 后1 克鲁兹 / 后3 毛 → 开局 `u.借来职业`：克鲁佐 = {特种, 狙击}；宗介 = {近卫, 尖兵, 指挥}；杨 = {特种, 指挥}；克鲁兹 = {近卫}；毛 = {特种, 尖兵}。宗介和克鲁佐换位后重算；宗介阵亡后克鲁佐仍有「特种」。非秘银站在相邻位时不出现在任何一方的表里。
  2. **连斩上限**：同一回合两台借了近卫的秘银各击破一次 → 只有一台再动；克鲁佐自己击破仍能再动。
  3. **强度**：上面那支五人 Lv10 打第 3 层 精英 / 侵蚀源 / 守军 编成（9 条 × 10 种子 = 90 场）。Claude 模拟实测：没有羁绊 94% / 3.75 回合 / 场均阵亡 1.17 → 交叉训练（带连斩上限）**99% / 2.62 回合 / 0.64**。通过线：平均回合比无羁绊**少 20%–35%**；把站位改成分散（前1 克鲁佐 / 前3 杨 / 前4 宗介 / 后1 克鲁兹 / 后5 毛），收益要**明显小于**紧凑站位（实测无上限时紧凑 −35%、分散 −13%）。

**依据（Claude 模拟实测，Lv10 秘银五人 vs 第 3 层非普通编成，90 场）**：

| 版本 | 胜率 | 平均回合 | 场均阵亡 |
|---|---|---|---|
| 无羁绊 | 94% | 3.75 | 1.17 |
| 只共享近卫 | 99% | 2.89 | 0.78 |
| 只共享指挥 | 98% | 3.36 | 0.92 |
| 只共享狙击 | 98% | 3.44 | 0.96 |
| 只共享尖兵 | 99% | 3.71 | 0.98 |
| 只共享特种 | 96% | 3.73 | 1.07 |
| 相邻共享 · 紧凑 · 连斩不限 | 99% | 2.43 | 0.59 |
| **相邻共享 · 紧凑 · 借来连斩全队 1 次（采用）** | **99%** | **2.62** | **0.64** |
| 相邻共享 · 分散 · 连斩不限 | 98% | 3.27 | 0.91 |
| 全队共享（不看站位） | 100% | 2.12 | 0.34 |

- 选「相邻」而不是「全队」：全队共享 −43% 太强，而且没有站位决策；相邻版让「谁挨着谁」变成编队时的选择（紧凑 vs 分散差约 3 倍收益）。
- 连斩上限 1：近卫连斩是单项收益最大的一条（单独就 −23% 回合），全员都能连斩时容易滚雪球；加上限后只少了约 5 个百分点的收益，但堵住了 6 台秘银时的连锁再动。
- 难度按作者的方向之后往上调；这里的「少 20%–35% 回合」是相对无羁绊的口径，调难度时不用跟着改。

### 结论（作者，2026-10-11）· 希望 / 出击上限（部署位）类藏品三条拍板

> 作者原话三条：① 「**可以允许上到 7-9 台**」；② 「**可以抬到 9，但是正常成长只到 6**」；
> ③ 「**可以，可以带一个负面换正面**」。背景调研在 `协作/集成战略藏品调研.md`（A 类 41 件 / B 类 14 件），
> 交付明细与真实输出在 `协作/任务板.md` 最后一段。

**决定 1：出击上限改成「两级封顶」—— 等级那条线封顶 6，含藏品的绝对封顶 9**
- **决定**：`出击上限 = min(绝对顶 9, min(等级成长顶 6, 3 + floor((肉鸽等级 − 1) / 3)) + 藏品加成)`。
  **正常成长（等级那条线）只到 6 台**；**7–9 台只能靠藏品**；整条链路的**绝对封顶 = 9**（= 前排 4 + 后排 5 全满）。
  下限沿用上一版的**起始 3 台**（负数藏品最多把上限压回 3 台）。练习模式（没有 RUN / 没有藏品加成）那条旧口径保留，封顶仍是 6。
- **落点文件**：`src/js/05-阵型.js`（常量 + `出击上限()` + 新 `藏品部署位加成()` + `出击上限提示()`）、
  `src/js/90-肉鸽.js`（`肉鸽数值` 的常量名 + `肉鸽.出击上限()` 带上藏品加成）、

  `src/js/99-boot.js`（`window.__game` 暴露）、`tests/grid.js` 第 [6] 段、`tests/smoke.js`、`tests/rank.js` 第 [7] 段。
- **需要改 / 新增的字段名**（数值全是「初稿·待作者调」）：
  `出击上限初值 = 3`、**`等级成长顶 = 6`**、**`绝对顶 = 9`**、`每几级加一台 = 3`、`肉鸽等级基准 = 1`
  （旧的 `出击上限顶` 拆成 `等级成长顶` / `绝对顶` 两个名字，全仓库不再用旧名）；
  `出击上限(肉鸽等级, 藏品加成 = 0)`；`藏品部署位加成(RUN)`（把 `RUN.藏品` 里 `数值.出击上限` 求和）；
  `出击上限提示(等级, 藏品加成) → {上限, 到顶, 解锁等级, 还差, 等级上限, 等级到顶, 等级成长顶, 绝对顶, 藏品加成}`
  （`到顶` = 顶到 **9**；`等级到顶` = 等级那条线到 **6**）。
- **验收方式**：`node tests/grid.js` 第 [6] 段 —— 等级 1/4/7/10 → 3/4/5/6；**等级 10 → 6，藏品 +1 → 7、+2 → 8、+3 → 9、+5 还是 9**；
