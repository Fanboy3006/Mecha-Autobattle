# 架构债务账本（Architecture Debt Ledger）

> **用途**：把「现在只能这样、但欠着」的架构妥协登记成条目，好让门禁（`tests/arch.js` 第 [6] 段）与
> `协作/架构快照.json` 的 `knownDebtIds` **对齐** —— 债务可以留，但**不许偷偷留**（账上必须有）。
> **格式（四列，缺一列不算登记）**：`ID | 位置 | 为什么存在 | 触发清理条件`。
> 清债规矩：**先让门禁红（或先写一条能红的检查）、再动代码**；当场清不掉的，就把「触发清理条件」写得更具体。

| ID | 位置 | 为什么存在 | 触发清理条件 |
|---|---|---|---|
| `DEBT-01` | `src/js/84-反馈.js` 的「战后休整回血行」（它读的是 `肉鸽界面.战后休整行`） | 那一句是 `90-肉鸽-6-存档与收尾.js` 的 `记战后回血行()` 写进界面的，**没有走 `ctx.log`**：为了不给「没有 `RUN` 的战斗」（练习模式 / `simulate()` / 平衡工具 / 调参室）多出任何一条记录，先跨层架了一座**只读**的桥 | 把「战后回血」改成一条**有 `RUN` 才写**的正式记录（`ctx.log` 里带类型 + 回血字段），并保证无 `RUN` 三快照（`tests/录像.js` 第 [8] 段）逐字节不变 |
| `DEBT-02` | `src/js/8b-决策日志.js` 的 `屏决策族['战斗']` 与 `战术码们()` | `ctx.气势 < 100` 时**枚举结果里不出现** `战术:总攻` / `战术:掩护`（族名在表里、产码为空）：为兼容既有的战斗屏枚举项集合与决策体量口径（`tests/决策.js` 第 [4] 段 ≤ 20 KB、`tests/录像.js` 第 [6] 段逐行「选择 ∈ 可选项」），先让这一族只在气势满 100 时才产码 | 定下「战术不可用也记进选项（带未满标注）」的口径后，让 `战术码们()` 恒产出两条并把状态写进选项短码，同时同步更新上面两处既有断言 |
| `DEBT-03` | 旧版录像（如 v0.6.6 的 `785164.json`）与 `src/js/89-录像-*.js` | 旧录像**只存操作流与旧版 `对账` 字符串**，没有内嵌当时的 `战斗结构` 参数快照 —— 跨规则版本重放时数值结果会随新版规则漂移（**Seed 只决定随机序列**）；现在只能靠 `规则签名` + `tools/replay.mjs` 的 `[跨规则版本重放]` 诊断**事后识别并告警** | 录像开始把**当时的规则参数快照**（或它的 `规则签名` + 参数差异清单）内嵌进录像（升 `录像格式版本`），`tools/replay.mjs` 能按嵌入的那份参数重放、或精确指出是哪几个参数漂了 |
| `DEBT-04` | `src/js/NN-*.js` 的 **56 个片段**（共享顶层全局作用域，同一个 `<script>`） | 没有命名空间对象，全靠**命名约定**（`录像.` / `选项.` / `肉鸽.` / `界面.`）与 `tests/arch.js` 的状态 Owner 扫描防越权；换来的是「拼接产物 = 一个大文件」这个单文件前提仍然成立、每笔改动成本最低 | 片段数或并行线数量再涨一档（或再出一次「两条线改同一个全局名」的事故）时，把每片包进 `const 模块 = { … }` 命名空间，`window.__game` 只做装配 |
| `DEBT-05` | `src/js/89-录像-1-存储与运行期.js` 的 `录像格式版本`（**仍是 `1`**）与 `src/js/89-录像-3-会话与导出.js` 新写的 `规则签名` 字段 | 录像 Schema 事实上多了 `规则签名`（架构 2.0 · Replay Versioning 的判据），**但没有递增 `录像.格式版本`**：`tests/上报.js` 第 [6] 段把「最小样例的 `格式版本 = 1`」锁成了常量（上报接收端也按这个常数对齐），当场升到 `2` 会把既有断言与接收端口径一起打红。读者这边**不受影响**：旧录像没有这个字段 → 读回**不凭空补**（`录像.认场()` 不补 → 导出文本逐字不变），`tools/replay.mjs` 把它当「跨规则宇宙」的一条判据 | 下一次**录像 Schema 大版本升级**时（与接收端 Apps Script 同步改）把 `录像格式版本` 升为 `2`，并同时更新 `tests/上报.js` 第 [6] 段的最小样例常量 + `对局录像/README.md` 的格式表 + `协作/接口约定.md` §20.2 |

> **对账**：本文件的条目 ID 必须与 `协作/架构快照.json` 的 `knownDebtIds` **完全一致**（多一笔 / 少一笔都算红）。
