## 2026-10-10 · 阵型改成「前 3 后 2」+ 编队拖动（作者口头追加）

- **阵型配置化**：新增 `src/js/05-阵型.js`，站位只在这一个地方配（现在是 `前排 3 / 后排 2` = 5 格）。
  排号 / 行列数 / 格子编号 / 位名 / 「同一列上有哪些格」全部从它推出来；引擎和界面不再写死「3 列」，
  以后加阵型只改 `阵型表`。出击上限跟着变成 5（默认五人队刚好排满）。
- **连带改动**：范围武器的 `col`（前1+后1、前2+后2 是一列，前3 自己一列）、`cross`、`all` 都按新格子重算；
  「换位」按作者定的**按列对位**做（前排第 3 列没有对位时在本排换空位 / 换队友，都没有就作罢）；
  测试里的 6 台编成改成 5 台（位置 5 已经不存在）。
- **拖动**：编队界面支持拖动（pointer 事件，鼠标和手指都能用）：列表 → 格子、格子 ↔ 格子（互换）、
  拖回列表 = 取回；「点机师 → 点格子」保留。M4 的招募界面复用同一套方法。
- **舰娘调研**（作者让我去看的）：舰娘阵型里和前后排有关的是 **かばう**（替旗舰挡枪，按阵型有概率）
  和 **警戒陣**（5 只时「主力 = 后 2、警戒 = 前 3」，靠前的吸火力）；它**没有**严格的「一列对一列」规则，
  所以换位按作者说的做。结论写进了任务板和 05-阵型.js 的注释。
- 测试：`battle_ui.js` 新增 [2b] 拖动段；`sim.js` / `commands.js` / `smoke.js` 全部按新阵型更新，四套都通过。

## 2026-10-10 · [M3] 指令和意图

- **引擎改了骨架**：从「一次算完整场」变成**一回合一个回合地打**（`开局 / 设指令 / 算意图 / 打一回合`），
  因为玩家的指令每回合都可能改，预计算好的整场记录没法反映第 3 回合改的指令。`simulate()` 保留，
  变成「每回合都设同一套指令」的薄封装，M1 的测试一条没改就跑过了。
- **指令**（方案第 4 节）：进攻 / 集火 / 守护 / 防御 / 换位 + 每台「大招：自动 / 保留」。
  指令存的是「位」，进回合时解析成**单位引用**——换位之后格子会变，只认格子号会认错人。
  守护：单体攻击改打守护者并按防御结算，守护者自己攻击 ×0.7；一名队友同时只能被一人守护。
  防御：不攻击、防御值 +50、下回合开始回 5% 最大 HP。
- **意图**（方案 5.3）：`算意图()` 是纯函数（AI 本来就只算不改），界面在指令阶段直接读它写在敌人卡上。
- **职业特色**（方案 6.3）：六条都做了，**只对我方生效**（敌人按梯队，没有「职业」）。
  指挥 / 近卫 / 嘲讽 / 特种都会写进战斗记录（〔指挥〕〔连斩〕〔嘲讽〕〔守护〕）。
- **修掉一个真 bug**：「大招开关：保留」原来只是「不优先」，大招威力太高照样会被 AI 挑中——
  现在「保留」直接从可用武器里拿掉，测试 [7] 盯着这一条。
- 界面：战斗屏分成**指令阶段 / 播放阶段**；播完一回合回到指令阶段（指令留着）。
  顺手让「谁在打谁」看得清：攻击者朝接触线冲一下并加一圈光，受击方闪白 + 飘伤害数字。
- 新测试 `tests/commands.js`：集火（含够不到时退回「进攻」）、守护替队友挨打、意图与行动一致、
  防御 / 换位的效果、六条职业特色、大招开关；全部通过。
- 自己定的几处（已记进任务板）：职业特色只给我方；指挥的「同一排」= 同一横排且不含自己；
  嘲讽只对敌方单体攻击生效且守护优先于嘲讽。
