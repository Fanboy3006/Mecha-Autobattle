## 0. 作者原话与为什么改

作者 2026-10-12 原话（按顺序）：

1. 「玩家做的决策需要有反馈，可以是即时的，也可以是滞后的，但是**一定要有明确反馈**。」
2. 「我们不应该设置每一个单位的决策，**单位层面只应该选择开不开大招**；大方向的决策应该是**全队性质**的，类似三国群英传 2 那样，全军突击这种指令，而不是去控制每一个人怎么操作。」
3. 「这个方针**不需要有 buff**，只需要告诉全队的方向就行。防御这个是**放弃攻击**，这样就需要给单位增加他们自动执行的防御指令，增加防御值。」
4. 「**保持到改为止**，**奶妈正常行动**。」
5. （更早）调难度、设计敌人要让作者在开发过程中也有乐趣。

为什么改：现在的五条指令（进攻 / 集火 / 守护 / 防御 / 换位）是**逐台**下的，跟自动战斗的定位冲突，玩家也累；而且大多数决策没有明确反馈，玩家不知道自己做得对不对，难度也就调不出意义。

## 1. 全队方针（替换逐台指令）

### 1.1 两层决策

| 层 | 玩家能决定什么 |
|---|---|
| **全队层** | 每回合开始的指令阶段，选**一条全军方针**（下表 5 条之一）。**保持到玩家改为止。** |
| **单位层** | 只有「大招：自动 / 保留」。天人的「TRANS-AM 自动 / 手动 + 本回合开」**保留**：它是大招性质的单位开关，作者 10-11 拍板过「TRANS-AM 应该是单个单位开关的」，不冲突。 |
| 战前 | 站位只在开战前的编队界面摆；**战斗中不再有换位**。 |

### 1.2 五条方针

**方针本身不带任何加成**（作者原话第 3 条）。代价和收益全部来自现有规则。

| 方针 | 全队怎么做 | 代价 / 收益从哪来（都是现有规则） |
|---|---|---|
| **全军突击**（默认） | 每台各自挑目标攻击 = **现在的「进攻」AI，逐字不变** | — |
| **集中攻击**（玩家点一个敌人） | 打得到它的单位都打它；打不到的照常自由攻击 | 目标在后排时，直射吃「被挡 −20」；近战够不着就照常打别人 |
| **攻击后排** | 优先打对面后排 | 同上，吃「被挡 −20」；近战够不着就照常打前排 |
| **前守后攻** | 我方**前排**执行「全军防御」的规则；**后排**照「全军突击」 | 前排没有输出，换前排更耐打 |
| **全军防御** | 所有单位**放弃攻击**；能做非攻击动作的照常做，其余执行**防御动作** | 这一回合几乎零输出，换全队更耐打 |

### 1.3 细则（逐条实现，逐条测）

1. **保持到改为止**：方针存在 `ctx.方针 = { 类型, 目标位 }`，回合之间不重置；玩家在指令阶段改了才变。
   - **每一场新战斗开始时是「全军突击」**（Claude 定：这样 `simulate()`、平衡工具和同种子复现都有固定起点）。
2. **集中攻击**：
   - 目标被击破 → 方针**自动回到「全军突击」**，并写一条记录：`〔方针〕集中攻击的目标 X 已击破，恢复全军突击`。界面上的方针也跟着变（不能出现界面写「集中攻击」、实际在自由攻击的情况）。
   - 单体武器：照现在 `50-AI.js` 里「集火」那一段的写法（`bestWeaponOn(actor, 指定, …)`），打不到才往下走自由攻击。
   - 范围武器：落点**必须包含目标**的候选里挑期望伤害最高的；没有能包含目标的落点，就按单体规则处理。
3. **攻击后排**：
   - 候选目标先只看对面**后排活着、而且这台用现有武器打得到**的单位，在这些里照常按现有 AI 挑；一个都打不到 → 照「全军突击」。
   - 范围武器：优先挑**覆盖后排单位最多**的落点，同样多再比期望伤害。
   - 对面后排全灭 → 本回合照「全军突击」（方针不改，后排有增援上来就继续生效）。
4. **防御动作**（单位自动执行，数值**沿用现有「防御」指令**，一个数都不改）：
   - 本回合受到的伤害按「防御值 +50」结算（`20-战斗计算.js` 现有的 `defending` 口子）；下回合开始回复 5% 最大 HP（`60-战斗.js` 现有的 `防御回复`）。
   - 记录照现在那句：`X 进入防御（本回合伤害按防御 +50 结算，下回合开始回复 5% HP）`。
5. **「奶妈正常行动」的口径**（作者原话第 4 条）：在全军防御（以及前守后攻的前排）下，**只禁止攻击**，不禁止行动。
   - 做法：照常跑这台的 AI，但把**所有攻击类动作**（`kind: 'attack'`，含范围攻击）从候选里拿掉；剩下的修理 / 支援 / 增益 / 再动照常挑。**一个都挑不出来 → 执行防御动作。**
   - 例：Iris、维诺、苏菲照常修理（修理阈值 60% 照旧）；Feena 照常放「月光祝福」「再动」。
   - 「再动」的规则不变：被再动的队友照**当前方针**行动（全军防御下再动出来的那一下也不能攻击）。
6. **跟方针无关、照旧的东西**：职业特色（重装嘲讽、近卫连斩、尖兵、狙击、指挥、特种）、势力特色、藏品、零件、Boss 脚本、敌方 AI，**一律不动**。
   - 嘲讽照常生效；它现在接手了原来「守护」的保护作用。
   - 近卫连斩只在击破时触发，全军防御下不攻击自然不会触发，不用特判。
   - 月球王国「残月的余响」（队友攻击后追加）：队友不攻击就不触发，不用特判。

### 1.6 接口

- `设指令(ctx, 指令表)` 拆成两个：
  - `设方针(ctx, { 类型, 目标位 })`：类型是 `'全军突击' | '集中攻击' | '攻击后排' | '前守后攻' | '全军防御'`；认不出来的当「全军突击」。
  - `设单位开关(ctx, { [位]: { 保留大招, TRANSAM, 本回合开TRANSAM } })`：字段和默认值照现在的 `默认指令()` 里那三项。
- `simulate(我方, 敌方, 方针, 种子, 选项)`：`方针` 可以是
  - 一个方针（整场不变，例如 `'全军突击'` 或 `{ 类型: '集中攻击', 目标位: 4 }`），或者
  - **按回合的表** `{ 1: '全军防御', 2: '全军突击' }`：表里没写的回合**沿用上一回合**（和「保持到改为止」一致）。
  - 传 `{}` 或不传 = 整场全军突击。**这条必须保证**：`tools/balance.mjs` 和现有测试传 `{}` 时，结果要和改动前「全员进攻」**逐字一致**（守护 / 换位被删，不影响全员进攻的路径）。
- `算意图(ctx)`：照旧是纯快照，但要按**当前方针**算（全军防御下我方的防御值 +50 会影响敌人挑谁打）。「意图和实际一致」的现有测试必须继续通过。
- `window.__game` 上新增 `设方针 / 设单位开关`，删 `设指令`；在 `协作/接口约定.md` 登记。

### 1.7 界面

- 指令阶段：战场上方一条**方针栏**，5 个按钮，当前方针高亮。
  - 选「集中攻击」后，**点敌人卡片**选目标；被选中的敌人卡片上一直挂「集中攻击」标记，直到它被击破或方针改掉。
- 战斗进行中，方针栏上**一直显示当前方针**（玩家随时看得见现在全队在干什么）。
- 单位卡片上只留「大招：自动 / 保留」（天人另有 TRANS-AM 开关）。

### 1.8 验收（`tests/commands.js` 重写；旧的集火 / 守护 / 换位断言删掉，换成下面这些）

1. **默认路径逐字不变**：同种子，`simulate(…, {}, …)` 的完整记录 == 改动前「全员进攻」的完整记录。改动前先跑一遍存成快照文件，再对比。
2. **保持到改为止**：第 1 回合设「全军防御」、之后不再调用 `设方针`，第 2、3 回合仍是全军防御。
3. **集中攻击**：打得到目标的每台都打它；目标被击破后下一台行动时方针已经是「全军突击」，并且记录里有那一条 `〔方针〕`。
4. **攻击后排**：对面后排有能打到的目标时，单体攻击的目标全部在后排；后排全灭后照常打前排。
5. **全军防御**：本回合我方**没有任何攻击记录**；修理单位在有人低于 60% 时照常修理；Feena 照常放月光祝福；没有非攻击动作的单位都有「进入防御」记录；下回合开始有回复 5% 的记录。
6. **前守后攻**：前排单位没有攻击记录（修理 / 支援照常），后排照常攻击。
7. **意图一致**：五种方针下，指令阶段算出的敌人意图 == 实际行动（沿用现有那套断言）。
8. **不动如山**：阿布拉德在任意方针下都吃装甲 +30%。
9. 全部现有测试通过（`node tests/*.js` 逐个跑，贴真实输出）。

## 2. 三层反馈

### 2.1 规矩（写进 `CLAUDE.md` 第 7 节，作为第 10 条）

> **10. 玩家的每个决策都要有三层反馈**：
> **预告**（下决策时：这样做会发生什么）、**即时**（生效的那一下：它刚才起作用了）、**结算**（战后 / 一局结束：它值不值、帮了多少）。
> 以后每加一个机制或决策，交付时都要在任务板写清三层各是什么；测试里要断言战斗记录或战报里真的有那一句。缺一层不算做完。

### 2.2 方针的三层反馈

| 方针 | 预告（指令阶段） | 即时（战斗中） | 结算（本场战报） |
|---|---|---|---|
| 全军突击 | — | — | 本场伤害占比 / 每回合输出 |
| 集中攻击 | 目标卡片挂标记 + 「全队对它的预计伤害合计 X / 它剩 Y HP」 | 每一下打它的伤害数字旁标「集中」；击破时 `〔方针〕集中攻击击破 X` | 「集中攻击：X 在第 N 回合被击破（共 K 次攻击）」 |
| 攻击后排 | 对面后排卡片挂标记；对每台我方标「打得到 / 打不到后排」 | 被挡时伤害旁标「被挡 −20」（已有的就沿用） | 「攻击后排：击破后排 N 台；因被挡少中 M 次」 |
| 前守后攻 / 全军防御 | 进入防御的单位卡片上显示盾标 + 「防御值 +50」 | 挨打时伤害数字旁标「防御」+ **这一下少挨了多少**（见 2.4） | 「防御共少挨 X，回复 Y」 |
| 大招开关 | 冷却剩几回合；「保留」时卡片上有标记 | 放大招切主题曲（已有）+ 记录 | 「大招造成全场 N% 的伤害」 |

### 2.3 其他决策（按 2.1 的规矩，第一批先补这几条）

| 决策 | 预告 | 即时 | 结算 |
|---|---|---|---|
| 站位（编队界面） | 每个位标出「会被敌方哪几台打到」（敌方意图已有的部分沿用） | 被挡标记 | 「前排承伤 N%」 |
| 势力羁绊（如秘银交叉训练） | 编队界面画出谁借到了谁的特色 | 触发时的记录（各势力已有的沿用） | 「借来的特色贡献了 N 次击破 / X 伤害」 |
| 藏品 / 零件 | 拿的时候写清作用（已有） | 生效时那台卡片闪一下 | 「这件本局加了 X」（按 `RUN` 累计） |

### 2.4 实现要点

- 「防御少挨了多少」：在结算这一下时，用同一套参数、**不带防御加成**再算一次 `dmgCore`，取两次的差值。**只用来显示，不影响实际伤害，不消耗随机数。**
- 「本场战报」：战斗结束屏加一块，按 2.2、2.3 的结算列逐条显示，数据全部从 `ctx.log` 里统计（缺字段就在记录里补字段，不要另开一套统计）。肉鸽里同样显示，记录写进 `RUN.日志`。
- 测试：每条结算句在固定种子下真的出现，数字和记录逐条加起来一致。

### 2.5 「如果当时没这么做」（第 4 件，前三件做完再做）

我们的引擎是确定性的：同种子、同方针，结果完全一样。所以战后可以**换掉一个决策再跑一遍**，告诉玩家他的决定换来了什么。

- **第一版只做一种**：本场有**阵亡**或**险些阵亡（剩 HP < 15%）**的我方单位时，取那一回合，把方针换成「全军防御」重跑一遍（如果那一回合本来就是全军防御，就换成「全军突击」），在战报里写：
  `「如果第 N 回合改成全军防御：X 不会倒下 / 仍会在第 M 回合倒下；战斗多打 K 回合 / 结果变成败。」`
- 做法：用同一组 `开局` 参数、同种子，`simulate()` 传按回合的方针表（1.6）重跑，**只读结果，不改真实战斗**。
- 诚实说明（**写进界面的小字**）：换掉一个决策后，后面的随机数顺序可能跟着变，所以这是**估算**。只展示粗粒度结果（谁倒没倒、多打几回合、胜负），**不展示精确伤害**。
- 测试：重跑不改变真实 `ctx`；同种子两次结果一致。

## 3. 调参室（作者亲手调难度）

参照已有的「音乐鉴赏」页做：作者在页面上调，存在浏览器里，「复制设置」交回来，由 AI 写进数据表。**目的是让作者拉一下、看一眼，几秒钟就有反馈。**

### 3.1 入口与布局

- 开场菜单加「**调参室**」入口（和「音乐鉴赏」并列）。
- 左边选战斗，中间调数，右边看结果。

### 3.2 选战斗

### 3.3 能调的数（第一版）

- **敌人全局倍率**：HP ×、伤害 ×、装甲 ×、防御值 +（四个滑条，默认 1 / 1 / 1 / 0）。
- **按敌人种类覆盖**：选一个敌人键（如 `captain`），单独调它的 HP / 装甲 / 威力倍率。
- **Boss 脚本**：`Boss脚本` 里的大技能间隔、伤害倍率、阶段参数。
- **回合上限**（只在调参室里生效，用来试）。

### 3.4 看结果（点「跑」之后）

- 胜率；**胜场**平均回合；回合数分布（1、2、3…12 各几场）。

## 4. 敌人设计流程（给作者、Claude、DSH 都看）

### 4.1 原则：敌人是一道题，不是一张数值表

一个敌人由「**它逼玩家做什么决定**」来定义，数值是第二步。我们玩家手里的杠杆是：**编队选谁、站位、全军方针、大招开关、藏品**。每个敌人至少要针对其中一个。例：

| 敌人逼玩家做的事 | 对应的杠杆 |
|---|---|
| 第 1 回合先手爆发 | 第 1 回合选「全军防御」 |
| 会回血的头目 | 「集中攻击」它 |
| 后排的炮台 / 奶妈 | 「攻击后排」 |
| 专打后排的刺客 | 站位（把耐打的放进挡住后排的位）、嘲讽 |
| 打一整列 / 一整排的炮 | 站位要错开 |
| 被大招打中会反伤 | 大招开关拨到「保留」 |
| 厚装甲 | 编队带特殊伤害 |

### 4.2 一个敌人怎么做出来

1. **作者说一句感觉**（例：「一个会偷后排的忍者」「打不死但越打越慢的东西」）。
2. **Claude 出三个机制不同的版本**，每个一张「敌人卡」，不给数值表：
   - 一句话：它在战斗里做什么；
   - 玩家看到什么（战斗记录 / 意图预告里怎么显示）；
   - 它逼玩家用哪个杠杆，怎么破；
   - 三层反馈：玩家怎么知道自己破对了。
3. 作者挑一个 → Claude 写字段和初稿数值 → **DSH 实现** → 作者在调参室里调手感、在游戏里遇到它。
4. **一次只做一个敌人。** 循环越短越好。

### 4.3 明日方舟 / 舰娘调研（DSH 可以和第 1–3 件并行）

产出放 `协作/敌人设计参考-明日方舟与舰娘.md`。要求：

- **搬「问题」，不搬敌人和数值。** 每条写：
  1. 原作里的敌人或节点（名字 + 一句话它做什么）；
  2. 它在原作里逼玩家做什么决定；
  3. 换到我们这里对应哪个杠杆（4.1 那张表），**做不了的直接写「做不了」+ 原因**（我们没有格子地图、移动、地形、区域，见 `docs/数值换算需求单.md` 第 1.2 节）；
  4. 战斗记录里它看起来是什么样（一句话）。
- **明日方舟**重点看：每类敌人「针对哪种干员 / 哪种打法」（重装 vs 法伤、飞行、无视防御的术士、自爆、护盾、隐身、召唤、Boss 的阶段机制）。
- **舰娘**重点看：**节点**怎么逼玩家改编成（潜艇点、空袭点、夜战点、Boss 点的特效 / 弱点机制、海域的路线条件）。舰娘的乐趣主要在编成和路线，不在敌人 AI。
- 至少 20 条；按「对应我们哪个杠杆」分组；每组标出我们现在**已经有**的敌人里哪个算是这一类（没有就写「缺」）。
- **不写数值建议**（数值归 Claude）；出处给链接。
