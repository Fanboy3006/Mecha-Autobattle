### 1.1 ARGON 裁定两处口径（新增，CC 照此执行）

**① 补位阈值 = 初始手牌上限（6），不是手牌总上限（10）** —— 维持现状，理由：

- 签字文本「手牌不到 6 张时按序补入（不超过手牌总上限 10）」有两解。ARGON 裁定取 **`新张数 < 6`（即 `min(初始上限, 总上限)`）**：
  开局手牌数在 [0, 6] 区间内不变（D-01 取舍说明里承诺的「开局手牌数不变、数值手感不变」得以保持）；
  照「补到 10」会让每回合开始把手牌灌到 10 张，与「空位补入」的取舍说明自相矛盾，且显著改变气力轮转节奏（属于玩法变更，不在 D-01 授权范围内）。
- **兑现**：`btl.gd` 的 `候补补位()` 现有写法已经正确，**不要改成补到 10**。

**② 正式规则下「取前 6 张」之后对手牌重排（0 耗回气牌提前）保留** —— 采纳，理由与依据：

- 正式规则分支在 `slice(0, 6)` **之后**还有一次 `免费回气先` 排序（`btl.gd:360`），所以手牌**排列顺序**与「纯粹按档位取前 6」不同。
- ARGON 实测默认五人队的取值结果：手牌 **6 张并含【激励】**（激励必进前 6）→ 重排只影响**展示顺序**，把唯一的 0 耗回气牌排到首位，对玩家是纯正收益，也让「JS 参考 vs 正式规则」的差异只剩「谁被截断」这一件事，更好对账。
- **兑现**：保留该排序；但请在 `已接受差异表.md` 的 D-01 行「对账开关」一列**补一句**「正式规则在取前 6 张后按『0 耗回气牌优先』重排（只影响手牌顺序）」，避免以后有人把它当成未登记的差异。

## §2 🔴 冻结语义纠错（开工前必须采纳，否则 M3 会照错的数施工）

以下四条出自交接卡 §3.1，**与 `js-reference-final`（`a745235`）的实际行为不一致**。ARGON 已逐条读源头核对，出处见每条的 `文件:行号`。
**它们不在 138 场战斗黄金样例的覆盖范围内**（那 138 场全是战斗），所以**不会**被对拍测试挡住 —— 只能靠本表拦住。

### 纠错 A（严重）· 推进剂余量表与「最短路」口径

| | 交接卡 §3.1 第 2 条（错） | `js-reference-final` 实际行为（对） |
|---|---|---|
| 余量表 | `2 / 4 / 6 / 8` | **`{ 1: 2, 2: 2, 3: 4, 4: 4 }`**（`src/js/91-地图.js:237`，★ 2026-10-13 收紧） |
| 上限公式里的「最短路」 | 「该图起点到出口最短路」 | **`直达` = `距离.get(出口尽头)`**（`91-地图.js:474-497`）；不再取「绕不过守军的那一条」 |
| 上限落点 | 「约 8 / 9 / 11 / 12」 | 四层初始上限**中位 8 / 9 / 11 / 12** —— 这一条交接卡是对的 |
| 预算比 | （未写） | `直达最短路 ÷ 上限` **最大值 0.846 ≤ 0.88**（`tests/map-1` 的 `[3b-1]` 钉着） |

**为什么必须改**：若照 `2/4/6/8` 施工，四层推进剂上限会**分别多出 0 / 2 / 2 / 4 点**，预算比被整体抬高，第 2 层与第 4 层的「推进剂张力」直接消失 —— 这是**难度与地图手感的实质变化**，不是笔误级别的细节。

**顺带纠正**：余量表收紧的**原因**是「守军改放到『直达最短路上的格 / 尽头的邻格』，所以『打赢守军再出口』的实际步数就等于直达，不再需要为绕路留预算」（`91-地图.js:239-248`）。
换言之，**守军是堵在直达路线上的收费站，不是需要绕开的东西** —— M3 的 `守军` 安放逻辑要照这个口径，否则余量表算出来的上限会对不上。

### 纠错 B · `林间空地` 不扣推进剂（交接卡写成「不扣或按节点表结算」，含糊）

- 实际：落到**未走过的** `类型 === '空'` 格 → **照常扣 `d` 点推进剂**（消耗 = 走过的格数，`src/js/90-肉鸽-3-开局与移动.js:350`），并当场标 `已过` + 结果条「经过林间空地：落脚休整片刻，未遭遇敌情。」（同文件 357-362，**不弹模态框**）。
- **口径**：`林间空地` 是**零成本的信息反馈格**，不是补给格。M3 照「扣 1 点 + 标已过 + 一条结果文本」实现，**不要**给它做「不扣推进剂」的分支。

### 纠错 C · 追击战之后是「下一层上限 −2」，交接卡漏了

- 实际：推进剂归 0 → 打追击战；**打赢后直接换层**（追击的本质是「被赶到下一层」），并把 `层推进剂修正 = −2` **记在下一层**（`90-肉鸽-3-开局与移动.js:192-197`）。
- 交接卡原文「打赢恢复少量推进剂」**没有这个恢复**：作用是「被追击过」的惩罚落在**下一层上限**上。
- **口径**：M3 的 `追击之后()` 要写 `追击 = true` + 进下一层 + 下一层上限 −2，**不要**实现「恢复推进剂」。

### 纠错 D · 出口那一步的追击战过「守军闸」（2026-10-13 修的一个真 bug）

- 实际：**只有**「脚下是出口格 + 推进剂 0」触发的这一次追击战，要过守军闸 —— 守军没清就**通不了下一层**，这一趟记进 `RUN.待换层`，等打赢守军那一下当场接着换层（`90-肉鸽-3-开局与移动.js:199-230`）。
- **走小径的免打守军**（`本层出口类型() === '小径'`），追击战打赢就照常换层 / 通关。
- 「在别处用光推进剂」触发的追击战**不加这道闸**。
- **口径**：交接卡「不直接判负」这句仍然成立（是「卡在出口、回头打守军」，不是判负），但 M3 必须实现 `出口追击` 这个**显式标记**（由「知道脚下是不是出口」的调用方置位），不能靠「`追击 && 推进剂 ≤ 0`」推断 —— 两种情形状态上一模一样。

### 纠错 E（措辞）· 小径的 `+2` 加在**下一层**

- 实际：走 `出口小径` **不给希望**，而是把**下一层的推进剂上限 +2**（`91-地图.js:128-136`、`259-267`；加的**量**从 `肉鸽数值.出口小径加成` 取，登记值是 `2`）。
- **口径**：实现成 `RUN.层出口小径`（层号数组）+ 下一层上限 +2，**不要**实现成「当前层立刻 +2 推进剂」。

| # | 情形 | ARGON 口径（依据） |
|---|---|---|
| 1 | 推进剂上限里「零件加成」与「余量表」的次序 | `上限 = 基础(该图最短路) + 余量[层] + 层修正 + 零件 + 小径`，**加法可交换**，逐项相加、**最后不要再一次取整**（`91-地图.js:274-296` 的 `推进剂明细()` 是唯一真源，界面读它） |
| 2 | 地图生成的随机数消耗 | 每层每次尝试 = **一条独立流** `mulberry32((种子 + 试*104729 + 试*试*31) >>> 0)`，存在率 `r() < 存在率` **只作用在格子存在性那一句**；「保证连通」补的 L 形走廊**发生在它之后、不消耗随机数**（`91-地图.js:348-382`）。★ 这条是**纯口径**，任何「用补格影响随机流」的实现都是错的 |
| 3 | 起点 / 出口 / 守军 / 隧道的初始化次序 | 起点 = 最上排中间格（固定补进）；出口尽头 = 最下排里离中间最近的**连通**格；出口小径 = 最右列离尽头 **≥3** 步；守军 = 四级优先（尽头邻格 ∧ 在直达最短路上 ∧ 必尽 → …，`91-地图.js:411-448`）；隧道 = 简单成对（左两列一端、右两列一端，图上距离 ≥2）。次序错一处 → 同种子地图就变 → 局外样例全红 |

| 6 | 藏品拿满转源碳 | `藏品转源碳 = 5`（实测导出值）；编制类藏品额外掉率 `0.15`（`编制类额外掉率`）。结算次序：先判「是否已持有 / 是否已满」→ 满则转源碳，**不再新增持有** |
