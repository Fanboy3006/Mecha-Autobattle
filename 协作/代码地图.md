## 一、四层与铁律

| 层 | 目录 | 一句话 | 铁律 |
|---|---|---|---|
| 内核 | `godot/core/` | 纯逻辑：战斗、肉鸽、数据表、工具 | 不碰场景树 / 文件 / 时间 / 引擎随机数；不引用 `session/` `presentation/` |
| 会话 | `godot/session/` | 读数据、存档、命令分发；**界面唯一入口** `GameSession` | IO 只在这一层；不引用 `presentation/`（唯一豁免见 RouteMap §4.2） |
| 表现 | `godot/presentation/` | 场景与界面 | 只读内核状态；写操作一律经 `GameSession` |
| 测试 | `godot/tests/` | `run_tests.gd` 自动发现 `unit/test_*.gd`；`golden/` 放样例 | 别打开 `tests/golden/` 下的大 JSON |

数据：`godot/data/js/*.json`（数值与内容，由 Godot 侧直接维护）· `godot/data/cards/*.json`（各势力 / 职业卡包，顶层写 `"结构"` 声明）。

## 二、一场战斗怎么跑

```
Setup.开局()                      core/battle/setup.gd      开局、单机牌组初始化、胜负判定
 └ 每回合 PhaseFlow               core/battle/phase_flow.gd 阶段推进
    ├ 玩家出牌 CardPlay → CardExec / WeaponExec    判定能不能打 → 执行卡牌 / 武器
    ├ 敌方 AI / Intent / Boss                      选目标、意图、Boss 脚本
    └ 结算 Flow → Calc                             单目标攻击结算（唯一入口）→ 命中 / 伤害 / 减免
 └ Setup.打一回合() / 结束判定
```

## 三、`core/battle/` 文件分组

**通用内核**（不许点名势力模块，规则 ⑤ 棘轮会拦）
- 算法：`calc`（命中 / 暴击 / 伤害 / 减免 / 修理 / 标定）· `reach`（射程、被挡、可达）· `fm`（阵型几何）· `swap`（换位底座 `swapPos` + 刷新链）
- 流程：`setup` · `flow` · `phase_flow` · `card_play` · `card_exec` · `weapon_exec` · `intent`
- 牌组：`deck_flow`（发牌、抽弃、大招槽、**武器栏换装栈**）· `sub_deck`（副牌组）· `card_pool` · `public_cooldown` · `ai_deck`
- 战斗状态：`btl`（高频转发）· `battle_log` · `morale`（战意）· `guard`（嘲讽 / 镜甲 / 自爆）
- 对手：`ai` · `boss` · `diff`（难度）
- 单位与参数：`units` · `traits`（编成词条）· `params`（**战斗结构参数总入口**）· `data_fn` · `relic_battle`（藏品战斗落地）
- 通用卡：`card_effects`（32 张战术牌）· `class_cards`（职业牌）· `repair_cards`（维修职业分类牌）

**注册表**（唯一允许点名模块的地方，规则 ⑥ 管边界）
- `rule_hooks.gd`：规则钩子 / 出牌门槛 / 大招槽按处理者分派的 `顺序` 表
- `fac.gd`：势力特色框架（17 个钩子）+ `ORDER`

**势力模块**

| 势力 | 文件 | 卡包 |
|---|---|---|
| ATX | `fac_atx` `fac_cb` `atx_three` `atx_duo` `atx_faction` `atx_godsbet` `atx_luck` `atx_smoke` `atx_rewrite` `atx_chips` | `cards/ATX.json` |
| 秘银 | `fac_mith` `mithril_v03_cards` | `cards/秘银.json` |
| 天人 | `celestial_v01`（全仓最大的生产文件之一，改前先看体积棘轮） | `cards/天人.json` |
| 殖民卫星军 | `colonial_v01` `colonial_units` `colonial_deck` `colonial_awaken`（觉醒 QTE 接口） | `cards/殖民卫星军.json` |
| 月球王国 | `fac_moon`（旧版光环 / 残月 / 不动如山；**v0.2.1 待实现**） | — |
| 影世界 | **未实现**（v0.2.1 待实现） | — |

## 四、`core/` 其余

- `core/run/`：肉鸽局外。`map_generator`（地图生成）· `map_navigator`（移动规则）· `node_resolver`（节点结算）· `run_state`（一局状态 / 存档字典）· `deck_builder` · `roster_manager`（名册）· `part_system`（零件）· `relic_system`（藏品）
- `core/data/`：`db`（全局表 `Db.T`）· `game_data` · `game_catalog`
- `core/util/`：`js`（`J`：JS 兼容语义，四舍五入 / 真假值都走它）· `js_compat`（稳定排序）· `rng`
- `core/version.gd`：版本号（界面 / 存档 / 录像都读它）

## 五、`session/` 与 `presentation/`

- `session/game_session.gd`：门面（开局 / 存档 / 进战斗 / 节点结算）
- `session/` 子模块：`data_loader`（JSON → Db，卡包结构校验、卡 id 全局唯一）· `save_service` · `battle_flow` · `battle_hand_view` · `battle_deck_view` · `run_facade` · `display_helpers` · `tooltip_text` · `live_monitor`
- `presentation/` 主画面：`boot/boot` · `menus/menu_view` · `battle/battle_view`（组装 + 转发）· `battle/result_view`
- 战斗面板：`board_panel`（棋盘）· `hand_panel`（手牌栏）· `deck_sidebar` · `log_panel` · `drag_aim`（拖拽瞄准）· `battle_fx_player`（演出）
- 肉鸽画面：`run_map/map_view` · `run_map/formation_view` · `menus/` 下 `shop` `rest` `event` `pick_card` `roster`
- 公共件：`theme/ui_theme` · `widgets/` 下 `hover_tooltip` `unit_card` `top_bar` `modal_layer`

## 六、按现象找文件

| 现象 | 先看 |
|---|---|
| 伤害 / 命中 / 暴击不对 | `calc` → `flow`（攻击结算入口） |
| 打不到 / 射程 / 被挡 | `reach` · `fm` |
| 牌打不出去 | `card_play`（不可打原因）→ 对应势力模块的 `卡不可打原因` → `rule_hooks` 顺序表 |
| 大招相关 | `deck_flow`（大招槽）→ 槽上 `"处理者"` 指向的模块 |
| 武器栏被换掉没还原 | `deck_flow` 的 `压栈武器栏` / `弹栈武器栏` |
| 换位 / 站位刷新 | `swap` |
| 敌人行为怪 | `ai` · `intent` · `boss` · `diff` |
| 数值参数从哪读 | `params` → `data/js/71-改动-5-参数入口.json` |
| 地图 / 节点 / 奖励 | `core/run/` 对应文件 |
| 界面显示不对 | 先查 `session/` 的 `*_view` / `display_helpers` / `tooltip_text`，再查 `presentation/` |
| 显示名 / 改名 | 去版权化-A（NAME 单）进行中，见 `协作/架构/NAME回执/` |

## 七、改代码的硬约束（详见 `godot/README.md`）

1. 新势力 / 职业模块：在 `rule_hooks.gd` 的 `顺序` 表登记 → 实现钩子 → 卡表放 `data/cards/` 并登记快照测试；**不许**在 `calc` / `btl` / `flow` / `card_play` 里点名模块。
2. 体积：单个 `.gd` > 1,000 行或 > 12,000 估算 token，**先拆再加功能**；`SIZE_RATCHET` 只许下调。
3. 注释：文件首行 `##` 职责注释不许动；生产代码注释占比 ≤ 15%，测试 ≤ 20%。
4. 门禁：全量 `run_tests.gd` 全绿 + `node godot/tools/build_godot_routemap.mjs --check` EXIT=0。
5. 改战斗结果：只重录一次原生样例（`godot/tools/record_native_golden.gd`，180 场约 3.5 分钟）并附差异摘要。
