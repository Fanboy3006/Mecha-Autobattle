### 三、数字怎么算（每条一句话 + 代码落点）

1. **预计伤害合计** = 逐台我方问 `chooseAttack(u, ctx)`（纯函数），**只有这一回合真的会落在点名目标身上**的那几台
   把它那一下的 `expected` 加起来（取整）。`台数` 另算：`打得到位(u, ctx, 目标位)` 数出来（射程 + 阻挡 + 范围落点）。
   ⚠ **两个数有时不等** —— 见第五节的第 1 条（上一件交付的判定就这样，这一件没改）。
2. **打得到后排** = 这一台手上的攻击武器里有一把：近战要 `rowReachable()` 放行；直射够得到（被挡只是 −20）；
   曲射 / 范围要有一个落点盖住**至少一个后排位**（`areaSlots()`）。
3. **大招冷却剩 N 回合** = 这一台**等级够、算大招、第一期可用**的那几把里，
   `max(readyTurn − 当前回合, cd)` 取**最小**（= 最快能放的那一把）；`≤ 0` 就是「已就绪」。
4. **防御少挨** = §2.4 的算法：**同一套参数、不带防御加成再算一次 `dmgCore`**，逐段取
   `不带防御时的那一下 − 实际挨的那一下`（`Math.max(0, …)` 兜底）。三次调用都在
   `20-战斗计算.js` 的 `resolveAttack()` 里：**先算预览（`preview: true` + `不带防御加成: true`）、再算真的**，
   两次看到的靶子状态完全一样；那一次预览**一个随机数都不消耗**。
5. **本场战报的每一个数**都从 `ctx.log` 数出来（§2.4：「缺字段就在记录里补字段，不许另开一套统计」）：
   - `我方 / 敌方伤害`：`类型 ∈ {攻击, 残月余响}` 且 `单位方` 对得上的那些记录，把 `伤害` 加起来
     （用类型白名单是为了**不重复计账**：势力记录里也有别的数字）；
   - `每回合输出`：同一批记录按 `回合` 分组求和；
   - `共 K 次攻击`（集中攻击）= 带 `集中` 字段的记录里、`目标位` 等于那次击破的位的条数；
   - `击破后排 N 台` = `方针 === '攻击后排'` 且 `命中` 且 `目标剩余HP ≤ 0` 且目标在后排位的记录条数；
   - `因被挡少中 M 次` = 上面那批里 `被挡` 且 `!命中` 的条数；
   - `回复 Y` = 现成的 `类型: '回复'` 记录的 `回复` 之和；`防御共少挨 X` = `防御少挨` 字段之和；
   - `大招造成全场 N%` = 我方攻击记录里**是大招**的那些的 `伤害` 之和 ÷ 双方总伤害 —— 判定复用
     `96-音乐.js`「放大招切主题曲」那条（按 `单位位` 找单位、按 `武器` 名字找条目、问 `isUltimate`），
     所以**不需要给攻击记录加「大招」字段**（默认路径的记录因此一个字段都不多）；
   - `前排承伤 N%` = 打我方的记录里 `目标位` 在前排的 `伤害` 之和 ÷ 我方挨的总伤害。

  localStorage 的配额本身就是按字符算的，两个口径一致；换成字节数的话中文记录会缩水到约 1/3。
- **单场就超上限时「不存」而不是「硬塞」**：硬塞会把整个键撑到上限之上（也就失去了「别让存档膨胀」的意义）；
  屏上那一刻仍然能复制 / 下载（导出走的是内存里那一份，不依赖 localStorage）。
- **`第 N 场` 的编号 = 这一场在「最近 N 场」里的位次**（最新的一场 = 第 N 场），
  界面上也是这么写的（存到第 1 场时说「第 1 场」，存满 5 场后说「第 5 场」）。
- **`我方 / 敌方` 存规格而不是完整单位对象**：完整单位对象一场要 60 KB（Boss 场），规格版 38 KB 且够复现
  （种子 + 编成 + 方针表 + 单位开关 + 波次 + 强化都在）；要真实数值随时能 `simulate()` 重放出来。
- **导出行首加前缀「行号. [第 N 回合] 」**：`文本` 一个字没改（抽条逐字比对钉着），
  前缀只是为了「一行一条 + 能对回第几回合」；作者要的是**记录原文**，不是排版。
- **测试第二处放 `tests/run.js`**（不是 `tests/commands.js`）：理由写在上面第「四」节最后一条。

### 三、余量为什么是 2 / 4 / 6 / 8（贴数字）

作者原话：「余量曲线先试 **+2 / +2 / +4 / +4**（必须是偶数）… **若你的实测量出来 +4 太松，可以调，但要贴数字**」。
实测（24 种子 × 4 层，同一批图、只改余量）：

| 余量 | 第1层 可行路线中位 | 第2层 | 第3层 | 第4层 | 预算比中位（第1层） |
|---|---|---|---|---|---|
| +2 / +2 / +4 / +4 | 16 | 15 | 16 | 20 | 0.80 |
| **+2 / +4 / +6 / +8（定稿）** | **17** | **14** | **15** | **24** | **0.75** |
| +6 / +8 / +10 / +12 | 19 | 22 | 16 | 24 | 0.571 |

读法：**余量往上加，可行路线只涨到一个「路网上界」就停住**（第 1 层 19 / 第 2 层 22 / 第 3 层 16 / 第 4 层 24），
再加只会把预算比压到 0.4–0.5（推进剂远超需要 = 又变回「走哪都一样」）。
定稿取 **2/4/6/8**（逐层 +2、全是偶数）：预算比中位 0.60、可行路线中位 16（平均 31.5），
是「余量不够 → 路线太少」与「余量过多 → 推进剂白给」之间最平衡的一档。

### 五、节点安放（调研 A2 / A3，「尽量」不做硬保证）

- **A2 守军放必经点（收费站）**：`生成层` 里优先挑「起点→两个出口」的割点，且仍然**贴着出口**（守军没清时两个出口都不放行的老语义不变）；
  没有合格格位 → 「两出口共同邻格」→ 「任一出口邻格」。实测（40 种子/层）：守军是**必经点** 85% / 100% / 85% / 100%（1/2/3/4 层）、**贴出口 100%**。
- **A3 战斗类进干路 / 收益类进支线**：优先池 = 割点 / 度 ≥3 的干路（战斗类）、死胡同 / 度 ≤2 的支线（收益类）；
  池子不够就回落到「哪儿都行」（**个数优先**）。实测：**收益类进支线 100%**（4 层 × 20 种子），
  **战斗类进干路 90%**（第 2 层最低 71%）。**没有**为「战斗类一个都不落死胡同」加特判。

### 六、自己定的地方（口径 + 理由）

① **连通下限按面积重算**：调研 §3 那串 `≥20/≥23/≥21/≥27` 与「5×5 × 0.78 ≈ 19.5 格」**自相矛盾**（≥20 会把 5×5 逼死）。
   口径 = `max(边长, ceil(0.85 × 存在率 × 边长²))`；真值 17 / 23 / 21 / 27（= 期望存活格的 87–89%），比旧的 `≥15`（24 格的 62%）严得多。
   **实测每层存活率**：19.5 / 26.2 / 25.1 / 33.2 格（期望 19.5 / 25.9 / 23.8 / 30.4）。
② **节点个数按可用格数放大**：`round(第 1 层个数 × 该层期望存活格 ÷ 第 1 层期望存活格)` + 整数配平。
   真值（`计划要放()`）：第 1 层 `作战4 精英1 黑市1 事件2 瞭望站2 遗迹1 招募站1 空2`（**与改前逐字一致**）；
   第 2 层 `作战5 精英1 侵蚀源1 黑市1 事件3 瞭望站3 遗迹1 休整1 招募站1 隧道2 空3`（22 槽）；
   第 3 层 `作战5 精英1 侵蚀源1 黑市1 事件2 瞭望站2 遗迹1 休整1 招募站1 隧道2 空3`（20 槽）；
   第 4 层 `作战6 精英2 侵蚀源2 黑市2 事件3 瞭望站3 遗迹2 休整2 招募站2 隧道2 空4`（30 槽）。
   ★ 第 3 层槽位比第 2 层少是**对的**（存在率 0.66 < 0.72 → 可用格更少），不是 bug。
③ **起点 / 出口那一格要「保证连通」**：实测 5×5 / 78% 下起点所在连通分量**中位只有 12 格**，
   「最下排一个可连通格都没有」在 300 次抽样里是 **100%** —— 78% 在 5×5 上够不到最下排（在渗透阈值附近）。
   所以生成时补一条 **L 形走廊**（从起点分量里离目标曼哈顿最近的格出发，先走行再走列），
   **存在率那一句一个字没改**，补格只发生在这条走廊上（实测每层 +0.3 / +0.6 / +0.9 / +1.4 格）。
④ **顺手修掉一个真 bug：重试种子的同余**。原写法 `mulberry32(种子 + 试×7919)`；
   而探针 / 测试常用 `种子 = 基种子 + i × 7919` —— 于是
   `(种子+7919) + (试−1)×7919 === 种子 + 试×7919`，**第 i+1 个种子的第 试−1 次尝试 = 第 i 个种子的第 试 次尝试**，
   一整批种子会生成出一模一样的图（实测第 2 层 24 个种子全是 23 格 / 同一条隧道；可行路线中位数被压到 10）。
   改成 `种子 + 试×104729 + 试²×31`：不再撞、也不与「种子差 7919」的调用方撞，仍然**同种子逐字相同**。
⑤ **推进剂上限照「实际最短路（含守军那一圈）」加**：守军是收费站（守军没清两个出口都不放行），
   所以「真正要走的最少步数」= `d(起点→守军) + d(守军→出口)`，它通常**大于** `d(起点→出口)`。
   照「直达最短路」给推进剂的话，作者要的「+余量」会被守军那一圈绕路吃光（预算比又会 >1.0）。
   所以 `地图.最短路` 存的是**含守军的那条**（两个出口取更费的），另存 `最短路尽头 / 最短路小径 / 直达` 三个对照量。
⑥ **重试上限 200 → 2000**：新硬条件让单次成功率降到 ~1/50–1/700（第 4 层最狠）；2000 仍然确定性（偏移只由 `试` 决定）。

### 四、口径要点（**给「分析会话」的规矩全在 `协作/战报分析-口径.md`**）

1. **工具 = 事实层，文档 = 推断层**，两边不越界。工具**只解析 + 算术**，每条结论挂「依据 = 记录第 N 条」；
   「他为什么这么做」这种**动机**一律归「需要问他」，工具和文档都不许给。
2. **推断必须标证据强度（强 / 中 / 弱）+ 写 2–3 条依据**；**不许评判玩家**（不写「打得好 / 差」），
   只写「你做了什么、它与规则的关系、当时还有哪些选择可行」。
3. **记录里没有的一律写「记录里没有这一项」**，一个字都不编（缺字段清单见下面第五节）。
4. **可以「重算」，但只能调引擎自己的函数**：`maxHp` 走 `makeUnit()`、是否大招走 `isUltimate()`、
   增援的强化走 `敌方强度倍率(层, 梯队)` —— **没有一条自己发明的公式**；`--no-game` 时整块关掉、照实说判不了。
5. **同名多台合成一组**（记录里没有 `单位位`，不硬猜是哪一台）：组槽的「倒下」= **整组全倒**（对整组是真的）；
   组槽 HP 偏小 → **不拿它判异常①**（避免误报），并在报告里点名。
6. **命令行的坑**：本机沙箱不给子进程开管道（`spawnSync` 默认 `'pipe'` 会 EPERM）→ 测试**import 工具直接调 `main()`**

## 二、判定：**漏洞**（不是设计）

- 规格（`CLAUDE.md` 第 2 节 M4 段，逐字）：`第 4 层：打赢出口守军 → 点出口 → 肉鸽.下一层() → 层 ≥ 4 → 肉鸽.通关()`；
  同段还有作者原话那条链：**「打完终点 Boss 通关」**。
- 代码里有**两道**守军闸，都查「守军那一格清没清」（`已过 || 类型 === '空'`）：
  `src/js/90-肉鸽.js` 的 `格菜单()`（出口格只给「去节点:守军」那一条）与 `src/js/80-界面.js` 的 `前进()` 开头。
  两道闸都在**「推进剂 0 → 追击战」之前**……**但 `前进()` 里那两道是顺序执行的，`追击战()`（大地图上的强制追击）
  走的是另一个入口** —— 见下一节。
- **★ 真漏洞点**：`src/js/80-界面.js` 的 `前进()` 里，「推进剂 0 → 追击战」那一支打赢之后由
  **`90-肉鸽.js` 的 `追击之后()` → `换层()`** 收尾（战棋 `31:300-302` 的 chase 分支）。
  `换层()` 改动前**只做两件事**：`层 >= 4 → 通关()`、否则 `进层(层 + 1)` —— **一个守军都没查**。
  ⇒ 「在出口那一格把推进剂花成 0、打赢追击战」= **绕开出口守军直接换层 / 直接通关**。
  第 4 层那一下尤其致命：`换层()` 的第一句就是 `通关()`。
- 复现（探针，仓库外）：第 4 层、守军没清、站在出口那一格、推进剂 1 → 走一步进出口（花成 0）
  →`界面.追击战()` → 打赢 → **改动前**：`结局 = '通关'`、层 4、日志尾「通关！…」。
  同一手法在第 1 层同样适用（换层）。
