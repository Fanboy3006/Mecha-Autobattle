# 黄金样例（从 JS 参考版导出，M2 / M3 的对拍依据）

由 `godot/tools/export_golden.mjs` 从封存的 JS 参考版（tag `js-reference-final`，规则签名 `r1:05a9cbf9`）导出。
**它们是迁移那一刻 JS 的行为快照，不是绝对真值**：Godot 跑不过时，先问 ARGON「这是规则还是缺陷」；是缺陷就登记到已接受差异表、由 ARGON 签字，不改 JS。

## 口径

敌人机制开 · 战术卡牌开（开局气势 25）· 全军突击（行动方针已取消）。即玩家实际在玩的规则。

导出前脚本会自检：用同一套流程、按 JS 旧基线口径（敌人机制关、关牌）重跑 47 场，必须与 JS 的 `simulate()` 逐条相同、总数 2788 —— 证明导出过程没有改变游戏行为。两次导出逐字节相同。

## 文件

| 文件 | 内容 | 场数 |
|---|---|---:|
| `battle/default.json` | 默认五人队 × 全部 47 条编成，种子 20261010，不出牌 | 47 |
| `battle/faction.json` | 7 个势力队 × 6 个代表编成（1~4 层，普通 / 精英 / 侵蚀源 / 守军 / Boss）× Lv20 / Lv30，每回合把能打的牌全打出 | 84 |
| `battle/character.json` | 6 张角色牌各一场（牌主 + 同势力 1 台，保证角色牌能进手牌） | 6 |
| `battle/card_baseline.json` | 默认五人队 vs 编成表[0]，种子 20261015，第 1 回合打【激励】【热血】（JS 开牌基线 31 条 + 结束记录） | 1 |
| `rng_vectors.json` | Mulberry32 / 四舍五入 / 稳定排序对拍向量 | — |

覆盖：32 张战术牌全部打出过；16 张条件牌全部发过；20 种事件类型；结局含全灭 / 被全灭 / 回合上限撤退。

## 一个样例

```
{ "id": "faction/秘银-Lv20-1-N1",
  "输入": { "我方": [{键, 位, 等级}], "敌方规格": [...], "种子": 20261100, "选项": {"战术卡牌": true, "波次": ...}, "编成": {...} },
  "命令": [ {"回合": 1, "类型": "打战术牌", "参数": "C_CMD_1"}, ... ],     // 每回合「打一回合」之前，按顺序执行
  "期望": {
    "事件": [ {...ctx.log 一条，去掉 文本/效果说明/触发说明, "_rng": 写这条时随机数已抽次数}, ... ],
    "回合摘要": [ 第 0 项 = 开局后（含全部「单位」），之后每回合一项（只含「单位变化」：[[单位下标, 单位摘要], ...]） ],
    "结果": {"结果": "胜", "原因": "敌方全灭", "回合": 3} } }
```

战斗流程（与 JS `simulate()` 同构）：`开局` → 每回合 {先执行本回合命令 → `打一回合`} 直到出结果或超过护栏（`max(MAX_TURN, 回合上限) + 2`）→ 没结果记「败 / 超出回合上限」→ 写一条 `类型: 结束` 记录。

## 数值编码

整数照存；**非整数存 `{"$f": "16 位十六进制"}`**（IEEE-754 小端位串），用 `GoldenCompare.decode()` 还原。不存 JSON 小数：Godot 的 JSON 解析会让部分小数丢精度。Godot 的 JSON 把整数也解析成 float，比较时数字一律按 float 比（JS 的数本来就是双精度）。

## 比对

`tests/golden_compare.gd` 的 `GoldenCompare.compare_events(样例, 实际事件)` 返回第一处分叉：哪个事件、哪个字段、第几回合、当时随机数抽到第几次。`_rng` 能把分叉定位到「从哪一次随机数开始走岔」。
