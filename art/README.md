# 机甲战棋 · 美术素材

本目录放**全部原创矢量美术素材**。目前完成的是**地图单位图标 + 表现层**（第 1 批）。
所有图形都是代码生成的矢量图形，不含任何外部图片或版权素材，可以随单文件 HTML 一起发布。

---

## 1. 文件

| 路径 | 说明 |
|---|---|
| `mech-icons.js` | **唯一可编辑的美术源文件**。23 个机体图标的几何数据 + 光照处理 + Canvas 后端 + 调色板 |
| `preview.html` | 审素材用的对照表页面。**双击打开**即可，不需要服务器 |
| `out/` | 各种自检用的 PNG（工具生成，可随时删；不参与游戏运行） |

开发工具在 `../tools/`，见第 9 节。

## 2. 怎么改素材

```powershell
# 1. 改 art/mech-icons.js（这是唯一的源文件）
node tools/render-art.mjs      # 生成图标对照表 PNG，自己看一眼
node tools/build-src.mjs       # 注入两份游戏 HTML
node tools/check-art.mjs       # 自检
node tools/boot-smoke.mjs      # 启动冒烟
node tools/render-game.mjs     # 用游戏自己的 draw() 渲染真实画面 → art/out/game-*.png
```

> **不要直接改 HTML 里的素材代码。** `src/index.html` 与 `src/artifact-fragment.html`
> 里夹在 `ART:mech-icons BEGIN/END` 之间的那一段是 `tools/build-src.mjs` 生成出来的。

## 3. 加一个新角色需要动什么

角色池要扩到几十个，所以**势力**和**战斗分类**都是查表得到的，不是逐个单位硬编码：

| 要加什么 | 在哪加 | 游戏侧会怎么反应 |
|---|---|---|
| 一个新机体（已有势力 / 已有分类） | `BUILD.xxx` 加几何 + `ICON_BY_MECH` 登记机体名 + `NAMES` 加中文名 | 自动用它的 `tags.势力` 选调色板、用 `tags.战斗分类` 选胸口核心色 |
| 一个新**势力** | `PAL` 加一套颜色 + `FACTION_PAL` 加一行（势力名 → 调色板键） | 游戏读的是 `FACTION_PAL[u.tags.势力]`，不用改游戏代码 |
| 一个新的**战斗分类** | `ROLE_COL` 加一个颜色 | 游戏读的是 `u.tags.战斗分类`，不用改游戏代码 |
| 一个新的**变身形态** | `FORMS` 里加一项，并写上 `icon:` 字段 | `iconIdOf()` 读 `FORMS[u.transform].icon`；**忘了写就会退回纯色块** |
| 一个新的**体积**（比如 4×4） | 游戏的 `SPR_MUL` 加一项 | 不加会回退成 `1.2` |

改完跑 `node tools/roster.mjs`：它会读游戏的全部单位模板和图标表对账，
按「势力 × 战斗分类」打覆盖表，把缺图标 / 缺中文名 / 缺调色板的单位全部列出来（缺项时以非 0 退出）。

## 4. 坐标约定

每个图标在自己的**单位空间**里描述：左上 `(0,0)`、右下 `(1,1)`。

- 图标会被缩放到「单位占用的格子区域」上：1×1 就是 1 格，2×2 就是 2×2 格。
- `y` 轴向下，`(0.5, 0.1)` 是机体的**正面**。
- **图标一律朝上画、不随朝向旋转**，朝向由游戏另外画的标记表示。
  这是刻意的：机体互相遮挡时，旋转的机体只会变成一团糊，而朝向是侧击 / 背击判定的
  依据，需要一个始终清晰、位置固定的标记。

### 3.1 精灵画布不是正方形

`makeSprite(id, opts, boxPx)` 生成的画布是 `width = boxPx`、`height = boxPx × (1 + headroom)`，
**单位空间的那个 1×1 方框贴在画布底部**，上方留出 `headroom`（默认 0.08）的余量。

这样机体就能「高出格子」站在格子上（像 SD 高达那样），而不是被硬塞进一格色块里。
游戏侧对应 `spriteSpec()` / `spriteRect()`。

## 4. 绘制指令

四种图元，游戏里的 Canvas 后端、离线光栅化器、以及 `tools/lib/canvas2d.mjs` 读同一份数据：

```js
{t:'p', pts:[[x,y],...], fill, grad, stroke, lw}   多边形
{t:'e', cx, cy, rx, ry,  fill, grad, stroke, lw}   椭圆
{t:'r', x, y, w, h, r,   fill, grad, stroke, lw}   圆角矩形
{t:'s', a:[x,y], b:[x,y], lw, fill}                粗线段（圆头）
```

`fill` 可以是颜色字符串，也可以是渐变对象
`grad = {g:[[x0,y0],[x1,y1]], st:[[0,c0],[0.5,c1],[1,c2]]}`（渐变优先）。

## 5. 三层识别系统

在 22–37px 这种尺寸下，单靠一个线索是认不出几十台机体的，所以用三层叠加：

| 层 | 表达 | 说明 |
|---|---|---|
| **地面标记形状** | 敌我 | 我方 = 压扁的**方形**环，敌方 = **圆形**环，中立物体 = 无标记。沿用原来「我方方块、敌方圆形」的读法 |
| **机体剪影** | 战斗分类 + 个体 | 近卫是细高剑士、尖兵是宽大的飞行框架、重装是超宽肩甲、狙击是一条贯穿整格的长枪…… |
| **胸口核心颜色** | 战斗分类 | 见下表。这是缩小后最快的区分线索 |

| 战斗分类 | 颜色 | 战斗分类 | 颜色 |
|---|---|---|---|
| 近卫 | `#ff9a86` 橙红 | 狙击 | `#ffa8dd` 粉 |
| 尖兵 | `#ffd766` 黄 | 特种 | `#7fe6ff` 青 |
| 辅助 | `#cfa8ff` 紫 | | |
| 重装 | `#8fd0ff` 蓝 | | |

> v0.17 起「医疗」分类已并入「辅助」，一共 **6 类**。

**阵营底色**（7 个势力）：影世界紫 `#8a6bd8`、月球王国银蓝 `#9fb7d8`、天人青绿 `#4fc3a1`、
卫星国防军樱粉 `#e88fb4`、预防者金黄 `#f2c14e`、ATX 近白 `#e9e7e2`、
米斯里尔军用深橄榄 `#7d9a58`；敌方红 `#d9564b`、已行动灰 `#56606b`。

`node tools/check-art.mjs` 会检查 7 套势力配色两两是否拉得开（判定条件是
**色相接近 + 明度也接近**，因为小尺寸下光靠饱和度区分不出来）。
7 个势力之后这条检查会越来越重要 —— 这是「同色相又同明度就分不出来」的兜底。

## 6. SD 比例

用了两个**统一系数**，而不是逐个图标手调（这样 23 个图标一起变，风格不会散）：

| 系数 | 值 | 作用 |
|---|---|---|
| `SD_HEAD` | 1.45 | 头的尺寸倍率。大头在缩小之后仍然认得出来，是「小尺寸可读」的关键 |
| `SD_LIMB` | 1.14 | 四肢粗细倍率。腿也画短了一点，整体更「矮壮」 |

头部还画了**两只发光的眼睛**（`head()` 里）：SD 机体的表情全靠这里，缩小后也是最快
认出「这是张脸」的东西。

## 7. 统一光照（赛璐璐明暗）

原来每个图元自带渐变、方向各不相同，看起来像「各画各的」。现在 `build()` 里有一道
`celShade()` 后处理：

- 光源固定在左上方（`LIGHT`）；
- 明暗分界线（terminator）是**全体共用的一个位置**，所以整个机体像被同一盏灯照着；
- 分界线是**硬的**（中间没有过渡），这是赛璐璐上色的关键特征；
- 颜色仍然取自原渐变的明暗两端，所以不同材质的色相不会串。
- 纯色填充（能量光、面罩、贴花）不动。

## 8. 外描边与细节等级

### 8.1 外描边
`build({outline:'#05070d'})` 会把整个剪影在 **8 个方向各偏移一份**垫在本体下面，
等于给机体套一圈暗边。机体互相重叠时，这圈边是「还分得开」的关键。
默认半径 `outlinePx = 0.021`（单位空间）。

### 8.2 细节等级 LOD
游戏按**实际显示尺寸**自动选等级：

| 等级 | 触发 | 处理 |
|---|---|---|
| `s` | ≤ 26px | 丢掉铆钉、细能量线等装饰，所有描边加粗 1.5 倍 |
| `m` | ≤ 46px | 保留中等细节 |
| `l` | 其余 | 全部细节 |

原因：缩小之后细于约 1px 的线只会变成一团糊，加粗反而更清楚。
在 `BUILD.xxx` 里用 `o.detail`（非 `s`）和 `o.fine`（`l`）来分流可选细节。

## 9. 表现层：机体是怎么画到地图上的

这一层在**游戏代码**里（`src/artifact-fragment.html`），素材层只负责产出精灵。

### 9.1 可视层表（从下到上）

角色池和机制还会继续膨胀，所以绘制顺序固化成一份**明确的层表**。
加新机制时是「往某一层里加一个组件」，而不是回头改 `draw()`。

| # | 层 | 函数 | 内容 |
|---|---|---|---|
| 1 | 地形 | `buildTerrain` | 地形预渲染位图 |
| 1b | 网格 | `drawGrid` | 调试开关，默认关 |
| 2 | **地块修饰** | `drawTileDecor` | 力场墙 / 地雷 / 区域效果…… |
| 3 | 范围提示 | （`draw` 内联） | 移动范围、攻击范围、威胁范围、地图炮路径、撤离区、陨石预警 |
| 4 | 单位地面 | `drawUnitGround` + `drawUnitLinks` | 投影、占位环、单位之间的连线 |
| 5 | 格子框选 | （`draw` 内联） | 选中框、目标框、光标框 |
| 6 | 机体 | `drawUnitSprite` | 机体精灵，**按脚印下沿排序**，前面的挡住后面的 |
| 7 | **机体附加** | `drawUnitAura` | 包住机体的光罩 / 屏障 / 光环 |
| 8 | 单位状态 | `drawUnitStatus` | 多段血条、蓄力条、增益减益徽记、朝向、飞行、破译、机体名 |
| 9 | 特效 | `drawFX` | FX 系统 |
| 10 | 浮动数字 | （`draw` 内联） | 伤害 / 回复数字 |

**第 5 层（格子框选）刻意画在机体下面**，否则线会切过机体；第 8 层刻意画在最上面，
否则会被前面的机体挡住。

### 9.2 可复用的标记组件

都设计成「**没有对应状态时什么都不画**」，所以现在接上它们不影响任何现有画面：

| 组件 | 用途 | 接进机制时要做什么 |
|---|---|---|
| `segBar(x,y,w,h,segs)` | **多段条**。`segs = [{ratio,color}]`，从左到右依次画，细缝分隔 | 只传一段时 = 现在的单条 HP 条。要加装甲层 / 护盾值就往 `segs` 前面 `unshift` 一段 |
| `badgeRow(cx,y,badges,max)` | **增益 / 减益徽记堆叠**，最多 `max` 个，多的显示 `+N` | 给单位挂 `u.badgeList = [{color, glyph}]` 就会出现；不挂就没有 |
| `auraRing(u,kind,color)` | **包住机体的光罩 / 光环** | 给单位设 `u.shield > 0` 就出现（`u.shieldColor` 可换色） |
| `unitLink(a,b,o)` | **单位之间的连线**（羁绊 / 锁定 / 治疗链） | `unitLinks.push({a: 单位A, b: 单位B, color, dashed})` |
| `tileDecor(k,kind)` | **地块修饰**的统一样式入口 | 往 `tileDecor` 里加一个 `kind` 分支 |
| `u.hidden` | **隐蔽 / 虚影** | 设 `u.hidden = true`，机体半透明绘制 |

`unitLinks` 是一个模块级数组，跟着每帧的要求重建即可（机制自己在合适的时机 push/清空）。

### 9.3 其它要点

- **机体精灵比它占的格子大**：`SPR_MUL = {1: 1.55, 2: 1.3, 3: 1.2}`，
  1×1 约 1.55 格宽、1.67 格高，底部对齐格子下沿、水平居中，允许盖住相邻格。
- **占位用地面环**：我方 = 压扁的**方形**环，敌方 = **圆形**环（沿用原来「我方方块、敌方圆形」的读法）。
- **朝向标记画在地面环的朝向那一侧**，不画在格子里 —— 机体比格子大，画在格子里会被挡住。
- **HP 条画在机体头顶上方**。地面环在脚下、机体在中间、血条在头上，三者不打架。
- 顶栏两个开关：「机体名」（默认关）、「网格」（默认关）。网格默认关是有意的：
  常驻网格 + 坐标数字非常像调试模式。
- **机体有一圈暗色外描边**（见 8.1），互相重叠时才分得开。

游戏侧相关常量：`SPR_MUL` / `SPR_HEADROOM` / `SPR_RES` / `SPR_OUTLINE`。

### 9.4 关于「40 个友军在地图上怎么认」

已确认的设计决定：**不做个人徽记**。地图只负责让玩家认出「这是**什么定位**」——
原型剪影 + 胸口核心色（分类色）；具体是谁靠**悬停 / 面板**，顶栏「机体名」开关给想看的玩家。

所以剪影的**分类特征**必须足够强（近卫 / 尖兵 / 辅助 / 重装 / 狙击 / 特种六类各有自己的形体语言），
而个体差异可以让步。这也是后面加角色时最该守住的一条。

### 9.5 还没画专属图标时：借用原型剪影

v0.18 起我方 34 台 / 敌方 28 种，其中一部分还没有专属图标。游戏的 `iconIdOf()` 查找顺序是：

```
中立 → debris；变身 → FORMS[形态].icon；ICON_BY_MECH[机体名]；都没有 → stockIcon(u)
```

`stockIcon(u)` 会**借用同战斗分类的原型剪影**，颜色仍按单位自己的势力走。
所以缺图标不会报错、也不会变成纯色块，只是「长得像同类的另一台」。
画好一个就在 `ICON_BY_MECH` 登记一个机体名，自动替换。

用 `node tools/roster.mjs` 可以随时查还差哪些（缺项时非 0 退出）。

## 11. 接口

```js
MechIcons.build(id, opts)                  // → 绘制指令数组
//   opts.pal      调色板对象或键名（ying/moon/cb/enemy/acted/rock）
//   opts.plate    'square' | 'circle' | 'none'（游戏里已不用，保留给对照表）
//   opts.size     显示尺寸（像素），用来推断 LOD
//   opts.lod      's' | 'm' | 'l'，显式指定（覆盖 size 推断）
//   opts.role     战斗分类名，决定胸口核心颜色
//   opts.inset    机体相对底板的缩放，默认方形 0.94 / 圆形 0.84
//   opts.outline  外描边颜色（推荐）
//   opts.outlinePx 外描边半径（单位空间，默认 0.021）
//   opts.cel      默认 true；设 false 可关掉统一光照

MechIcons.draw(ctx, prims, size, x, y)     // 画到 2D 上下文
MechIcons.makeSprite(id, opts, boxPx)      // → 离屏 canvas（游戏里每帧 drawImage）
MechIcons.ICON_BY_MECH                     // 机体名 → 图标 id
MechIcons.PAL / ROLE_COL / NAMES / ROLE_OF / FACTION_OF
```

### 为什么需要自己实现 Canvas 2D

本机沙箱里 **headless 浏览器起不来**（Chrome 的 mojo 需要命名管道，被沙箱拒绝），
`npm` 的缓存目录又在工作区外写不进去，所以 Playwright 也装不上。
为了能用眼睛检查画面，`tools/lib/canvas2d.mjs` 实现了一份够用的 Canvas 2D，
`render-game.mjs` 拿它顶替浏览器，把游戏自己的 `draw()` 跑出 PNG。

**已知差异**：canvas 上的**文字不会渲染**（要内嵌中文字体），所以导出的画面里没有
网格坐标数字、浮动伤害数字和「撤离区」标签；虚线按实线画。HTML/CSS 的界面（顶栏、
右侧面板）不属于 canvas，也不在该工具的渲染范围内。
