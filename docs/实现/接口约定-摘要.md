## 一、口子在哪（三类）

| 类别 | 长什么样 | 谁用 |
|---|---|---|
| **`window.__game`** | 每个测试 / 工具 / 界面都从它取内核（`tests/lib/dom-stub.mjs` 的 `loadPage()` 跑完 `index.html` 后就有） | 所有测试、`tools\balance.mjs`、`tools\replay.mjs`、`tools\战报分析.mjs`、调参室 |
| **`ctx`（一场战斗的上下文）** | `ctx.log`（逐条战斗记录）、`ctx.rng`、`ctx.方针`、`ctx.allies` … | 引擎内部、反馈层、录像 / 记录导出 |
| **`localStorage` 键** | 一律 `<项目前缀>-<用途>`（见下表） | 存档 / 录像 / 战斗记录 / 调参室 / 上报 / 声音开关 |

**五步循环的入口**（`60-战斗.js`）：`开局(...)` → `设方针(ctx, …)` / `设单位开关(ctx, …)` → `算意图(ctx)`（纯函数）→ `打一回合(ctx)`；一整场用 `simulate(我方, 敌方, 方针, 种子, 选项)` 薄封装（`方针` 可以是**一条**，也可以是**按回合的表**；`{}` / 不传 = 整场全军突击）。

**localStorage 键一览**（都互相独立）：`mecha-autobattle-run-v4`（肉鸽存档，v1–v3 一律丢弃+清键）、`mecha-autobattle-录像`（最近 20 局）、`mecha-autobattle-战斗记录`（最近 5 场 / 500 KB）、`mecha-autobattle-已上报`、`mecha-autobattle-上报开关`、`mecha-autobattle-tune`（调参室）、`mecha-autobattle-sound`。

## 三、改接口的规矩（原文里反复强调的几条）

1. **先登记、再改代码**：改了 `window.__game` 的字段 / 函数、模块之间的字段 → **先写进 `协作\接口约定.md`**（谁都要读它）。
2. **默认路径逐字不变**：新机制一律做成**开关**（`战斗结构.*` / `选项.*`），不传 / 关掉时**与改动前逐字相同**（任务板与 `tests/commands.js` 第 [1] 段盯着）。
3. **新增字段「只有真的用上才写」**：不然默认路径的记录就不是逐字节不变了。
4. **别改播放时序**（`85-播放.js`）：即时标注只加显示。
5. **存档只加字段不升版本；要升版本就换键并把旧档安全丢弃**（不崩、不追认）。
