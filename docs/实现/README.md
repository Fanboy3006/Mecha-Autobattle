> ★ 本目录的部分正文（`交付记录.md`、`构建与测试.md`）是从 `CLAUDE.md` **逐字搬过来的**（**一字未改**）；其余几篇是**索引 / 摘要**，权威原文各自的出处都写在文件开头。

## 要改代码，先读哪一篇（建议顺序）

1. [`坑与红线.md`](坑与红线.md) —— **红线先看**（只写自己那条线的文件、旧仓库只读、随机数带种子、不手改生成物、不 `git add -A`…）
2. [`构建与测试.md`](构建与测试.md) —— 构建命令 + 21 套测试 + 本机沙箱的坑（子进程管道 / Playwright 装不上 / DOM 替身测不到 CSS 视觉效果）
3. [`接口约定-摘要.md`](接口约定-摘要.md) —— 改接口**先登记**到 `协作/接口约定.md`，再动代码
4. [`结构表.md`](结构表.md)（P1 交付后）或 `CLAUDE.md` 第 3 节 —— 找到该改哪个文件
5. [`交付记录.md`](交付记录.md) —— 找同类改动当初是怎么落地的（含「旧 → 新 → 为什么」）

## 提交前那几步（照 `协作/协作框架.md` 第 3 / 10 / 18 节）

| 步骤 | 命令 / 动作 |
|---|---|
| ① 重建生成物 | `node tools/build-src.mjs`（**生成物不许手改**） |
| ② 生成物同步自检 | `node tools/build-src.mjs --check` |
| ③ 全量验收 | `node tools/verify-all.mjs` → 期望 **绿 22 / 22　红 0** |
| ④ 边写边跑冒烟 | `node tests/smoke.js`（框架 §15：每写完一段就跑一次） |
| ⑤ 核暂存区 | `git diff --cached --name-only`（**只许有自己这条线的文件**；发现别人的 → 停下报统筹） |
| ⑥ 提交 | 提交说明**中文**、以 `[标签]` 开头（如 `[文档]`）；**不 push**（推送由统筹做） |
