# 对局录像（数据集）

> **这里放什么**：作者自己玩的一局一局的**对局录像**（`.json`），用来攒数据集 ——
> 目标是以后让 AI **理解并模拟作者的打法**。
> **谁写的**：作者 2026-10-12 提出、Claude 出规格、DSH（录像线）实现。
> 实现 = `src/js/89-录像.js`（录）+ `tools/replay.mjs`（重放与校验）；
> 格式与接口登记在 `协作/接口约定.md`；进度与实测数字在 `协作/任务板.md` 的「录像」一节。

---

## 0. 一句话

**录操作，不录局面。** 整局随机都来自种子（同种子连跑两遍逐字相同），所以一份录像里只记三样：

1. **种子**（这一局的随机全部由它决定）
2. **游戏版本号**（`__game.version`）
3. **按顺序的每一个操作**（动作名 + 参数，带序号；战斗内的操作再带回合号）

要局面的时候用工具**重放还原**（`node tools/replay.mjs <文件>`）。所以一局只有**几十 KB**，
而不是几百 KB 的逐帧日志。

---

## 1. 怎么攒（作者怎么拿到文件）

游戏里（**肉鸽一局**，练习模式 / 调参室不录）：

| 在哪 | 做什么 |
|---|---|
| **战斗结算屏** | 「对局录像」那一块 →「复制录像 JSON」/「下载 .json」 |
| **开场菜单** | 「对局录像（最近 N 局）」→ 列表 → 点某一局 → 复制 / 下载 |
| 招募 / 晋升 / 黑市 / 零件屏 | 想写理由时点「＋ 为什么选它？」（**可以不填**，默认收起）—— 填了就记进那一步的 `理由` 字段 |

* **一局结束**（**胜 / 败 / 放弃都算**）**自动封存**；游戏里**保留最近 20 局**（超了从最老的丢）。
* 下载下来的文件名形如：
  `对局录像-种子20261010-v0.6.2-20261012-193237-败.json`
  （**种子 + 版本 + 日期 + 结果**）。
* 把文件放进本文件夹即可（`对局录像/`）。文件名保持原样最省事（种子 / 版本 / 结果一眼看得出）。

> **游戏里的存档与这个文件夹无关**：录像存在**独立**的 `localStorage` 键
> `mecha-autobattle-录像` 里（不动 `RUN`、不动肉鸽存档的版本号）；
> 进行中的那一局**跟着读档继续记** —— 读档回来接着往**同一份**录像里追加，不重开一份。

## 2. 格式

```jsonc
{
  "格式版本": 1,                       // 录像格式自己的版本（不是游戏版本）
  "游戏版本": "0.6.2",                 // 录的时候 __game.version
  "种子": 20261010,                    // 这一局的种子（重放要用它）
  "分队": "无",                        // 开局选的分队
  "开始时间": "2026-10-12 19:30:04",   // 取自 RUN.t0（读档回来一模一样）
  "结束时间": "2026-10-12 19:32:11",
  "结果": "败",                        // 通关 = 胜 / 耐久耗尽 = 败 / 玩家放弃 = 放弃
  "结果原因": "作战耐久耗尽",           // 结束的那一句话（可选）
  "操作": [
    { "序号": 1, "屏": "分队", "动作": "选分队", "参数": "无",
      "对账": "无局" },
    { "序号": 3, "屏": "招募", "动作": "用券", "参数": "0", "理由": "先补前排",
      "对账": "层1 场0 Lv1/0 希望8 源碳20 耐久10 推进剂10 格2 队[] 券3 藏品0 零件0 结局-" },
    { "序号": 12, "屏": "编队", "动作": "编队",
      "参数": "[{\"键\":\"U8\",\"位\":0,\"等级\":10},{\"键\":\"S4\",\"位\":1,\"等级\":10}]",
      "对账": "层1 场0 Lv1/0 …" },
    { "序号": 20, "屏": "战斗", "动作": "方针", "参数": "集中攻击", "回合": 1, "对账": "… 战1 …" },
    { "序号": 21, "屏": "战斗", "动作": "点敌人", "参数": "4", "回合": 1, "对账": "… 方针集中攻击@4 …" },
    { "序号": 22, "屏": "战斗", "动作": "大招", "参数": "0", "回合": 1, "对账": "… 开关[0:留]…" },
    { "序号": 23, "屏": "战斗", "动作": "开打", "参数": "", "回合": 1, "对账": "… 结败" },
    { "序号": 27, "屏": "大地图", "动作": "去节点", "参数": "14", "对账": "…" },
    { "序号": 40, "屏": "大地图", "动作": "弹窗", "参数": "藤蔓", "弹窗": "遗迹",
      "可选项": ["藤蔓", "交流", "离开"], "对账": "…" }
  ],
  "最终摘要": { "结局": "失败", "层": 1, "…": "…", "日志": [["第 1 层", "…"]] }
}
```

### 2.1 `操作[]` 里每一步的字段

| 字段 | 一定有？ | 意思 |
|---|---|---|
| `序号` | ✔ | 这一局里的第几步（1 起，连续） |
| `屏` | ✔ | 下这一个决定时**在哪一屏**（分队 / 招募 / 大地图 / 编队 / 战斗 / 黑市 / 晋升 / 奇遇 / 零件 / 菜单 / 录像…） |
| `动作` | ✔ | 动作名（**就是界面上那个按钮的名字**，`80-界面.js` 动作表里的键） |
| `参数` | ✔ | 动作的参数（`去节点:14` 的 `14`、`招募:B1` 的 `B1`、`开新局` 这里是**实际用的种子**） |
| `回合` | 战斗内 | 战斗内的操作带**回合号**（第几回合下的这条方针 / 拨的这个开关） |
| `理由` | 填了才有 | 作者在「为什么选它？」里写的**一句话**（招募 / 晋升 / 黑市 / 零件这 4 个关键选择） |
| `对账` | ✔ | 这一步**做完那一瞬间**的紧凑局面串（层 / 资源 / 名册 / 当前格 / 战斗内的回合与双方 HP / 当前方针）。**重放时逐步比对它** —— 对不上就报「第 N 步开始对不上」 |
| `弹窗` / `可选项` | 弹窗答案那一步 | 弹窗标题 / 当时摆出来的选项（遗迹三选一、休整三选一、瞭望站、隧道、侵蚀源代价） |

### 2.2 哪些操作一定在

**大地图 / 肉鸽外壳**：`选分队`、`去节点`（移动到格子）、`招募`、`用券` / `丢券`、`晋升`、
`黑市买` / `黑市卖` / `黑市刷新` / `黑市离开`、`奇遇`（事件选项）、`休整`、`探查遗迹`、`瞭望`、`穿隧道`、
`弹窗`（三选一的答案）、`前进`（出口换层）、`使用零件`、`存个档` / `继续上一局`、`放弃本局`。

**编队**：`编队` —— **开战那一刻的最终结果**（出击名单与站位；摆位是拖动出来的，所以单记一步）。

**战斗内**：`方针`（每回合开始时的全队方针，集中攻击的目标位在下一步 `点敌人`）、
`大招`（自动 / 保留）、`TRANSAM` / `开TRANSAM`（天人的单位级开关）、`开打`。

> **没有记的**：`回菜单` 这类纯导航有时会记（它不改变局面）；录像自己的「看 / 复制 / 下载」四个动作**不记**
> （它们不是游戏操作）。

## 3. 怎么用（重放与校验）

```bash
node tools/replay.mjs 对局录像/对局录像-种子20261010-v0.6.2-20261012-193237-败.json
```

工具用 `tests/lib/dom-stub.mjs` 把游戏在 Node 里跑起来，**按同一个动作派发入口逐条重放**，然后：

1. **逐步校验**：每一步做完的局面串与录像里的 `对账` 比 —— 不一致就报
   「**第 N 步开始对不上**」+ 当时**期望 / 实际**（**不崩**）；
2. **最终校验**：重放结束后的 `RUN` 重建《最终摘要》，与录像里的 `最终摘要`**逐字比对**；
3. **版本号不同**时**先警告、照样尽量重放**。

```bash
node tools/replay.mjs <文件> --导出决策        # 另外打一份 JSONL（每个决策点一行）
node tools/replay.mjs <文件> --导出决策 --out=决策.jsonl
node tools/replay.mjs <文件> --quiet           # 只打结论
```

`--导出决策` 的每一行：

```jsonc
{ "序号": 3, "屏": "招募",
  "局面摘要": { "层": 1, "希望": 8, "源碳": 20, "耐久": 10, "推进剂": 10,
                "名册": [], "券": ["尖兵","近卫","重装"], "藏品": [], "零件": [],
                "当前节点": { "格号": 2, "类型": "空", "名": "空节点" } },
  "可选项": ["用券:0","用券:1","用券:2"],      // ★ 由重放工具**就当时局面现场枚举**
  "选择": "用券:0",                            // 保证在「可选项」里
  "理由": null,
  "最终结果": "失败（败）" }                    // 这一场 / 这一局的最终结果
```

* 战斗内的行还带 `局面摘要.战斗`（回合 / 方针 / 单位开关 / 双方 HP / 敌人预览）。
* **行数 = 决策点数**（导航、`开打` 这类不算决策的步不出行）。
* 「可选项」是重放工具枚举的（招募候选 / 可去的格子 / 黑市货 / 三选一 / 5 条方针……）——
  **游戏本身不用为此改逻辑**。

## 4. 规矩（改这个文件夹 / 改格式前先读）

1. **别手改录像文件**：它是「当时真的这么点了」的证据。要修数据就重录一局。
2. **格式版本**（`格式版本`）只在字段含义变了时才 +1；改了格式要同步
   `src/js/89-录像.js` 的文件头 + `协作/接口约定.md` + 本文件。
3. **保留最近 20 局**（游戏里）、**屏上最多画 200 步**（只是画面；存下来的操作一条不少）。
4. **同种子 + 同一串操作 = 同一局**：重放的《最终摘要》必须与录像逐字相同，
   否则说明有「不来自种子的随机」或版本不一致 —— 把这当成 bug 报，不要手改录像去迁就工具。
